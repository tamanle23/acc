# 484: Fix MediabunnyClient Cache Fetch Error & Sidecar Warmup Deduplication

## Problem
1. **Fetch API "URL scheme 'cache' is not supported" Crash**:
   In `apps/studio/src/renderer/workers/MediabunnyWorkerReader.ts`, when `this.assetId` was present, `uri` was unconditionally constructed as `cache:${this.assetId}` regardless of whether the asset was actually downloaded or cached into `ContentCacheRegistry`. When an un-cached asset (such as `'asset-matrix-core'` pointing to a remote gettyimages URL in demo IR) was opened, `CachedAssetBlob.blob()` resulted in a cache miss. In `resolveClientMediabunnySource()`, the failure fell through to a generic `fetch(uriOrPath)` call, which attempted to execute `fetch("cache:asset-matrix-core")`. The browser runtime threw `Fetch API cannot load cache:asset-matrix-core. URL scheme "cache" is not supported.`
2. **Duplicate Sidecar Warmup Dispatch Resurfacing**:
   Console logs showed:
   ```
   [PreviewWorkerCoordinator.ts] Sidecar worker successfully warmed up.
   [PreviewWorkerCoordinator.ts] Sidecar worker successfully warmed up.
   [PreviewWorkerCoordinator.ts] Duplicate WARMED_UP response received from sidecar worker.
   [PreviewWorkerCoordinator.ts] Duplicate WARMED_UP response received from sidecar worker.
   ```
   Root causes:
   - `StudioBootController.ts` used dynamic `await import('../../renderer/PreviewWorkerCoordinator')` while components statically imported it, triggering Vite chunk splitting warnings and multiple module scopes.
   - `PreviewWorkerCoordinator` and `PreviewWorkerBridge` singletons were stored solely as class static variables without binding to `globalThis`, permitting secondary instances across module chunks.
   - `initWorker()` registered an anonymous arrow function with `bridge.addMessageListener()`, which was not deduplicated by `Set.add()`.
   - `preview.worker.ts` lacked an in-flight/completed warmup guard, eagerly processing and re-dispatching `WARMED_UP` on every incoming `WARMUP` message.

## Plan
1. **Fix Client Source Resolution & Worker Reader**:
   - In `MediabunnyWorkerReader.init()`, check `ContentCacheRegistry` first. Only use `cache:${this.assetId}` if the blob actually exists in cache; otherwise retain and decode `this.src` directly via `UrlSource`.
   - In `resolveClientMediabunnySource()`, strictly guard `fetch()` to only execute on `http:`, `https:`, `blob:`, or relative paths, never on `cache:` or `file:`. Wrap `fetch` in `try/catch`.
2. **Guarantee Sovereign Singleton & Idempotent Worker Warmup**:
   - Bind `PreviewWorkerCoordinator` and `PreviewWorkerBridge` singletons to `globalThis` using `Symbol.for('@acc/studio/PreviewWorkerCoordinator')` and `Symbol.for('@acc/studio/PreviewWorkerBridge')`.
   - In `PreviewWorkerCoordinator`, guard constructor against secondary allocations and bind `handleBridgeMessage` to an instance method.
   - In `preview.worker.ts`, add `isWorkerWarmedUp` and `isWorkerWarmingUp` state flags to discard duplicate `WARMUP` message executions.
   - In `StudioBootController.ts`, make `PreviewWorkerCoordinator` import static.
3. **Verify**:
   - Add automated test assertions in `autogenerated-tests/mediabunny_isomorphic_decoder.test.ts`.
   - Verify all test suites and run studio production build.

## Changes
- `packages/core-web/src/media-engine/MediabunnyClientStrategy.ts`: Guarded `fetch` against `cache:` and `file:` schemes and wrapped in `try/catch`.
- `apps/studio/src/renderer/workers/MediabunnyWorkerReader.ts`: Checked `ContentCacheRegistry` before overriding `this.src` with `cache:`.
- `apps/studio/src/renderer/PreviewWorkerCoordinator.ts`: Added `globalThis` singleton binding, constructor guard, instance arrow listener, and early break on `alreadyWarmed`.
- `apps/studio/src/renderer/workers/PreviewWorkerBridge.ts`: Added `globalThis` singleton binding.
