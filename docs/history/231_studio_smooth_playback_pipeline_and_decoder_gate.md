# Task History #231: Studio Smooth Playback Pipeline, Hardware Decoder Gating & Chunked Audio DSP

## Problem
During video playback in `@acc/studio`, pressing **Play** caused the playback to run for 2–5 seconds and then the entire application hung, resulting in browser tab unresponsiveness and system commit memory exhaustion (`0x800705AF: The paging file is too small for this operation to complete`).

### Root Cause
1. **Unbounded WebCodecs Hardware Decoder Queue Flooding:** On every frame tick during playback, cache misses in `PreviewFrameMemoryManager` triggered asynchronous WebCodecs decodes via `MediabunnyWorkerReader.requestFrame` without in-flight deduplication or concurrency gating. 30–60 hardware decodes were fired per second, allocating unmanaged native video frames until memory was exhausted.
2. **Main-Thread Audio DSP Freeze:** `WebAudioEngine.startPlayback` synchronously computed a 30-second stereo audio mix ($1.32\times 10^6$ Float32 samples) on the main UI thread via `UniversalAudioMixer.mixStereo`, causing massive frame drops and freezing the browser event loop.
3. **Linear Scan in Staged Disposal:** In `PreviewFrameMemoryManager`, `pendingDisposal` was an `Array` with linear `.includes()` scans on every eviction and render tick.
4. **Re-entrant Paint Storms:** Decoded frames resolving out-of-order directly triggered recursive `renderCurrentFrame` passes during active playback.

## Plan
1. **Implement In-Flight Deduplication & Concurrency Gate ($\le 2$)**:
   - In `MediabunnyWorkerReader`, deduplicate requests by frame number using `Map<number, Promise<ImageBitmap | null>>`.
   - Gate active WebCodecs decodes to a maximum of 2 concurrent operations; gracefully reject or defer excess decodes.
2. **4-Frame Proactive Lookahead**:
   - In `WorkerClipPrewarmer`, actively pre-decode $[currentFrame + 1 \dots currentFrame + 4]$ into `PreviewFrameMemoryManager` so upcoming frames are hot in memory before playhead advancement.
3. **Suppress Re-entrant Paint Storms**:
   - In `preview.worker.ts`, hold the previous canvas frame on cache miss, populate the cache upon resolution, and suppress immediate repaints during active playback (allowing natural next-tick painting).
4. **$O(1)$ Post-Render Drain Queue**:
   - Refactor `pendingDisposal` in `PreviewFrameMemoryManager` to `Set<ImageBitmap>`.
5. **Lightweight Non-Blocking Audio Chunking**:
   - In `WebAudioEngine`, reduce synchronous startup synthesis from 30.0s to responsive 5.0s chunks, streaming into `UniversalAudioStreamWorklet`.

## Changes
- `apps/studio/src/workers/MediabunnyWorkerReader.ts`: Added `inFlightRequests`, `activeDecodes` semaphore ($\le 2$), and unified `execute()` deduplication.
- `apps/studio/src/workers/WorkerClipPrewarmer.ts`: Added `prewarmSequentialLookahead` for 4-frame forward lookahead window.
- `apps/studio/src/workers/preview.worker.ts`: Suppressed re-entrant paint storms during active playback and passed `isPlaying` state to prewarmer.
- `apps/studio/src/workers/PreviewFrameMemoryManager.ts`: Converted `pendingDisposal` from `Array` to `Set<ImageBitmap>` for $O(1)$ operations and clean disposal.
- `apps/studio/src/lib/audio/WebAudioEngine.ts`: Chunked initial audio playback synthesis to 5.0s.
- `autogenerated-tests/mediabunny_reader_concurrency_gate.test.ts`: Added unit tests for deduplication and max 2 concurrency gate.
- `autogenerated-tests/webaudio_engine_chunked_synthesis.test.ts`: Added tests for chunked audio synthesis and ring buffer streaming.

## Walkthrough
1. WebCodecs hardware decoder requests are deduplicated and strictly capped at $\le 2$ active decodes per reader.
2. 4-frame sequential lookahead warms upcoming frames before the playhead reaches them, avoiding starvation.
3. Audio synthesis starts in lightweight 5s slices instead of blocking 30s chunks.
4. Memory disposal is $O(1)$ post-render with zero GPU resource leaks.
