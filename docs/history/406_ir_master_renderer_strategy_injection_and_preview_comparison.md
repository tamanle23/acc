# 406 — IRMasterRenderer MediaEngineStrategy Injection & IRMasterRenderer vs IRPreviewEngine Comparison

## 1. Problem

1. `IRMasterRenderer.preloadAssets(baseDir, engineType)` retrieved the media engine ad hoc from the global `MediaEngineRegistry` (`has` / `get` / `throw`).
   - `engineType` was a required parameter, but the only internal caller (`render()`) never passed it, so any timeline with `assets` (even `{}`) threw before asset loading.
   - The renderer was coupled to a global static registry, which hurt testability and made the dependency invisible in the constructor signature.
2. There was no written comparison between the two frame-evaluation engines (`IRMasterRenderer` for export, `IRPreviewEngine` for Studio preview), which makes drift between them hard to spot.

## 2. Plan

1. Add an optional `mediaEngineStrategy?: IMediaEngineStrategy` as the 5th constructor argument (backward compatible with ~25 existing call sites).
2. Remove the registry lookup from `preloadAssets` and drop its `engineType` parameter; use the injected strategy.
3. Inject the strategy at call sites that render with a real engine.
4. Add tests for the injection; repair existing tests that referenced the renderer and were broken by pre-existing environment/design drift.
5. Document the Master vs Preview comparison and the resulting follow-ups.

## 5. Walkthrough — IRMasterRenderer vs IRPreviewEngine

Files: `packages/ir/src/renderer/IRMasterRenderer.ts` (Master) and `apps/studio/src/renderer/IRPreviewEngine.ts` (Preview). Both delegate pixel work to `IRCanvasCompositor.renderFrame`.

### 5.1 Purpose

| | Master | Preview |
|---|---|---|
| Role | Headless deterministic export of the whole timeline | Interactive random-access preview in Studio |
| Entry point | `render(options)`: frame-range loop returning `HeadlessRenderResult` | `renderFrame` / `renderFrameAsync`: one frame to a `CanvasRenderingContext2D`, returns `PreviewFrameResult` |
| Frame input | Integer loop `startFrame..endFrame`, seeded | Any frame, `Math.round` then clamped to `[0, totalFrames]` |
| Output | RGBA bytes in a pre-allocated buffer, handed to `IIRFrameSink` | Direct canvas draw plus `latencyMs` |
| Compositor profile | `'master'` | `'preview'` |

### 5.2 Constructor & dependencies

| | Master | Preview |
|---|---|---|
| Arguments | `timeline`, `seed`, `pluginRegistry?`, `resourceManager?`, `mediaEngineStrategy?` | `timeline`, `pluginRegistry?`, `audioSourceResolver?`, `audioSampleRate`, `options?` |
| Default plugin registry | `createIsolatedCoreModifierPlugins()` | `registerCoreModifierPlugins(ModifierPluginRegistry.createIsolated())` |
| Resource manager | Injectable; defaults to singleton | Always `NativeResourceManager.getInstance()` |
| Media engine | Injected strategy (video decoders) | None |
| Asset source | Own `imageCache` + `videoDecoders`, filled by `preloadAssets` | `AssetTextureCache` singleton or `options.textureCache` |
| Active-sequence lookup | Compositor iterates tracks | `IntervalTreeIndex.queryActive(frame)` (for the result's `activeSequences`) |

### 5.3 Master render pipeline (`render()`)

1. Set a resolution-aware GPU budget on the resource manager (`computeResolutionBudgetBytes`, optional `maxMemoryMb`).
2. Recompute asset lifespans; clear evicted-key set; compute `[startFrame, endFrame)` from `chunkStart`/`chunkEnd`.
3. Preload assets if `timeline.assets` is set and `imageCache` is empty.
4. Pre-flight track- and sequence-level modifier `execute` hooks.
5. Audio: unless `skipAudio`, `mixTimeline`; with a sink and no `audioPath`, export a temp WAV (also cached in `CacheNamespace.Audio`).
6. Initialize the sink if not already initialized.
7. Allocate one RGBA buffer and (if visual) one reusable canvas.
8. Per frame: abort check → `lock.acquire(f)` → `renderCanvasFrame` (or procedural rasterizer) → `sink.consumeFrame` → optional per-frame SHA-256 and cumulative hash → `evictExpiredSequences` → `lock.acknowledge(f)` → progress → cooperative `setTimeout(0)` yield every `yieldInterval` (default 5).
9. Finalize sink, delete temp audio (cache + disk on Node), close decoders, return result with `cumulativeHash`.

### 5.4 Preview pipeline (`renderFrame` / `renderFrameAsync`)

1. Clamp frame, compute `timeSec = frame / fps`, pick texture source, query interval tree.
2. Create a per-frame resource scope; build the effective timeline (shallow clone with ephemeral transform overrides, or the original if none).
3. `IRCanvasCompositor.renderFrame` with `executionProfile: 'preview'`.
   - `renderFrame`: fire-and-forget (`void ...catch(warn).finally(dispose)`), returns immediately.
   - `renderFrameAsync`: awaited in `try/catch/finally`.
4. Return `PreviewFrameResult` with timing.

### 5.5 Capabilities exclusive to each

**Master only:** `DeterministicNoiseGenerator`; `FrameBackpressureLock`; `UniversalHasher` and hash chain; sink lifecycle; chunk ranges; `AbortSignal`; `yieldInterval`; memory budgeting; lookahead lifespan eviction; video decoders with sequential `readNextFrame` and per-asset `onAssetDrawn` close; `dispose` / `Symbol.dispose`.

**Preview only:** `PreviewWorkerCoordinator` sidecar preflight with `onModifierWarmed` events and per-sequence task cancellation; `syncTimeline` (rebuilds interval tree and audio mixer); ephemeral drag overrides and `getEffectiveTimeline`; LOD scale; `debugMode`; `renderAudioSlice`; `seek`.

**Shared:** `UniversalAudioMixer` (whole-timeline mix vs slices); per-frame resource scopes disposed in `finally`; defensive catching of composition errors.

## 6. Findings & Recommendations

| # | Finding | Recommendation |
|---|---|---|
| F1 | `renderFrame` and `renderFrameAsync` duplicate the preamble (clamp, query, scope, effective timeline, compositor options). | Extract a private helper returning `{ clampedFrame, timeSec, activeSequences, frameScope, options }`; keep only the await/fire-and-forget difference in the two methods. |
| F2 | Default plugin registries are built by two different expressions. | Use one shared factory so Master and Preview cannot drift; verify `createIsolatedCoreModifierPlugins()` equivalence first (not verified). |
| F3 | Preview hard-codes the `NativeResourceManager` singleton. | Add an optional injected resource manager to `IRPreviewEngineOptions`, mirroring Master. |
| F4 | `autoPreflight` field initializer is `true`, but the constructor overrides it with `options?.autoPreflight ?? false`, and the options doc says "omitted ⇒ no preflight". | Remove the dead initializer (set it to `false`) to match the documented behavior. |
| F5 | Preview has no decoder path; video in preview depends on whatever populates `AssetTextureCache`. | Document the contract, or add a preview video-frame provider behind `IPreviewTextureProvider`. |
| F6 | `HeadlessRenderOptions.engine` is declared but no longer read by `IRMasterRenderer` (engine now comes from the constructor). | Deprecate or remove the field and update callers that still pass it (`ir-render.ts`, studio export code). |
| F7 | `render()` preloads only when `imageCache.size === 0`; a timeline with only video assets re-preloads on each `render()`. Master also closes decoders at the end of `render()`, so re-rendering reopens them. | Track a preload flag instead of using cache size. |
| F8 | `ClientExportOrchestrator` does not inject a strategy in fallback path (`new IRMasterRenderer(irState.timeline, 42)`). | Pass `MediaEngineRegistry.get('mediabunny-client')` into `IRMasterRenderer`. |

## 7. Deep Research Synthesis & Diagnostic Analysis (Audio Pipeline)

### 7.1 Root Cause: Why There Is No Audio in Output Video

Tracing the export pipeline (`ClientExportOrchestrator` -> `export.worker.ts` -> `IRMasterRenderer` -> `UniversalAudioMixer` -> `MediabunnyClientSink`):

1. **Web Worker Context Lacks `OfflineAudioContext`**:
   - In `apps/studio/src/renderer/workers/export.worker.ts`, export executes in a dedicated Web Worker.
   - When `IRMasterRenderer.render()` runs, it invokes `this.audioMixer.mixTimeline(this.timeline)`.
   - `UniversalAudioMixer.mixTimeline()` iterates all audio clips and delegates decoding to `this.decodeAsset(resolvedPath)`.
   - `MediabunnyClientStrategy.createAudioDecoder().decodeToPCM()` checks:
     ```ts
     const OfflineCtx = (globalThis as any).OfflineAudioContext || (globalThis as any).webkitOfflineAudioContext;
     if (!isVideoContainer && OfflineCtx && arrayBuffer) { ... }
     ```
   - In standard browser Web Workers, `OfflineAudioContext` is frequently undefined or unsupported. When falling through to `UrlSource` without protocol resolution or across relative/CORS boundaries, the decoder returns `null`.
   - As a result, `mixTimeline` produces an all-zero buffer or 0 total samples.

2. **Sink Initialization / Finalization Audio Mismatch**:
   - In `IRMasterRenderer.ts`:
     ```ts
     if (sink && !options.audioPath) {
       audioResult = await this.audioMixer.mixTimeline(this.timeline, { baseDir: options.baseDir });
       if (audioResult.totalSamples > 0) {
         tempAudioWavPath = `${outDir}/.temp_${Date.now()}_master_audio.wav`;
         await UniversalAudioMixer.exportToWav(tempAudioWavPath, audioResult);
     ```
   - In browser/worker environments, `tempAudioWavPath` uses a simulated filesystem path. `exportToWav` fails or no-ops without Node `fs`.
   - In `export.worker.ts`, `sink.initialize({ ..., enableAudio: true })` is called before passing `sink` to `IRMasterRenderer`. `IRMasterRenderer` detects `sink.isInitialized()` and skips passing `audioPath`.
   - On completion, `IRMasterRenderer` invokes `await sink.finalize(audioResult)`.
   - In `MediabunnyClientSink.finalize()`, audio samples are only pushed if `this.audioSource && audioResult && audioResult.totalSamples > 0`. If `audioResult` has 0 samples or is silent, zero audio samples are appended to `AudioSampleSource`, creating an MP4 with an empty or silent audio track.

3. **Fallback In-Process Export Completely Disables Media Engine**:
   - In `apps/studio/src/lib/export/ClientExportOrchestrator.ts`:
     ```ts
     const masterRenderer = new IRMasterRenderer(irState.timeline, 42); // 5th argument omitted!
     ```
   - When falling back to in-process export, no `mediaEngineStrategy` is injected, leaving `IRMasterRenderer` unable to decode audio or video assets.

### 7.2 Root Cause: Why Preview Audio Is Inconsistent Between Playings

1. **Decoded Audio Cache Race Condition (`getAudioChannels` returning `null` on Play 1)**:
   - In `apps/studio/src/lib/audio/AudioAssetCache.ts`:
     ```ts
     public getAudioChannels(assetId: string, src?: string): DecodedAudioData | null {
       const existing = this.cache.get(assetId);
       if (existing) return existing;
       if (src && !this.inFlight.has(assetId)) {
         this.fetchAndDecode(assetId, src);
       }
       return null;
     }
     ```
   - On the first press of Play, `WebAudioEngine.startPlayback()` executes synchronously. The audio asset is not yet in `AudioAssetCache`, so `getAudioChannels()` returns `null` and kicks off `fetchAndDecode()` in the background.
   - Because `audioSource` is `undefined`, `UniversalAudioMixer.sampleClipAudio()` falls back to procedural synthesis (`synthBGM`, `synthPilotVoice`, `synthLaserSFX`). The user hears procedural synth tones.
   - Meanwhile, `fetchAndDecode()` finishes and triggers subscribers.
   - On the second press of Play, `getAudioChannels()` returns the real decoded PCM audio. The user now hears the actual asset.
   - When the LRU cache evicts the entry (`MAX_CACHE_ENTRIES = 8`), subsequent seeks or playback can fall back to procedural sound again, leading to inconsistent audio across playings.

2. **Clip-Local Time vs. Timeline Global Time in `sampleClipAudio`**:
   - In `UniversalAudioMixer.ts`:
     ```ts
     // sliceStart is the global timeline time (e.g. 5.0s)
     const { left: rawL, right: rawR } = this.sampleClipAudio(clip, sliceStart, durationSec);
     ```
   - And in `DecodedPcmSource.sample()` (`AudioSourceAdapter.ts`):
     ```ts
     const targetTime = timeOffsetSec + (i / targetSampleRate) + this.trimStartSec;
     let sourceSampleIdx = targetTime * this.sourceSampleRate;
     ```
   - When a clip starts at `clip.startTimeSec = 5.0s` and is 2.0s long:
     - At timeline time `5.0s`, `sampleClipAudio` passes `timeOffsetSec = 5.0s`.
     - `sourceSampleIdx` is computed as `5.0 * sampleRate = 220,500 samples`.
     - Because `220,500 > sourceLength (88,200)` and `loop` is `false`, the adapter returns all zeros (complete silence).
     - Any clip placed after `t = 0` on the timeline samples past its source buffer and outputs silence.

3. **SPSC AudioWorklet vs. `AudioBufferSourceNode` Chaining**:
   - In `WebAudioEngine.ts`, `pushChunk` is sent to `streamWorklet` while an `AudioBufferSourceNode` is concurrently scheduled if `!this.isWorkletActive`.
   - If the AudioWorklet initializes asynchronously after playback starts, dual output or audio cancellation can occur.
   - The 1000ms refill interval in `startRefillScheduler()` can fall behind real time if the tab throttles or background tasks delay timers, causing audio gaps or drift relative to video frames.
