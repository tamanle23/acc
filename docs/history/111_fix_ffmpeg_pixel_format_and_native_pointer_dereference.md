# 111. Fix FFmpeg FFI Pixel Format Resolution & Native Pointer Dereference

## Problem & Context
During 3D Depth scene rendering, FFmpeg encoders (`h264_nvenc` and `libx264`) failed with:
```
[h264_nvenc @ 0000014ae3fefc80] Invalid video pixel format: -1
[libx264 @ 0000014ae3fefc80] Invalid video pixel format: -1
```
This occurred because:
1. `FFIVideoEncoder.ts` attempted to set pixel format and dimensions via `AVCodecParameters` struct using incorrect byte offsets, leaving `AVCodecContext` initialized with `pix_fmt = -1` (`AV_PIX_FMT_NONE`).
2. `safeArrayBuffer` helper in `FFIVideoEncoder.ts` passed `ptr(new BigUint64Array([BigInt(ptrVal)]))` into `toArrayBuffer`, taking the address of a temporary 8-byte JS buffer rather than dereferencing the actual native memory address, corrupting struct reads across `AVStream` and `codecpar`.

## Proposed Plan
1. **Fix Codec Option Configuration**:
   - Explicitly configure dimensions and pixel format on `AVCodecContext` using `av_opt_set` (`"video_size"`, `"1920x1080"`), `"pixel_format"`, and `av_opt_set_int` (`AV_PIX_FMT_YUV420P`).
2. **Fix `safeArrayBuffer` Dereference**:
   - Convert `ptrVal` directly to numeric address for `toArrayBuffer(numPtr, offset, length)`, enabling valid 64-bit native pointer reads.
3. **Robust Fallback**:
   - Ensure clean context deallocation and reinitialization when falling back from NVENC to CPU `libx264`.
4. **Verification**:
   - Run `autogenerated-tests/ffi_primitives.test.ts`, `autogenerated-tests/phase3_depth3d_vision.test.ts`, and full 28-scene `autogenerated-tests/stress_render.test.ts`.

## Changes Made
- `packages/core/src/ffmpeg-ffi/FFIVideoEncoder.ts`:
  - Fixed `safeArrayBuffer` to cast `ptrVal` to `number` without allocating intermediate JS arrays.
  - Replaced faulty `AVCodecParameters` manual byte manipulation with direct `av_opt_set(codecCtx, "video_size", ...)` and `av_opt_set(codecCtx, "pixel_format", ...)`.
  - Added clean context reset on `libx264` fallback.
