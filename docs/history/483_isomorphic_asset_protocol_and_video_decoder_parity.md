# 483: Isomorphic Asset Protocol Resolution & Video Decoder Strategy Parity

## Problem
1. **Direct `fs` File Resolution Bypass**:
   `MediabunnyServerStrategy.ts` bypassed `@acc/core-isomorphic/AssetProtocolRegistry`, directly performing raw `fs.existsSync` checks and `FilePathSource` instantiations. This prevented the server engine from handling non-disk media protocols (`cache:`, `blob:`, `http:`, `data:`), violating the isomorphic runtime mandate.
2. **Missing Client Video Decoder Strategy Parity**:
   While `MediabunnyServerStrategy` implemented `createVideoDecoder()` using `MediabunnyVideoDecoder`, `MediabunnyClientStrategy` lacked `createVideoDecoder()`. Concurrently, `apps/studio/src/renderer/workers/MediabunnyWorkerReader.ts` manually instantiated low-level Mediabunny `Input` and `CanvasSink` rather than delegating to an isomorphic `IVideoDecoder` implementation.
3. **Windows `file:///C:/...` Normalization Defect**:
   In `AssetProtocolRegistry.ts`, parsing `file:///C:/path` stripped the 7-character prefix `file://`, leaving `/C:/path`. On Windows, Node.js `fs.existsSync('/C:/path')` evaluates to `false`, causing disk-backed asset loading failures on Windows host systems.
4. **Premature Frame Deletion in Multi-Track Canvas Compositing**:
   In `IRMasterRenderer.renderCanvasFrame()`, `assetResolver.onAssetDrawn` deleted the decoded video frame from `activeVideoFrames` immediately upon the first sequence's draw call. When multiple concurrent tracks or picture-in-picture sequences referenced the same asset at frame $t$, subsequent sequences encountered a missing texture or blank frame.
5. **Missing Explicit Resource Management**:
   Decoders lacked dual synchronous and asynchronous disposal (`[Symbol.dispose]` and `[Symbol.asyncDispose]`), and `Input.dispose()` was omitted in audio decoding pathways.

## Plan
1. **Extend Core Contracts & Fix Normalization**:
   - Update `IVideoDecoder` in `@acc/core-isomorphic` with dimensions (`width`, `height`, `duration`), `VideoDecoderOptions`, and dual disposal symbols.
   - Fix `AssetProtocolRegistry` to normalize Windows `file:///` URLs (stripping the leading slash before drive letters: `/C:/` $\rightarrow$ `C:/`).
   - Fix `IRMasterRenderer` to recognize `cache:` URIs as absolute and retain active multi-track video frames across all sequences until deterministic frame cleanup in `finally`.
2. **Unify Server Media Engine & Resource Leaks**:
   - Introduce `resolveServerMediabunnySource()` in `MediabunnyServerStrategy.ts` supporting `cache:`, `blob:`, `file:`, `http:`, and `data:`.
   - Update `MediabunnyVideoDecoder` to scale directly via `CanvasSink` target dimensions, return zero-copy pool canvases, implement `[Symbol.dispose]` and `[Symbol.asyncDispose]`, and call `this.input?.dispose()`.
   - Refactor `createAudioDecoder().decodeToPCM` to resolve via `resolveServerMediabunnySource()` and safely dispose `Input` in `finally`.
3. **Implement WinterTC Client Video Decoder & Studio Worker Refactor**:
   - Implement `resolveClientMediabunnySource()` and `MediabunnyClientVideoDecoder` in `@acc/core-web/src/media-engine/MediabunnyClientStrategy.ts` conforming strictly to WinterTC (zero Node.js dependencies).
   - Implement `MediabunnyClientStrategy.createVideoDecoder()`.
   - Refactor `apps/studio/src/renderer/workers/MediabunnyWorkerReader.ts` to wrap `MediabunnyClientVideoDecoder`.
4. **Formal Testing & Verification**:
   - Author `autogenerated-tests/mediabunny_isomorphic_decoder.test.ts`.
   - Verify all existing conformance test suites and execute `@acc/studio` production build.

## Changes
- `packages/core-isomorphic/src/media-engine/types.ts`: Added `VideoDecoderOptions` and extended `IVideoDecoder` with dimensions, duration, and disposal symbols.
- `packages/core-isomorphic/src/assets/AssetProtocolRegistry.ts`: Added Windows file URL normalization (`/C:/` $\rightarrow$ `C:/`) and removed dead code in `CachedAssetBlob.blob()`.
- `packages/ir/src/renderer/IRMasterRenderer.ts`: Updated `isAbsolutePath()` to match `cache:`, and removed premature frame deletion in `onAssetDrawn` for multi-track frame retention.
- `packages/core/src/ffmpeg-ffi/FFIVideoDecoder.ts`: Added `[Symbol.dispose]()` and `[Symbol.asyncDispose]()`.
- `packages/core/src/media-engine/strategies/MediabunnyServerStrategy.ts`: Added `resolveServerMediabunnySource()`, updated `MediabunnyVideoDecoder` with direct scaling and explicit input disposal, and wrapped audio decoding in `finally { input?.dispose(); }`.
- `packages/core-web/src/media-engine/MediabunnyClientStrategy.ts`: Added `resolveClientMediabunnySource()`, implemented `MediabunnyClientVideoDecoder`, added `createVideoDecoder()` factory, and protected audio decoder with `finally { input?.dispose(); }`.
- `apps/studio/src/renderer/workers/MediabunnyWorkerReader.ts`: Refactored to compose `MediabunnyClientVideoDecoder`, delegating frame decoding while maintaining scrub throttling and concurrency gating.
- `autogenerated-tests/mediabunny_isomorphic_decoder.test.ts`: Created comprehensive unit test suite covering protocol normalization, strategy parity, dual disposal, and error handling.
