# History Entry 385: Backend Multi-Tenancy IDOR Elimination & Security RBAC Hardening (Iteration 52 Phase 3)

## Problem & Context
Prior to Phase 3:
1. `WorkflowDefinitionController.java`, `WorkflowExecutionController.java`, `WorkflowApprovalsController.java`, `WorkflowDlqController.java`, and `TaskWorkerController.java` declared `@RequestHeader(value = "X-Tenant-Id", required = false) String headerTenantId` parameters and invoked local `resolveTenantId()` fallbacks.
2. This created an Insecure Direct Object Reference (IDOR) vector contradicting `HeaderSanitizerFilter` (which strips incoming client tenant headers) and bypassed Zero Client Trust contracts.
3. Multiple workflow endpoints lacked method-level `@PreAuthorize` annotations, violating the Principle of Least Privilege and creating an inconsistent security posture compared to `TenantBillingController` and `MetadataController`.

## Plan
1. Strip all `@RequestHeader("X-Tenant-Id")` parameters and remove all local `resolveTenantId()` methods across workflow controllers.
2. Strictly enforce `TenantContextHolder.getRequiredTenantId()` as the single source of truth for tenant identity.
3. Apply granular `@PreAuthorize` authorization annotations across all endpoints:
   - `hasAuthority('WORKFLOW_READ') or hasRole('ADMIN')` for read endpoints.
   - `hasAuthority('WORKFLOW_WRITE') or hasRole('ADMIN')` for execution, resolution, and breakpoint mutations.
   - `hasAuthority('WORKFLOW_ADMIN') or hasRole('ADMIN')` for definition registration and execution migrations.
   - `hasAuthority('ROLE_SYSTEM_CUSTODIAN') or hasAuthority('platform:worker:manage')` for worker fleet and task worker operations.
4. Implement formal verification suite `autogenerated-tests/backend_tenancy_security_rbac.test.ts`.

## Changes Completed
- Refactored in `apps/backend/acc-ms-aio`:
  - `WorkflowDefinitionController.java`: Enforced `TenantContextHolder.getRequiredTenantId()`; applied `@PreAuthorize` (`WORKFLOW_ADMIN`, `WORKFLOW_READ`, `WORKFLOW_WRITE`).
  - `WorkflowExecutionController.java`: Enforced `TenantContextHolder.getRequiredTenantId()`; applied `@PreAuthorize` (`WORKFLOW_WRITE`, `WORKFLOW_READ`).
  - `WorkflowApprovalsController.java`: Enforced `TenantContextHolder.getRequiredTenantId()`; applied `@PreAuthorize` (`WORKFLOW_READ`, `WORKFLOW_WRITE`).
  - `WorkflowDlqController.java`: Stripped `X-Tenant-Id` header parameter; preserved class-level `@PreAuthorize`.
  - `WorkerFleetController.java`: Applied class-level `@PreAuthorize("hasAuthority('ROLE_SYSTEM_CUSTODIAN') or hasAuthority('platform:worker:manage') or hasRole('ADMIN')")`.
  - `TaskWorkerController.java`: Enforced `TenantContextHolder.getRequiredTenantId()`; applied class-level `@PreAuthorize`.
- Created:
  - `autogenerated-tests/backend_tenancy_security_rbac.test.ts`: Formal AST assertions verifying absolute absence of `X-Tenant-Id` and 100% `@PreAuthorize` presence.

  - All workflow controllers strictly query `TenantContextHolder.getRequiredTenantId()`.
  - 100% of workflow endpoints have valid `@PreAuthorize` annotations adhering to the Principle of Least Privilege.
