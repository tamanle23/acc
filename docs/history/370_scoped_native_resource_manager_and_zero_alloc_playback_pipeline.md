# 370: Scoped Native Resource Manager & Zero-Alloc Video Playback Pipeline

## Problem
During continuous timeline playback in Studio, Chrome's task manager reported native GPU memory ballooning over 1GB–2GB. Root cause analysis revealed three architectural defects:
1. **Unbounded Mid-Frame Allocations in IR Plugins (`Depth3DPlugin`, `Camera3DPlugin`, `frame-breaker`)**: On every 33ms frame tick (30 FPS), plugins were executing `resolveSubjectCutout`, `resolveDepthMapData`, `createImageBitmap`, scratch canvas allocations, and dynamic particle object creation per frame. Because V8 garbage collection is asynchronous and decoupled from native GPU memory reclamation, native buffers accumulated into gigabytes.
2. **Per-Frame WebCodecs Decoding Allocations**: In `MediabunnyWorkerReader`, `requestFrame` invoked `createImageBitmap(raw)` per frame tick during playback, producing ~250MB/s of unmanaged GPU textures.
3. **Main-Thread React Texture Thrashing**: When timeline playback advanced, React state updates triggered `syncTextures()` and duplicate `renderFrame()` calls from the main thread into the dedicated worker thread, creating race conditions and redundant texture transfers.

## Plan
Implement the four pillars defined in `docs/iterations/master_implementation_plan_iteration_45.md`:
1. **Scoped Native GPU Resource Engine (RAII) in `@acc/core-isomorphic`**: Create `NativeResourceManager`, `FrameResourceScope`, and `SequenceResourceScope` enforcing an immutable 64MB GPU memory ceiling with synchronous LRU eviction.
2. **Strict Zero-Alloc Frame Loop in IR Plugins**: Pre-bake textures (subject cutout, depth canvases, normal maps, background plates) during Phase 1 preflight (`execute()`) and register them to `SequenceResourceScope`. Make `renderClipSpace()` strictly synchronous and zero-alloc. Statically pre-allocate typed particle arrays.
3. **Sequential Video Reader & Circular Double-Buffer**: Pre-allocate exactly two `OffscreenCanvas` instances (Slot A and Slot B) in `SequentialVideoReader`. Alternating pointers on each frame tick without creating any intermediate `VideoFrame` or `ImageBitmap` allocations per frame.
4. **Decouple React UI from Worker Playback**: Block `syncTextures()` and duplicate `renderFrame()` calls when `isPlaying === true`, ensuring complete sovereignty of the worker RAF loop.

## Walkthrough
1. When playback starts, `PreviewWorkerBridge.startPlayback()` flags `isPlaying = true`.
2. The worker's RAF loop renders frames sequentially. For video tracks, `SequentialVideoReader` paints Frame N on Slot A and pre-paints Frame N+1 on Slot B via `OffscreenCanvas.drawImage()`. No `VideoFrame` or `ImageBitmap` objects are created.
3. For sequence modifiers (`Depth3DPlugin`, `Camera3DPlugin`), all textures are retrieved synchronously from `SequenceResourceScope`. No allocations occur mid-frame.
4. Any transient canvas acquired during the frame is registered in `FrameResourceScope` and synchronously disposed in `renderCurrentFrame`'s `finally` block.
5. React UI texture syncing and main-thread render dispatches are blocked while playing, ensuring zero frame thrashing.
