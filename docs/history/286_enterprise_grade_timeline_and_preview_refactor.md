# Task 286: Enterprise-Grade Video Editing Preview, Timeline & Isomorphic Canvas Refactor

## Context & Problem
The video editing timeline in `apps/studio` previously relied heavily on DOM-level track and clip layouts with direct React element tree mapping, individual WaveSurfer waveform DOM container instances, and floating-point IEEE-754 time tracking. This created:
1. Significant main-thread DOM diffing and GC pressure during 60/120fps playback and scrub cycles.
2. Jitter and floating-point time drift across high-framerate scrub sequences.
3. Memory and GC spikes caused by repeated `createCanvas` allocations inside the frame rendering loop across 50+ VFX and filter generators.
4. Risk of browser GPU out-of-memory crashes due to undisposed `ImageBitmap` objects in thumbnail filmstrips.

## Architecture & Implementation
We executed the master integration plan for Iteration 17 across five key pillars:

### 1. SMPTE / OTIO RationalTime Arithmetic (`@acc/core-isomorphic`)
- Created `packages/core-isomorphic/src/math/time/RationalTime.ts` with BigInt backing and a standard 10MHz (`10_000_000`) master timescale.
- Guarantees exact integer divisibility across all film, broadcast, and gaming framerates (23.976, 24, 25, 29.97, 30, 48, 50, 59.94, 60, 120, 240 fps) and audio sampling rates (44.1kHz, 48kHz, 96kHz).
- Integrated `RationalTime` directly into `DeterministicTimelineClock.ts` and `ClockState`.

### 2. Universal Canvas Scratch Pool (`packages/core`)
- Created `packages/core/src/isomorphic/canvas/CanvasScratchPool.ts` implementing tiered resolution bucketing (256x256, 512x512, 1280x720, 1920x1080).
- Exposed `UniversalCanvasProvider.acquireScratchCanvas(w, h)` and `releaseScratchCanvas(canvas)` to eliminate per-frame allocations across the 50+ `createCanvas` call sites in overlay generators, vision filters, and IR renderers.

### 3. Two-Tier Dedicated Worker Architecture & OffscreenCanvas Rendering
- Created `apps/studio/src/workers/timeline.worker.ts` and `apps/studio/src/lib/timeline/TimelineWorkerBridge.ts`.
- Offloads track lane, clip block, and thumbnail rendering to a dedicated Web Worker via `canvas.transferControlToOffscreen()`.
- Main thread retains high-frequency playhead needle, timecode ruler, and cyan snaplines running on an overlay canvas driven by `requestAnimationFrame`, bypassing React DOM reconciliation.

### 4. Viewport Virtualization & Memory Hygiene
- **1D Interval Tree**: Augmented interval tree index in `timeline.worker.ts` performing $O(\log N)$ horizontal culling of visible clips within $[T_{\text{start}}, T_{\text{end}}]$.
- **WaveformLODPyramid**: Created `apps/studio/src/lib/timeline/WaveformLODPyramid.ts` with 4 decimation levels (1:1, 4:1, 16:1, 64:1), maintaining $O(1)$ peak draw complexity across arbitrary zoom scales ($px/\text{frame}$).
- **ThumbnailLRUCache**: Created `apps/studio/src/lib/timeline/ThumbnailLRUCache.ts` with explicit `.close()` disposal on evicted `ImageBitmap` instances to eliminate browser GPU memory leaks.
