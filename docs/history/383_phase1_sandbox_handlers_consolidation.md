# History Entry 383: Unified Sandbox Domain Handler Consolidation & Zero-Trust Token Derivation (Iteration 52 Phase 1)

## Problem & Context
Prior to this phase:
1. `apps/console/src/core/sandbox/handlers/` maintained duplicate copies of `billing`, `users`, `workspace`, `auth`, `apps`, `chats`, and `system` handlers, containing thousands of lines of diverging mock logic.
2. Several handlers trusted client `x-tenant-id` headers or fell back to global store state without inspecting authentication credentials, creating IDOR and impersonation risks inconsistent with production backend Zero Client Trust contracts.

## Plan
1. Implement canonical `extractTenantFromAuth` in `packages/sandbox/src/tenant-auth.ts`:
   - Derive tenant identity strictly from verified Bearer JWT claims (`decodeJwt(token)?.tenantId`).
   - Reject unauthenticated or invalid token requests with strict `401 Unauthorized`.
   - Disregard any client-supplied `x-tenant-id` header.
2. Update `packages/sandbox/src/handlers/` (`users-sandbox-handler.ts`, `billing-sandbox-handler.ts`, `workspace-sandbox-handler.ts`) to enforce `extractTenantFromAuth`.
3. Refactor all duplicate handlers in `apps/console/src/core/sandbox/handlers/` into thin re-export adapters pointing to `@acc/sandbox`.
4. Create formal verification test suite `autogenerated-tests/sandbox_handlers_consolidation.test.ts`.
