# History Record 400: Backend Sandbox Two-Tier Safeguards & In-Process PGlite WASM Synchronization

## 1. Problem
During `pnpm dev:sandbox` execution, the Spring Boot application failed to initialize with:
```
Caused by: org.postgresql.util.PSQLException: FATAL: database "acc" does not exist
```
Investigation revealed that:
1. `acc-sandbox/pom.xml` previously declared `io.github.jakvbs:pglite-spring-boot-test:0.4.0` with `<optional>true</optional>`, whereas `PgLiteDatasourceConfiguration.java` queried `io.roastedroot.pglite4j.jdbc.PgLiteDriver`.
2. When the driver failed to load via reflection, `PgLiteDatasourceConfiguration` silently fell back to an external PostgreSQL instance on `localhost:5432/acc`, which failed when the database did not exist on the host machine.
3. Furthermore, `acc-sandbox` was unconditionally included in `acc-ms-aio/pom.xml`, creating a security and architectural risk that development/sandbox beans could be bundled into release fat JARs or activated in production, SIT, or UAT environments.

## 2. Plan
1. **In-Process WebAssembly PGlite**:
   - Add `io.roastedroot:pglite4j:0.0.3` directly to `apps/backend/pom.xml` (`<dependencyManagement>`) and `apps/backend/acc-sandbox/pom.xml` (non-optional).
   - Refactor `PgLiteDatasourceConfiguration.java` to fail-fast with `IllegalStateException` on missing driver and purge all `localhost:5432/acc` and `ensurePostgresDatabaseExists` fallback code.
2. **Safeguard Level 1 (Early Runtime Lockdown)**:
   - Implement `SandboxEnvironmentPostProcessor` implementing `EnvironmentPostProcessor` and `Ordered.HIGHEST_PRECEDENCE`.
   - Abort boot immediately with `SecurityException` if `application.sandbox.enabled=true` under restricted profiles (`prod`, `production`, `sit`, `uat`).
   - Register via `apps/backend/acc-sandbox/src/main/resources/META-INF/spring.factories`.
   - Explicitly declare `application.sandbox.enabled: false` in `application-prod.yml`, `application-sit.yml`, and `application-uat.yml`.
   - Add JUnit 5 test `SandboxEnvironmentPostProcessorTest.java`.
3. **Safeguard Level 2 (Build-Time Packaging Exclusion)**:
   - Move `acc-sandbox` in `apps/backend/acc-ms-aio/pom.xml` into a Maven profile `sandbox` (active by default when `!excludeSandbox`).
   - Add profiles `prod`, `sit`, and `uat` setting `<excludeSandbox>true</excludeSandbox>`.
   - Add npm convenience scripts `build:prod` and `build:no-sandbox` to root `package.json` and `apps/backend/package.json`.
4. **Verification**:
   - Create formal verification test suite `autogenerated-tests/backend_sandbox_safeguards.test.ts`.

## 5. Walkthrough
1. **Developer Experience**: Running `pnpm dev:sandbox` loads the in-process WebAssembly PostgreSQL 17 engine (`io.roastedroot.pglite4j.jdbc.PgLiteDriver`) with persistent file-backed storage (`tmp/db/pglite-sandbox`) or in-memory mode without requiring external PostgreSQL instances or Docker.
2. **Runtime Security Guard**: If a developer or CI misconfiguration attempts to pass `-Dapplication.sandbox.enabled=true` with `-Dspring.profiles.active=prod` (or `sit`/`uat`), `SandboxEnvironmentPostProcessor` halts the JVM with a `SecurityException` at `HIGHEST_PRECEDENCE` before any beans or database connections are initialized.
3. **Packaging Security Guard**: Running `pnpm build:prod` packages `acc-ms-aio` with `-Pprod -DexcludeSandbox`, completely omitting `acc-sandbox.jar` from `BOOT-INF/lib/`.
