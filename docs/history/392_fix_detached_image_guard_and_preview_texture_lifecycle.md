# 392. Fix Detached Image Guard and Preview Texture Lifecycle

## Problem
During direct gizmo manipulation (dragging or resizing) in the Studio viewport, an uncaught promise rejection occurred:
```
wrapCanvasContext.ts:26 Uncaught (in promise) InvalidStateError: Failed to execute 'drawImage' on 'OffscreenCanvasRenderingContext2D': The image source is detached
    at rawCtx.drawImage (wrapCanvasContext.ts:26:28)
    at drawFrameBreakerFrame (frame-breaker.ts:216:7)
    at FrameBreakerRenderer.renderFrame (core-renderers.ts:11:5)
    at Depth3DPlugin.renderClipSpace (Depth3DPlugin.ts:439:18)
```
### Root Causes:
1. **Premature Texture Disposal During Async Rendering**:
   When interactive gizmo transforms produce rapid 60 FPS pointer move events, `preview.worker.ts` handles subsequent texture updates via `safeSetTexture`. If an asynchronous plugin pass (such as `Depth3DPlugin.renderClipSpace`, which awaits neural cutout or depth maps) is in-flight, `safeSetTexture` was eagerly calling `existing.close()` on the previous `ImageBitmap`. This detached the underlying pixel buffer while the in-flight render was awaiting and preparing to draw it with `ctx.drawImage`.
2. **Missing Async Frame Synchronization in Worker**:
   `preview.worker.ts`'s `renderCurrentFrame` did not await the async composition result of `engine.renderFrame`. Its `finally` block immediately ran `frameScope.dispose()`, `ctx.restore()`, and reset `isRendering = false` while asynchronous plugin draw passes were still in-flight.
3. **Absence of Defensive Guarding in `wrapCanvasContext`**:
   Neither `wrapCanvasContext.ts` nor `frame-breaker.ts` guarded against detached or closed image sources (e.g. `width === 0`, `height === 0`), violating the universal defensive coding invariant (`Never crash main render loop; wrap volatile/AI calls in try/catch with fallbacks`).
4. **Redundant Texture Sync Triggers**:
   In `Preview.tsx`, `activeSequences` was computed directly via `irState.intervalTree?.queryActive(currentFrame) || []` without memoization. Every gizmo drag movement updated React state (`transform`), causing `Preview` to re-render with a new array reference for `activeSequences`. This triggered `useViewportRenderStrategy`'s `useEffect` to fire `syncTextures` on every pixel of mouse movement.

---

## Plan
1. **Defensive Canvas Context Wrapping (`wrapCanvasContext.ts`)**:
   - Add zero-dimension and detached buffer checks (`width === 0`, `height === 0`, `displayWidth === 0`).
   - Catch `InvalidStateError` and detached/closed buffer exceptions in `drawImage` and `createPattern`, skipping invalid draws gracefully rather than crashing the render loop.
2. **Frame-Breaker Aspect Ratio and Fallback (`frame-breaker.ts`)**:
   - Safeguard image dimension calculations against 0 dimensions to prevent `NaN` aspect ratios.
   - Wrap inner frame `ctx.drawImage` in a try/catch with dark card fallback.
3. **Async Composition Synchronization in `IRPreviewEngine`**:
   - Introduce `renderFrameAsync` returning `Promise<PreviewFrameResult>` and ensuring RAII cleanup only occurs after `IRCanvasCompositor.renderFrame` completes.
   - Add `.catch(...)` error handler to `renderFrame` to eliminate unhandled promise rejections.
4. **Deferred Texture Disposal Queue in `preview.worker.ts`**:
   - Introduce `textureDisposalQueue` and `drainDisposalQueue()`.
   - When `safeSetTexture` replaces an existing texture while `isRendering === true`, push the old texture into `textureDisposalQueue` instead of closing it immediately.
   - Drain and close queued textures only in `renderCurrentFrame`'s `finally` block after `await engine.renderFrameAsync` resolves.
5. **Memoize Active Sequences in `Preview.tsx`**:
   - Wrap `activeSequences` query in `useMemo([irState.intervalTree, currentFrame])` to prevent spurious texture synchronization on mouse move events.
6. **Verification & Regression Testing**:
   - Create unit tests in `autogenerated-tests/detached_image_guard.test.ts`.

## Changes
- `packages/core-isomorphic/src/canvas/wrapCanvasContext.ts`:
  - Added `isDetachedOrInvalid` predicate.
  - Wrapped `origDrawImage` and `origCreatePattern` with defensive `try/catch` handlers for `InvalidStateError` / detached image sources.
- `packages/effect-engines/src/depth3d/frame-breaker.ts`:
  - Guarded `imgW` and `imgH` against 0/NaN dimensions.
  - Added defensive fallback for inner scene `ctx.drawImage`.
- `apps/studio/src/renderer/IRPreviewEngine.ts`:
  - Added `renderFrameAsync` for explicit Promise-based composition.
  - Added `.catch(...)` rejection handler in synchronous `renderFrame`.
- `apps/studio/src/renderer/workers/preview.worker.ts`:
  - Turned `renderCurrentFrame` into an `async` function and awaited `engine.renderFrameAsync`.
  - Added `textureDisposalQueue` to defer `.close()` calls during active frame rendering.
- `apps/studio/src/components/Preview.tsx`:
  - Memoized `activeSequences` using `useMemo` with `[irState.intervalTree, currentFrame]`.
- `autogenerated-tests/detached_image_guard.test.ts`:
  - Created formal unit tests covering zero-dimension checks, `InvalidStateError` interception, and `IRPreviewEngine` async composition.

## Walkthrough
1. **Interactive Gizmo Manipulation**:
   - Moving or resizing a gizmo overlay on an image sequence with `vfx/depth3d` no longer causes detached image rejections.
   - Active render passes retain their underlying `ImageBitmap`s until rendering finishes; any subsequent textures pushed during the render wait in `textureDisposalQueue`.
2. **Defensive Render Loop**:
   - If a buffer is closed concurrently by any external subsystem or transfer boundary, `wrapCanvasContext` intercepts the `InvalidStateError` and preserves render loop stability.
