# Task 429: Hide OPFS Companion Metadata Files (*.meta.json) in Studio Debugger

## Problem
In ACC Studio's OPFS Explorer Debugger modal (`Ctrl+Shift+O`), every cached media file is accompanied on disk by a companion metadata JSON file (`<filename>.meta.json`). `OpfsTree.tsx` was rendering both the raw media file and its `.meta.json` file as sibling rows in the directory tree. This produced visual clutter and duplicate rows. Furthermore, selecting the primary media file already loads and displays its companion metadata inside `OpfsFilePreview.tsx`'s dedicated Metadata Inspector tab, making standalone `.meta.json` rows redundant and confusing.

## Plan
1. **Unconditional Metadata Exclusion**:
   - In `apps/studio/src/components/debugger/opfs/OpfsTree.tsx`, add an `isMetadataFile` helper that detects `node.isMetadata` and case-insensitive filename suffix `/\.meta\.json$/i`.
   - Update `filterNode` to reject any metadata companion files immediately, preventing them from appearing in directory listings, search query results, or JSON category filters.
   - Guard `filteredRoot` so that if the root node itself is a metadata file, it resolves to `null`.
2. **Filter Chips Refinement**:
   - Remove the obsolete `'meta'` chip from the filter chips bar in `OpfsTree.tsx` so only actionable content categories (`ALL`, `MEDIA`, `JSON`, `OTHER`) are shown.
3. **Formal Verification**:
   - Add unit and integration tests in `autogenerated-tests/studio_opfs_tree_metadata_filter.test.ts`.
   - Run tests, check schema drift, and build `@acc/studio`.

## Changes
- **`apps/studio/src/components/debugger/opfs/OpfsTree.tsx`**:
  - Exported `isMetadataFile(node: OpfsTreeNode): boolean`.
  - Filtered out all `*.meta.json` files unconditionally in `filterNode`.
  - Updated filter chips list to `['all', 'media', 'json', 'other']`.
  - Guarded `filteredRoot` for metadata files.
