# 485: Fix Video Decoder Retry Storm, Negative Caching & Dead Getty Images Demo URL

## Problem
During timeline scrubbing or playback in Studio, hundreds of repeated console warnings flooded the browser console:
```
MediabunnyWorkerReader.ts:83 [MediabunnyWorkerReader] Failed to initialize video https://media.gettyimages.com/id/1340037487/video/the-matrix-reloaded-cast-…s.mp4?s=mp4-640x640-gi&k=20&c=QmuoEVN4gNDv1DFmosfSTKNY5_OgW0MB29aWUAQw1nM=
```
This warning repeated up to 60 times per second, saturating CPU cycles, spamming devtools, and stalling WebCodecs worker thread performance.

### Root Causes
1. **Missing Negative Caching & Cooldown in `MediabunnyWorkerReader`**:
   When `init()` failed to open a video, it set `isInitializing = false` and returned `false`. On every subsequent animation frame (30–60fps), `preview.worker.ts` invoked `decoderPool.acquireLease(assetId)`. Because `reader.getIsInitialized()` was false, `acquireLease()` invoked `reader.reacquireHardwareDecoder()`. That method reset `this.initPromise = null` and re-invoked `this.init()`, creating a continuous 60fps retry storm.
2. **Missing Negative Caching in `WebCodecsDecoderPool`**:
   `WebCodecsDecoderPool.acquireLease()` had no check for readers in a failed cooldown state, blindly attempting hardware re-acquisition on every tick.
3. **Dead Getty Images Demo Video URL in Demo IR Templates**:
   `defaultDemoIR.ts` and `complexSciFiDemoIR.ts` referenced an old Getty Images URL for `asset-matrix-core`. Getty Images media blocks hotlinking and CORS from browser origins, failing network range requests. In `footageBank.ts`, `footage_matrix_rain` was already defined as `type: 'image'` with the live Unsplash matrix digital stream photo (`photo-1526374965328-7f61d4dc18c5`), while the demo IR templates had an outdated placeholder.

## Plan
1. **Implement Negative Caching & Backoff Cooldown in `MediabunnyWorkerReader`**:
   - Add `failedAt` timestamp tracking and `RETRY_COOLDOWN_MS = 30_000` (30s cooldown).
   - In `init()` and `reacquireHardwareDecoder()`, check `isFailed()` and return `false` immediately without re-triggering network or logging warnings during the cooldown.
   - On initialization failure, record `failedAt = performance.now()` and emit `console.warn` once. On success, reset `failedAt = 0`.
2. **Implement Guard in `WebCodecsDecoderPool`**:
   - In `acquireLease()`, if `item.reader.isFailed()`, immediately return `false` to suppress repeated hardware allocations.
3. **Replace Dead Demo Video URL**:
   - In `defaultDemoIR.ts` and `complexSciFiDemoIR.ts`, replace the dead Getty Images URL with the live, CORS-enabled Unsplash matrix photo (`photo-1526374965328-7f61d4dc18c5`) with `type: 'image'`.
4. **Automated Verification**:
   - Create `autogenerated-tests/mediabunny_worker_reader_backoff.test.ts` to verify cooldown behavior, single warning emission, and pool fast-rejection.
   - Run full test suites and verify production build.
