# 383. Studio Inspector Simplification: Keyframe Diamond Elimination & Pure Sequence Controls

## Problem
1. **Misleading Keyframe Diamond UI**: In `apps/studio`, `NumberControlStrategy` embedded a `KeyframeDiamondButton` on every numerical property (e.g. contrast, saturation, exposure, volume, particle count). When users clicked the diamond, it wrote a `TemporalCurve` object (`{ keyframes: [...] }`) to `modifier.params`, but downstream plugins and engines evaluated `Math.round({} * 100) === NaN%` and the schema validator rejected non-numeric parameters.
2. **Premature Universal Architecture Complexity**: Introducing a complex multi-layer `TemporalParamResolver` across the entire compositor pipeline was over-engineered and rarely needed in practice, as keyframing in NLEs is largely specialized per use case (Transform/Motion and 3D Splines).
3. **User Intent Alignment**: The user chose to drop the Universal Temporal Keyframe plan completely, eliminate `KeyframeDiamondButton`, and treat sequence inspector properties purely as static sequence-level values without keyframe branching.

## Plan
1. Drop the Universal Temporal Keyframe plan artifact.
2. Refactor `PrimitiveControlStrategies.tsx` (`NumberControlStrategy`) to remove `KeyframeDiamondButton`, eliminate all `isKeyframed`, `keyframes`, `currentTimeSec`, and `usePlayheadFrame` dependencies, and treat values purely as static sequence-level numbers.
3. Safely delete obsolete `apps/studio/src/components/inspector/KeyframeDiamondButton.tsx`.
4. Verify with full studio test suites and production Vite build.

## Changes
- `apps/studio/src/components/inspector/strategies/PrimitiveControlStrategies.tsx`: Removed `KeyframeDiamondButton` and all keyframe state/branching logic. Cleaned up `NumberControlStrategy` to directly bind number input and slider to sequence-level scalar values.
- `apps/studio/src/components/inspector/KeyframeDiamondButton.tsx`: Deleted obsolete file.
