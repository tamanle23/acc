# 478. Establish 100% Isomorphic and WinterTC Compliant Architecture in @acc/effect-engines

## Problem
`packages/effect-engines` was originally conceived as a shared effects library for audio DSP, depth mapping, overlays, and color grading. However, architectural debt accumulated over time, causing severe runtime coupling and portability issues:
1. **Node.js Binary Leaks (`Buffer`)**: `packages/effect-engines/src/vision/types.ts`, `utils.ts`, and 11 vision estimation/segmentation strategies used Node's global `Buffer` or `Buffer.isBuffer()` / `Buffer.from()` instead of standard Web/WinterTC binary representations (`Uint8Array`, `ArrayBuffer`). This caused runtime failures in standard Web Workers, Cloudflare Workers, and WinterTC-compliant edge environments.
2. **Ghost Dependencies & Redundant Bundle Overhead**:
   - `packages/effect-engines/package.json` declared `pts` (Point/Space computation library) which was never imported across the package.
   - `gsap` was imported in `DeterministicParticleField.ts` merely to calculate basic mathematical easing curves (`power2.out`, `sine.inOut`, `expo.inOut`), inflating bundle size and pulling Node/DOM dependencies into pure mathematical simulators.
3. **Canvas Context Interface Inconsistency (`any` vs `ICanvasContext2D`)**: Multiple renderers (`Depth3DPlugin`, `TrackingCalloutEngine`, `captions-canvas`, `ColorGradingEngine`) accepted `ctx: any` rather than the canonical `ICanvasContext2D` abstraction from `@acc/core-isomorphic`, bypassing compile-time safety and type hinting.
4. **Non-Standard & Inefficient Asset Ingestion**: `loadAssetBytes` in `src/depth3d/index.ts` relied only on protocol handlers without standard Web `fetch()` fallback or caching integration. Furthermore, vision depth/segmentation strategies serialized `ICanvasInstance` to PNG buffers (`toBuffer('image/png')`), only for callers to immediately re-decode them with `createImageBitmap` / `loadImage`, introducing substantial CPU overhead and worker decode failures.

## Plan
1. **WinterTC Binary Conformance**:
   - Update `packages/effect-engines/src/vision/types.ts` to re-export isomorphic vision primitives from `@acc/core-isomorphic` (`SubjectSegmentationResult`, `DepthEstimationResult`, `VisionImageInput`).
   - Standardize all 11 vision strategies (`BiRefNet`, `Rmbg`, `Sam2Tiny`, `SamVitBase`, `SlimSam`, `GrabCutFallback`, `DepthAnythingV2Small`, `DepthAnythingV2Base`, `DptLarge`, `GlpnMetric`, `HeuristicDepth`) on `Uint8Array` and live `ICanvasInstance` passing.
   - Guard Node-only modules (`require('os')`) and replace `Buffer.isBuffer` with `input instanceof Uint8Array`.
2. **Dependency Pruning & Closed-Form Math Easing**:
   - Remove unused `pts` and `gsap` dependencies from `packages/effect-engines/package.json`.
   - Implement `IsomorphicEasing` in `src/overlay-effects/utils/IsomorphicEasing.ts` with pure closed-form functions for `power2Out`, `power2In`, `sineInOut`, `expoInOut`, and `linear`.
   - Re-route `DeterministicParticleField.ts` to use `IsomorphicEasing`.
3. **Canvas Interface Strictness**:
   - Enforce `ICanvasContext2D` across `IDepth3DRenderer.renderFrame`, `ColorGradingEngine.applyCanvasTransform`, `TrackingCalloutEngine.renderTrackingCallout`, and `drawCanvasCaptionsFromSnapshot`.
4. **Universal Asset Ingestion & Zero-Re-Encode Pipeline**:
   - Upgrade `loadAssetBytes` to cascade: Memory Cache -> `AssetProtocolRegistry` -> Web standard `fetch()`.
   - Preserve and reuse live `depthCanvas` and `maskCanvas` directly in `resolveDepthMapData` and `resolveSubjectCutout` to eliminate redundant PNG encode/decode roundtrips.
5. **Formal Verification**:
   - Add comprehensive tests in `autogenerated-tests/effect_engines_pure_isomorphic.test.ts` verifying WinterTC conformance, pure math easing precision, canvas rendering, and `Uint8Array` strategy operations.
   - Verify all existing effect-engines and particle VFX test suites pass.
   - Run production studio build.
