# 462. Preview Playback Black Flashing Resolution & RAM Optimization

## Problem
During timeline playback in `@acc/studio`, preview video playback exhibited frequent black flashing across multiple frame rates (24, 25, 29.97, 30, 60 FPS). Concurrently, Chrome's Task Manager reported memory consumption exceeding ~1.5 GB for the studio tab.

Investigation revealed four interacting root causes:
1. **Premature Shared Canvas Texture Eviction**: In `preview.worker.ts`, after rendering each frame, textures were aggressively discarded from `textureCache` via `onAssetDrawn` and in the `finally` block. The circular ping-pong slot canvases (`canvasA` and `canvasB`) in `SequentialVideoReader` were not marked as shared, causing them to be wiped/cleared between frames.
2. **Missing Hold-on-Miss Mechanism**: When video decoding experienced even a millisecond of jitter or when switching between clip boundaries, `SequentialVideoReader.getFrameCanvas()` returned `null`. Because textures had been discarded, `IRCanvasCompositor` painted an opaque black/dark fallback rectangle (`rgba(20, 20, 28, 0.4)` / `#000000`), appearing visually as rapid black flicker.
3. **Duplicate Web Worker Thread Allocation**: Both `WorkerRenderStrategy` and `PreviewWorkerCoordinator` independently instantiated `new Worker(new URL('./workers/preview.worker.ts', import.meta.url))`. Each worker loaded the entire bundle (transformers, ONNX WASM, Mediabunny, audio pipelines), duplicating ~500–700 MB of heap memory.
4. **Redundant Decoding Lookaheads**: `WorkerClipPrewarmer` was pre-decoding 4 sequential lookahead frames into `PreviewFrameMemoryManager` concurrently while `SequentialVideoReader` was actively decoding into ping-pong slots during continuous playback, leading to thread contention and unclosed GPU texture allocations.

## Plan
1. **Implement Zero-Blackout Hold-On-Miss**:
   - Update `SequentialVideoReader` so slot canvases are created with `_isShared = true` to protect them from lifecycle disposal.
   - On decode latency or missed frames, return the currently active canvas (`this.getActiveCanvas()`) instead of `null`.
   - Provide headless/universal canvas fallback for non-DOM test environments via `UniversalCanvasProvider`.
2. **Protect Shared Ping-Pong Assets in Worker**:
   - In `preview.worker.ts`, update `onAssetDrawn` and frame cleanup routines to check `!(asset as any)._isShared` before evicting textures.
3. **Unify Preview Worker Threads**:
   - Refactor `PreviewWorkerBridge` into a singleton (`PreviewWorkerBridge.getInstance()`) and expose `getWorker()` and `addMessageListener()`.
   - Wire `PreviewWorkerCoordinator` to reuse the singleton worker from `PreviewWorkerBridge` rather than spawning a duplicate worker.
4. **Eliminate Redundant Sequential Lookahead During Playback**:
   - Refactor `WorkerClipPrewarmer.ts` to bypass sequential lookahead decoding during active playback (`isPlaying === true`), reserving lookahead solely for next-clip frame 0 discovery.
5. **Throttled Timeline Preflight**:
   - In `useViewportRenderStrategy.ts`, avoid invoking `preflightTimeline` on every frame tick; invoke only when timeline reference changes.
6. **Formal Verification**:
   - Author `autogenerated-tests/studio_preview_playback_cadence.test.ts` to verify slot canvas protection, hold-on-miss behavior, and monotonic clock advancement across all standard frame rates.
   - Run existing test suites (`studio_solid_migration_architecture.test.ts`, `studio_liquid_glass_theme.test.ts`) and full production build.

## Changes

### `apps/studio/src/renderer/workers/SequentialVideoReader.ts`
- Marked `canvasA` and `canvasB` with `(canvasA as any)._isShared = true` and `(canvasB as any)._isShared = true`.
- Integrated `UniversalCanvasProvider.createCanvas()` fallback so `SequentialVideoReader` runs reliably in headless Node/Bun test environments as well as browser OffscreenCanvas environments.
- Implemented hold-on-miss: when a requested frame cannot be decoded in time or is not yet ready, `getFrameCanvas()` returns `this.getActiveCanvas()` if a previously rendered frame exists, completely eliminating black frame flashes.

### `apps/studio/src/renderer/workers/preview.worker.ts`
- In `workerAssetResolver.onAssetDrawn`, guarded texture cache eviction with `!(asset as any)._isShared`.
- In the rendering loop `finally` block, preserved shared slot assets while continuing to evict one-off dynamic frames.

### `apps/studio/src/renderer/workers/WorkerClipPrewarmer.ts`
- Removed redundant sequential lookahead decoding during active playback (`isPlaying === true`), preventing double-decoding pipelines and GPU texture bloat.
- Retained boundary prewarming for upcoming clips at frame 0.

### `apps/studio/src/renderer/workers/PreviewWorkerBridge.ts`
- Transformed `PreviewWorkerBridge` into a singleton with `getInstance()`.
- Added `getWorker()` and `addMessageListener()` to enable sharing the worker across rendering strategies and coordinator.

### `apps/studio/src/renderer/strategies/WorkerRenderStrategy.ts`
- Updated constructor to acquire the worker via `PreviewWorkerBridge.getInstance()`.

### `apps/studio/src/renderer/PreviewWorkerCoordinator.ts`
- Refactored `initWorker()` to acquire the singleton worker from `PreviewWorkerBridge.getInstance()` and register its listener via `addMessageListener()`, eliminating duplicate Web Worker threads.

### `apps/studio/src/components/preview/useViewportRenderStrategy.ts`
- Memoized/throttled `preflightTimeline` invocation to trigger strictly on timeline structure changes rather than per-frame render ticks.

### `autogenerated-tests/studio_preview_playback_cadence.test.ts`
- Created dedicated test suite validating:
  1. Slot canvas initialization with `_isShared = true`.
  2. Zero-blackout hold-on-miss returning active canvas on miss instead of `null`.
  3. Deterministic timeline clock monotonicity across 23.976, 24, 25, 29.97, 30, 60, and 120 FPS.

## Walkthrough
- During active playback, `PreviewWorkerCoordinator` and `WorkerRenderStrategy` now communicate over a single shared `preview.worker.ts` Web Worker instance.
- As frames advance across the timeline (whether 24, 30, or 60 FPS), `SequentialVideoReader` decodes frames into alternating ping-pong canvases (`canvasA` and `canvasB`).
- When a frame decode takes longer than a single frame interval, `SequentialVideoReader` returns the last successfully decoded slot canvas (`this.getActiveCanvas()`) instead of `null`.
- The compositor draws the held frame seamlessly without dropping to the black fallback rectangle.
- Memory consumption is curtailed by eliminating the duplicate worker thread and eliminating unneeded sequential lookahead decodes during playback.
