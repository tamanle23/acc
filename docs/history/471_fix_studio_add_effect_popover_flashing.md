# 471. Fix Studio Add Effect Popover Flashing

## Problem
When clicking the "+ Add Effect" button in `apps/studio/src/components/RightSidebar.tsx` / `InspectorHeader.tsx`, the modifier command palette popover (`ModifierAddPicker.tsx`) flashed/flickered continuously and closed approximately 17ms after mounting.

### Root Causes
1. **Kobalte Popover `onFocusOutside` False-Positive Trap**:
   In `@kobalte/core/popover` (`DismissableLayer`), when `modal: false` (the default for studio popovers), `createFocusScope` automatically moves focus to the first tabbable child (the search `<input>` inside `ModifierAddPicker`). When the `focusin` event fired on the input during Portal mounting, Kobalte's `createInteractOutside` handler received the event in the capture phase. Because of timing differences during portal element attachment, `containsComposed(ref(), target)` evaluated to `false`, treating the focus on its own child input as an "outside focus" event. Because `modal: false`, `onFocusOutside` did not prevent default, immediately calling `local.onDismiss()` and triggering `onOpenChange(false)` just 17ms after mounting.
2. **SolidJS JSX Slot Reactive Dependency Inversion**:
   In `InspectorHeader.tsx`, the add effect launcher was structured as:
   ```tsx
   <Show when={props.addEffectSlot}>
     {props.addEffectSlot}
   </Show>
   ```
   In SolidJS's JSX compilation, passing JSX expressions as props compiles to getters (`get addEffectSlot() { return _$createComponent(ModifierAddPicker, ...); }`). Wrapping this getter in `<Show when={props.addEffectSlot}>` established a reactive dependency on all signals accessed within `ModifierAddPicker` (including `isAddPickerOpen()`). Whenever `isAddPickerOpen()` toggled between `false` and `true`, the `when` condition re-evaluated, tearing down the existing DOM and component tree and mounting a brand new instance of `ModifierAddPicker`.
3. **Native HTML `autofocus` Race Condition**:
   In `ModifierAddPicker.tsx`, the search `<input>` had the native HTML `autofocus` attribute. The browser's native autofocus algorithm fires synchronously during DOM insertion, racing against Kobalte's Portal layer registration and event listener binding.

---

## Plan & Solutions

1. **Guard `onFocusOutside` in `apps/studio/src/components/ui/popover.tsx`**:
   - In `PopoverContent`, intercepted `onFocusOutside`:
     ```tsx
     onFocusOutside={(e: any) => {
       const target = e.detail?.originalEvent?.target as HTMLElement | undefined;
       if (target && (e.currentTarget?.contains?.(target) || target.closest?.('[data-slot="popover-content"]'))) {
         e.preventDefault();
         return;
       }
       local.onFocusOutside?.(e);
     }}
     ```
   - If the focused target is inside the popover content, `e.preventDefault()` prevents Kobalte from executing `onDismiss()`. True outside focus shifts (e.g. tabbing away) still dismiss normally.
2. **Eliminate Reactive Slot Re-Evaluation in `InspectorHeader.tsx` & `RightSidebar.tsx`**:
   - Replaced `<Show when={props.addEffectSlot}>` in `InspectorHeader.tsx` with direct children/slot projection:
     ```tsx
     <Show when={props.canAddEffect}>
       {props.children ?? props.addEffectSlot ?? (
         <Button ... onClick={props.onOpenAddPicker}>Add Effect</Button>
       )}
     </Show>
     ```
   - In `RightSidebar.tsx`, mounted `<ModifierAddPicker>` directly as children of `<InspectorHeader>`. This guarantees the component is mounted once and is never torn down when `isAddPickerOpen` toggles.
3. **Smooth Managed Focus in `ModifierAddPicker.tsx`**:
   - Replaced native `autofocus` attribute with `searchInputRef` and a `createEffect` timer when `props.open` is true, ensuring clean focus placement without portal mounting race conditions.
