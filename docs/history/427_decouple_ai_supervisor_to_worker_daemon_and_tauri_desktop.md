# 427: Decouple AI-Supervisor to Headless Worker Daemon and Tauri 2.x Desktop Host

## Problem
The previous `apps/ai-supervisor` setup attempted to package a Bun-based supervisor engine and a SolidJS dashboard inside Electrobun. This suffered from critical runtime defects on Windows 11:
1. `electrobun dev` repeatedly failed to render windows or create native system tray icons due to unstable upstream Windows FFI bindings in Electrobun (`.hutch`, `.cottontail-tmp`).
2. Heavy architectural coupling: `python-backend` was buried under `apps/ai-supervisor/python-backend`, yet required monorepo-wide accessibility for AI inference pipelines (TTS, LLMs).
3. The supervisor process was entangled with desktop window lifecycles, causing worker task execution to die if the window or desktop shell closed.

## Plan
1. **Elevate `python-backend` to Top-Level Package**: Move `apps/ai-supervisor/python-backend` to `apps/python-backend/` as a first-class monorepo package with independent `pyproject.toml` and pytest suites.
2. **Migrate Supervisor Engine to `@acc/worker` (Port 3333)**: Consolidate the entire supervisor engine (`SupervisorEngine`, `HardwareProfiler`, `RuntimeManager`, HTTP REST endpoints, SSE telemetry, and TaskWorkerFactory) into `apps/worker`. This turns `@acc/worker` into a headless background daemon that boots and manages Python and Studio services.
3. **Migrate Desktop Host to Tauri 2.x & Rust (`apps/supervisor-desktop`)**:
   - Rebrand `apps/ai-supervisor` to `apps/supervisor-desktop` (`@acc/supervisor-desktop`).
   - Use standard SolidJS + Vite + Tailwind CSS for UI compilation (`pnpm ui:build`).
   - Implement a lightweight (~11 MB) Tauri 2.x native Rust host with:
     - Native Windows 11 system tray (`tauri::tray::TrayIconBuilder` with dynamic green/yellow/red icon switching).
     - Smart auto-spawning & adoption of the `@acc/worker` daemon on port 3333 with Windows Job Objects (`KILL_ON_JOB_CLOSE`).
     - Real-time SSE listener (`/api/telemetry/stream`) driving tray tooltip and icon updates.
     - Close-to-tray window management.

## Changes

### 1. Python Backend Elevation
- Moved `apps/ai-supervisor/python-backend` to `apps/python-backend/`.
- Updated `packages/core/src/ipc/IPCFacade.ts` to locate `apps/python-backend`.

### 2. Unified Worker Daemon (`apps/worker`)
- Migrated supervisor engine subsystems to `apps/worker/src/supervisor/`:
  - `SupervisorEngine.ts`: Added `isWorkerInProcess` awareness so the worker does not attempt to spawn or terminate its own host process.
  - `server/HttpServer.ts` and routes (`serviceRoutes.ts`, `telemetryRoutes.ts`, `ttsRoutes.ts`, `staticRoutes.ts`).
  - `HardwareProfiler.ts`, `RuntimeManager.ts`, `configStore.ts`, `portScanner.ts`, `IProcessRunner.ts`, `LogManager.ts`, `StartupManager.ts`, `UpdateManager.ts`, `windowsStartup.ts`.
- Restored `packages/core/src/conductor/TaskWorkerFactory.ts` and `IConductorTaskCommand.ts`.
- Updated `apps/worker/src/index.ts` to bootstrap the supervisor HTTP/SSE engine on port 3333 alongside `SandboxTaskPoller` and `TaskWorkerFactory`.
- Updated `apps/worker/package.json` dependencies (`@acc/proto`, `@grpc/grpc-js`, `@grpc/proto-loader`, `@types/bun`).

### 3. Tauri 2.x Desktop Host (`apps/supervisor-desktop`)
- Replaced Electrobun configurations with Tauri 2.x:
  - `apps/supervisor-desktop/src-tauri/Cargo.toml`: Tauri 2 (`tray-icon`, `image-ico`, `image-png`), `windows-sys` (Job Objects), `reqwest`, `futures-util`.
  - `apps/supervisor-desktop/src-tauri/tauri.conf.json`: Configured window attributes, frontend dist (`../dist`), build scripts.
  - `apps/supervisor-desktop/src-tauri/src/process.rs`: Windows Job Object process supervisor with auto-spawning, port polling, and instance adoption.
  - `apps/supervisor-desktop/src-tauri/src/tray.rs`: Native system tray with menu actions ("Open Dashboard", "Purge All VRAM", "Restart Fleet", "Quit") and dynamic icon status switching.
  - `apps/supervisor-desktop/src-tauri/src/sse.rs`: Async SSE telemetry stream consumer updating tray color in real time.
  - `apps/supervisor-desktop/src-tauri/src/lib.rs` & `main.rs`: Window event listeners (`prevent_close` hides to tray on close button click).
  - `apps/supervisor-desktop/src/ui/stores/supervisorStore.ts`: Configured dynamic REST base (`http://127.0.0.1:3333`).
- Cleaned up obsolete Electrobun artifacts (`.hutch`, `.cottontail-tmp`, `electrobun.config.ts`, `src/bun/`, `src/views/`).
- Added root scripts in `package.json`: `supervisor:dev`, `supervisor:build`, `desktop:dev`, `desktop:build`, `worker:dev`.

## Walkthrough
1. **Headless Execution**:
   - Run `bun run apps/worker/src/index.ts` (or `pnpm worker:dev`). The worker boots on port 3333 and handles task queue processing and Python hypervisor lifecycle.
2. **Desktop GUI Execution**:
   - Run `pnpm desktop:dev` (or execute `acc-supervisor-desktop.exe`). The lightweight Tauri host opens the SolidJS control plane and places a reactive status icon in the Windows 11 taskbar tray.
   - If the worker daemon is not running, the desktop host auto-spawns it; if already active, it smoothly adopts the existing instance.
   - Closing the desktop window hides it into the tray; clicking the tray icon re-focuses the window. Right-clicking provides instantaneous VRAM purging, fleet restarting, and clean exit.
