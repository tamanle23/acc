# [123] Unify All 6 Pipelines Under Orchestrator & Middleware Architecture

## 1. Problem Statement
Previously, the multi-pipeline content generation suite suffered from architectural asymmetry:
1. Only Pipeline 4 (`GenerativeStoryPipeline`) utilized an orchestrator pattern (`EditingPipelineOrchestrator`), while Pipelines 1 (`Scraper`), 2 (`DB Templating`), 3 (`Repurposing`), 5 (`Rule Logic`), and 6 (`Ambient Stream`) executed procedural code in monolithic `run()` functions.
2. The core middleware engine `PipelineRunner` in `@acc/core` lacked integration with all 6 pipelines, missing stage duration metrics, standard export middleware, and unified registry resolution.

## 2. Implementation Plan & Changes
1. **Universal Context & Interfaces (`packages/core/src/pipeline/`)**:
   - Implemented `UnifiedPipelineContext<TInput>` extending `PipelineContext` with IR ast, asset registry, VFX queue, timings, and export deliverables.
   - Implemented `IPipeline<TInput>` interface establishing standard `buildRunner()` and `execute()` contracts.
   - Implemented `PipelineRegistry` for centralized pipeline resolution via aliases and IDs.
   - Implemented `createExporterDispatcherMiddleware` for automated multi-modal deliverable export.
2. **Enhanced PipelineRunner (`packages/core/src/PipelineRunner.ts`)**:
   - Added generic context typing (`TContext extends PipelineContext`).
   - Added stage execution timing metrics (`ctx.timings[mw.name]`).
   - Reinforced defensive fault isolation with fallback continuation.
3. **Decomposition of All 6 Pipelines (`apps/cli/src/pipelines/`)**:
   - **Pipeline 1 (`ScraperPipeline`)**: Decomposed into `ScraperLLMSummarizeStage`, `ScraperTTSSynthesisStage`, `ScraperCardCompositionStage`, and `ExporterDispatcherMiddleware`.
   - **Pipeline 2 (`DBTemplatingPipeline`)**: Decomposed into `DBDataNormalizationStage`, `DBBarChartCompositionStage`, and `ExporterDispatcherMiddleware`.
   - **Pipeline 3 (`RepurposingPipeline`)**: Decomposed into `RepurposingHookExtractionStage`, `RepurposingCompositionStage`, and `ExporterDispatcherMiddleware`.
   - **Pipeline 4 (`GenerativeStoryPipeline`)**: Decomposed into `StoryFolderResolutionStage`, `StoryOrchestratedRenderStage`, and `StoryMetadataPersistenceStage`.
   - **Pipeline 5 (`RuleLogicPipeline`)**: Decomposed into `RuleLogicProofValidationStage`, `RuleLogicChalkboardCompositionStage`, and `ExporterDispatcherMiddleware`.
   - **Pipeline 6 (`AmbientStreamPipeline`)**: Decomposed into `AmbientParticleShaderCompositionStage` and `ExporterDispatcherMiddleware`.
4. **CLI Integration (`apps/cli/src/index.ts`)**:
   - Integrated `defaultPipelineRegistry` for unified pipeline discovery.
