# 208. Bundling & Version Isolation for `uv` and Python with ACC Supervisor

## Context & Objectives
To ensure hermetic runtime reproducibility and prevent version collisions across diverse developer and end-user environments (e.g. system Python 3.10 vs 3.14), the ACC Supervisor desktop ecosystem required dedicated runtime isolation. Relying on whatever Python version is globally installed in the host `PATH` creates potential compatibility and `ENOENT` issues.

This task implemented **Hybrid Managed Provisioning** via `RuntimeManager`:
1. Standalone `uv` binary isolation into `~/.acc/bin/` conforming to rule `GLOBAL-STORAGE`.
2. Dedicated hermetic CPython 3.12 provisioning into `~/.acc/python-env/`.
3. Non-blocking UX with a `PROVISIONING` service status and yellow tray indicator.
4. Complete environment variable isolation (`UV_PYTHON_INSTALL_DIR=~/.acc/python-env`, `UV_PYTHON=3.12`).

---

## Architectural Changes & Components

### 1. RuntimeManager Subsystem (`apps/ai-supervisor/src/bun/RuntimeManager.ts`)
- **Paths**:
  - `storageDir`: `~/.acc/`
  - `binDir`: `~/.acc/bin/`
  - `uvBinaryPath`: `~/.acc/bin/uv.exe` (Windows) / `~/.acc/bin/uv` (Unix)
  - `pythonInstallDir`: `~/.acc/python-env/`
- **Methods**:
  - `ensureUv()`: Fast copies detected local system `uv` or fetches standalone release binary from Astral GitHub releases.
  - `ensurePython(version = "3.12")`: Executes `uv python install 3.12 --install-dir ~/.acc/python-env` with piped progress logging.
  - `isReady()`: Validates that both `uv` and Python 3.12 are provisioned.
  - `getExecutionEnv()`: Prepends `binDir` to `PATH` and injects `UV_PYTHON_INSTALL_DIR`, `UV_PYTHON: "3.12"`, and `PYTHONUNBUFFERED: "1"`.

### 2. Supervisor Engine Multi-Daemon Integration (`apps/ai-supervisor/src/bun/SupervisorEngine.ts`)
- Added `"PROVISIONING"` status to `ServiceStatus`.
- Updated `updateTrayColor` to keep tray icon `yellow` during runtime provisioning.
- Implemented `findRepoRoot` to dynamically locate the monorepo root via `bun.lock`/`.git` boundary scanning, avoiding invalid directory resolution from `apps/ai-supervisor/src/bun`.
- Fixed `uv_spawn ENOENT` error caused by non-existent `cwd` by defensively resolving and verifying `pythonBackendCwd` and `serverScript` before calling `spawn`.
- Updated `startPythonBackend` to check `runtimeManager.isReady()`. When unprovisioned, service state transitions to `PROVISIONING` and executes `ensureRuntime()`, logging progress before spawning `server.py` with isolated execution environment.
- Supported dependency injection for `RuntimeManager` in `SupervisorEngine` constructor to allow isolated testing.

### 3. Core IPCFacade Fallback (`packages/core/src/ipc/IPCFacade.ts`)
- Updated `GRPCAIStrategy.ensureDaemonRunning` to check for `~/.acc/python-env/` and inject `UV_PYTHON_INSTALL_DIR` and `UV_PYTHON: "3.12"` into standalone daemon spawns.

### 4. Architecture Synchronization (`docs/SYSTEM_ARCHITECTURE_DOCUMENT.md`)
- Updated Section 11 to document the `RuntimeManager` architecture, background provisioning lifecycle, and runtime isolation model.
