# Task History: 338 - AI-Supervisor Purge Runtime Compilations & Dedicated Native Compilation Pipeline

## Context & Requirements
Previously, both `WindowHost.ts` and `NativeTrayBridge.ts` contained inline fallbacks that attempted to invoke `swiftc` via `spawn(...)` at application runtime if the precompiled binary was missing. This introduced unexpected build latency, unmanaged compiler subprocesses, and fragile dependencies inside core runtime paths.

The goal was to migrate all native build/compilation logic to a dedicated build-time script and completely eliminate `spawn("swiftc", ...)` from the application's runtime core logic.

## Implementation Architecture
1. **Dedicated Native Compilation Script (`apps/ai-supervisor/scripts/compile-native.ts`)**:
   - Manages building Universal Mach-O (`arm64` + `x86_64`) binaries for both `tray_runner_mac` and `webview_host_mac` using `swiftc` and `lipo`.
   - Places verified executables directly in `src/assets/bin/`.
   - Wired cleanly into the build pipeline:
     ```json
     "compile:native": "bun run scripts/compile-native.ts",
     "build": "bun run compile:native && bun run build:ui && bun build src/bun/index.ts --compile --outfile=dist/acc-supervisor.exe"
     ```

2. **Purged Runtime Compilations from Application Logic**:
   - **`NativeTrayBridge.ts`**:
     - Removed `spawn(["swiftc", ...])`.
     - `resolveMacBinary` is now a pure, synchronous filesystem lookup strictly checking `src/assets/bin/tray_runner_mac` and `~/.acc/bin/tray_runner_mac`. Zero runtime compilation.
   - **`WindowHost.ts`**:
     - Removed `spawn(["swiftc", ...])`.
     - `resolveMacBinary` is now a pure, synchronous lookup strictly checking `src/assets/bin/webview_host_mac` and `~/.acc/bin/webview_host_mac`. Zero runtime compilation.

3. **Pure Execution at Runtime**:
   - The runtime app only ever launches the pre-built, universal Mach-O binaries shipped in `assets/bin/`.
