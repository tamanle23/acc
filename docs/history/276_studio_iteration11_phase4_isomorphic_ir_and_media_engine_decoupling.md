# 276: Studio Iteration 11 Phase 4: Isomorphic IR Package Unification & Media Engine Decoupling

## Overview & Background
In Iteration 11 Phase 4, we addressed critical architectural fragility where `@acc/ir/client` existed as an artificial subpath export containing 10 dummy plugin stubs (`createClientPluginStub`), while server native utilities (`FFIVideoDecoder`, `child_process`, `fs`, `FFmpegManager`) risked polluting browser application bundles during production Vite/Rollup builds.

This task re-evaluated the scope across `@acc/ir`, `@acc/core`, and `@acc/effect-engines`, completely decommissioning the legacy client subpath and creating a pure, unified, 100% isomorphic `@acc/ir` engine alongside `@acc/ir/server`.

---

## Architectural Changes & Key Accomplishments

### 1. Complete Removal of `@acc/ir/client` & Fake Stubs
- Deleted `packages/ir/src/plugins/clientRegistry.ts` (eliminating all 10 fake client plugin stubs: `vfx/color_grading`, `editorial/split_edit`, `editorial/transition_crossfade`, `transition/crossfade`, `overlay/blend_mode`, `overlay/canvas_particles`, `vfx/depth3d`, `vfx/camera_3d`).
- Deleted `packages/ir/src/client.ts`.
- Removed `"./client"` export from `packages/ir/package.json`.
- Migrated all call sites across `apps/studio` and test suites to import directly from canonical `@acc/ir`.
- Both browser and server environments now execute identical, real modifier plugins via `registerCoreModifierPlugins`.

### 2. Media Engine Decoupling & Server Isolation
- Decoupled `FFIVideoDecoder` from `IRMasterRenderer.ts` by defining the `IVideoDecoder` contract and adding `createVideoDecoder(filePath, targetWidth, targetHeight)` to `IMediaEngineStrategy` and `BunFFIEngineStrategy`.
- Isolated native server batch workers and muxers under `@acc/ir/server`:
  - `IRChunkWorkerPool`
  - `FFIChunkConcatMuxer`
  - `IRMasterRenderer`
  - Server frame sinks (`FFIVideoEncoderSink`, `FluentPipeVideoSink`, `MediabunnyServerSink`, `MediaSinkFactory`)
- Created `packages/core/src/client.ts` (`@acc/core/client`) exporting pure browser-safe types and `MediabunnyClientSink`.
- Updated `packages/ir/src/renderer/sink/IIRFrameSink.ts` to import type-only definitions from `@acc/core/client`.

### 3. Effect Engines & Plugin Isomorphism
- Exported `ColorGradingEngine`, `Depth3DFactory`, and `SurfaceNormalGenerator` via `@acc/effect-engines/client`.
- Switched `CanvasParticleOverlayPlugin`, `ColorGradingPlugin`, `Camera3DPlugin`, and `Depth3DPlugin` to import from `@acc/effect-engines/client`.
- Wrapped server-only depth preflight functions (`resolveSubjectCutout`, `resolveDepthMapData`) in `Depth3DPlugin` and `Camera3DPlugin` behind Node runtime checks with dynamic `require` to guarantee zero bundling of native C/Node.js dependencies into browser bundles.
