# 193. Master Integration Plan (Iteration 2) Phase 2: Hardware Accelerated Encoders & GPU Pipelining Suite (Option C)

## 1. Context & Motivation
Following Phase 1 (`191_master_integration_plan_iteration2_phase1_scripting_frameworks.md`) and the formalization of Option B (`192_formalize_option_b_pure_history_archival.md`), Phase 2 executes Pillar 2 (Option C): **Hardware Acceleration & Multi-GPU Pipelining**.
Previously, `FFIVideoEncoder.ts` relied on a static check for `h264_nvenc` followed by a hard fallback to `libx264`. It lacked dynamic multi-platform hardware encoder probing (macOS Apple Silicon `VideoToolbox`, Linux `VAAPI`, Intel `QSV`, AMD `AMF`), fine-grained codec options tuning (`preset`, `tune=hq`, `spatial_aq`, `temporal_aq`), and flexible codec selection (`h264` vs `hevc`).

## 2. Key Changes Made

### A. Dynamic Hardware Encoder Prober (`packages/core/src/ffmpeg-ffi/GPUEncoderResolver.ts`)
- Implemented `GPUEncoderResolver` with cross-platform awareness:
  - macOS Darwin: `h264_videotoolbox` / `hevc_videotoolbox` -> `libx264` / `libx265`.
  - Windows: `h264_nvenc` / `hevc_nvenc` -> `h264_qsv` / `h264_amf` -> `libx264` / `libx265`.
  - Linux: `h264_nvenc` / `hevc_nvenc` -> `h264_vaapi` / `h264_qsv` -> `libx264` / `libx265`.
- Defensive hardware verification (`testEncoderOpenable`):
  - Allocates a lightweight test context and attempts `avcodec_open2` to verify that the GPU device and driver are actually responsive.
  - Automatically cleans up the test context (`avcodec_free_context`) with zero nursery heap leaks.
  - If a GPU device is uninitialized or absent (e.g. AMF without `amfrt64.dll`), it falls back gracefully through the candidate chain down to CPU.
- Cached lookups: subsequent queries return in $O(1)$ time without repeating FFI probes.
- Helper `getAvailableEncoders()`: inspects and returns all openable hardware and software encoders.

### B. Hardware Video Encoding Strategy (`packages/core/src/ffmpeg-ffi/EncodingStrategies.ts` & `GpuVideoEncodingStrategy.ts`)
- Implemented `GpuVideoEncodingStrategy` extending `FileVideoEncodingStrategy`:
  - NVIDIA NVENC tuning: `preset=p4/p6`, `tune=hq`, `rc=vbr`, `cq=crf`, `spatial_aq=1`, `temporal_aq=1`.
  - Apple VideoToolbox tuning: `profile=high`, `realtime=0`, `allow_sw=0`, `q=crf`.
  - Intel QSV & AMD AMF tuning: hardware preset and rate-control parameters.
  - Preserves all container allocation (`mp4`, `mkv`, `mov`, `webm`) and `movflags +faststart` optimizations.

### C. FFIVideoEncoder Modernization (`packages/core/src/ffmpeg-ffi/FFIVideoEncoder.ts`)
- Integrated `GPUEncoderResolver.resolveSync` during `initialize()`.
- Added constructor parameters `hardwarePreference?: HardwareEncoderType` and `targetCodec: 'h264' | 'hevc'`.
- Upgraded defensive fallback in `initialize()`: if opening the resolved hardware codec fails, it falls back to CPU `libx264`/`libx265`.
- Added inspection getters: `getActiveEncoderName()`, `isHardwareAccelerated()`, and `getHardwareType()`.
- Downstream sinks (`FFIVideoEncoderSink`, `IRChunkWorkerPool`, `IRMasterRenderer`, `VideoExporter`) automatically inherit GPU acceleration with zero configuration changes.

### D. Verification & QA Suite (`autogenerated-tests/gpu_encoder_resolution.test.ts`)
- Created comprehensive test suite verifying:
  - Prioritized candidate chain generation across platforms and forced preferences.
  - Defensive fallback to `libx264` when an unavailable hardware encoder is forced.
  - Openable encoder discovery on local host (verified active NVENC hardware).
  - Codec tuning parameters in `GpuVideoEncodingStrategy`.
  - Real RGBA frame encoding with auto-detected hardware encoder and verified non-zero output file sizes.
  - Explicit CPU fallback frame encoding and clean stream finalization.
- Results: **11 passed, 0 failed, 41 assertions**.
