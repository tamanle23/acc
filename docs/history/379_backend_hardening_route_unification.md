# 379. Zero-Stub Cryptographic Security, Route Unification to `/api/v1/...` & Persistence Hardening

### Problem
1. **Cryptographic Backdoor Violation**: `PayOsBillingService.java` contained hardcoded backdoor signature strings (`"mock_signature_ok"`, `"test_valid_sig"`), violating the monorepo's `ZERO-STUB-PROHIBITION` rule.
2. **Synthetic Data Injections**: `buildBillingHistory` injected synthetic mock transaction records (`orderCode: 1712800000000L`) when database records were empty, masking real data states.
3. **In-Memory VAT State & Mock Corporate Defaults**: Corporate VAT invoice preferences were held in an in-memory `ConcurrentHashMap` with a synthetic fallback company template, risking data loss on pod restart.
4. **Route Versioning Inconsistencies**: Workflow controllers in `apps/backend/acc-ms-aio` had divergent route paths (some dual `/api/...` and `/api/v1/...`, others strictly `/api/v1/...`), while console callers previously made un-versioned requests.

### Plan
1. Harden `PayOsBillingService.java`: Remove backdoor bypass tokens, enforce constant-time HMAC-SHA256 verification using `MessageDigest.isEqual()`, persist VAT preferences in `TenantBilling.billingMetadata` JSONB, remove synthetic history injections, and sanitize quota exceptions.
2. Unify all workflow controllers in `apps/backend/acc-ms-aio` strictly under canonical `/api/v1/...` namespaces.
3. Harmonize console API client (`apps/console/src/features/workflow-executions/api/use-workflow-executions.ts`) to call `/v1/workflow/executions`.
4. Update unit test suites in `acc-fw` to compute genuine HMAC-SHA256 signatures and verify rejection of all bypass strings.
5. Create reusable formal test suites in `/autogenerated-tests/` verifying HMAC mathematics and route invariants.
