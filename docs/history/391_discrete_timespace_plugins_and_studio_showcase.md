# 391: Discrete `time_space/*` Motion Graphic Plugins & Studio Showcase

## 1. Problem Formulation
Prior to this iteration, the procedural motion graphics pipeline in `@acc/ir` was centralized in a single monolithic plugin `TimeSpaceModifierPlugin.ts` (`time_space`). While mathematically robust, this design suffered from:
1. **Inspector Bloat**: All 11+ motion graphic templates shared a single schema with runtime `visibleIf` predicates, causing clutter and irrelevant fields in Studio's Inspector.
2. **Duplication Risk**: Parallel ad-hoc implementations across packages (`TrackingCalloutEngine`, `HologramHUDPlugin`, `LowerThirdFactory`).
3. **Limited Studio Demos**: Studio only supported 2 demo projects (`defaultDemoIR` and `complexSciFiDemoIR`), lacking broadcast news and audio visualizer demonstrations.

## 2. Implementation Plan
- **Phase 1**: Implement `BaseTimeSpacePlugin<TParams>` in `packages/ir/src/plugins/time-space/` encapsulating state machine lifecycle, cache invalidation, and isomorphic canvas rendering.
- **Phase 2**: Implement 12 discrete plugins with bespoke schemas under `packages/ir/src/plugins/time-space/`, export barrel, register in `registerCoreModifierPlugins`, and maintain backward-compatibility adapter.
- **Phase 3**: Synchronize `VideoIR` types in `packages/ir/src/types/modifiers.ts` and runtime validation in `packages/ir/src/schema/VideoIRSchemaValidator.ts`.
- **Phase 4**: Expand Studio Inspector catalog (`modifierCatalog.ts`) and introduce 4 rich production demo projects (`defaultDemoIR`, `complexSciFiDemoIR`, `broadcastNewsDemoIR`, `cyberAudioVisualizerDemoIR`) wired to `Titlebar.tsx` and `irState.ts`.
- **Phase 5**: Create comprehensive test suite `autogenerated-tests/discrete_timespace_plugins.test.ts`.
