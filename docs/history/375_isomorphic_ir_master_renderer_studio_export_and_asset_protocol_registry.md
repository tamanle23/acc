# 375. Isomorphic IRMasterRenderer Studio Web Worker Export & AssetProtocolRegistry

## Problem Statement
In `@acc/studio`, video export was hand-rolled directly in `ClientExportOrchestrator.ts` using `IRPreviewEngine` and manual `AssetTextureCache` queries on the browser main UI thread. Because `AssetTextureCache` uses bounded LRU caches without upfront pre-warming, cache misses synchronously returned fallback placeholder canvases (`#151518` charcoal with `[▶ VIDEO]` / `[🖼 IMAGE]` badges) during export. Running exports on the main thread also caused UI thread starvation and prevented responsive cancellation.

## Execution Plan & Changes
1. **Isomorphic Asset Loading via `AssetProtocolRegistry`:**
   - Updated `packages/ir/src/renderer/IRMasterRenderer.ts` `preloadAssets()` to resolve visual assets through `AssetProtocolRegistry.getInstance().resolve(...)` backed by `ContentCacheRegistry`.
   - Enabled transparent loading of `http:`, `blob:`, `data:`, `cache:`, and `file:` asset references across Browser, Web Worker, and Node/Bun headless runtimes.
2. **Cooperative Yielding & `AbortSignal` Support in `IRMasterRenderer`:**
   - Extended `HeadlessRenderOptions` with `signal?: AbortSignal` and `yieldInterval?: number`.
   - Wired immediate loop abortion and microtask yielding inside the Phase 2 frame loop.
3. **Audio Finalization Alignment:**
   - Updated `packages/core-web/src/media-engine/MediabunnyClientSink.ts` `finalize()` to accept `DecoupledAudioMixResult` and planar PCM Float32 channels.
4. **Dedicated Background Export Web Worker:**
   - Created `apps/studio/src/renderer/workers/export.worker.ts` and `ExportWorkerBridge.ts` to execute `IRMasterRenderer.render({ engine: 'mediabunny-client', sink })` in a separate background thread with direct OPFS scratch stream writing.
5. **Refactored `ClientExportOrchestrator.ts`:**
   - Replaced manual ~180-line frame readback and audio mixing loop with `ExportWorkerBridge` delegation and in-process `IRMasterRenderer` fallback.
