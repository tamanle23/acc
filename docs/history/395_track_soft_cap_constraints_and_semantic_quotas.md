# 395: Universal Track Soft-Cap Constraints & Semantic Track Quotas

## 1. Problem Formulation
As the VideoIR authoring ecosystem expands across manual human editing and automated generative AI pipelines, unrestrained track allocation created critical performance bottlenecks:
1. **Unbounded Track Sprawl**: Automated AI pipelines or rapid multi-clip insertion spawned chaotic timelines with dozens of tracks, creating severe GPU texture pressure, WebGL context loss risks, and canvas compositing degradation.
2. **Lack of Semantic Role Differentiation**: Physically, tracks were typed only as `'video'`, `'audio'`, `'timed_text'`, or `'data'`, obscuring functional creative roles: `main` (spine), `overlay` (PIP/visualizer), `audio` (voice/SFX/BGM), `text` (captions), `effects` (adjustment tracks), and `stickers`.
3. **Preserving Foundational Generality**: The core `VideoIRDocument` and `IRTrack` schema could not be mutated or bloated with rigid role enums; quotas and classification needed to live cleanly in the authoring engine.

## 2. Implementation Plan
- **Phase 1: Authoring Policy & Engine Implementation (`packages/ir`)**:
  - Implement `SemanticTrackRole`, `TrackQuotaLimit`, `TrackAuthoringPolicy`, `DEFAULT_TRACK_AUTHORING_POLICY`, `TrackQuotaStatus`, and `CanAddTrackResult`.
  - Implement `classifyTrackRole()`, `evaluateTrackQuotas()`, and `canAddTrack()`.
  - Implement `canPlaceSequenceOnTrack()` and `findWhitespaceTrack()` for temporal whitespace reuse.
  - Enhance `generateNextTrackId()` with semantic prefixes (`track_v_overlay_1`) while maintaining legacy backward compatibility (`track_v2`).
- **Phase 2: Authoring Engine Formal Unit Tests (`autogenerated-tests/`)**:
  - Create `autogenerated-tests/track_soft_cap_policy.test.ts` testing default classification, quota status, soft-cap warning threshold (6 overlays), hard-cap rejection (10 overlays), manual override (11th overlay allowed), custom policies, and whitespace reuse.
- **Phase 3: Studio UI Integration (`apps/studio`)**:

  - Wire `addTrack()`, `checkCanAddTrack()`, and `getTrackQuotas()` into `IRStateManager`.

  - Add quota telemetry and `addTrack` with policy validation into `StudioTimelineState.ts`.

## 4. Verification
- `classifyTrackRole` accurately detects `main`, `overlay`, `audio`, `text`, `effects`, and `stickers` across diverse naming, index, and modifier patterns.
- `evaluateTrackQuotas` correctly tallies tracks per semantic role and flags threshold breaches.
- `canAddTrack` warns when the 6th overlay track is approached (`isWarning: true`).
- `canAddTrack` strictly rejects adding an 11th overlay track when `isManualOverride: false`.
- `canAddTrack` allows adding an 11th overlay track when `isManualOverride: true` with a clear warning reason.
- `generateNextTrackId` generates semantic IDs (`track_v_overlay_1`) while preserving legacy compatibility (`track_v2`).
- `findWhitespaceTrack` successfully locates non-overlapping temporal gaps on existing tracks to avoid spawning extra tracks.
- Studio UI provides non-intrusive soft-cap badges and renders `TrackQuotaModal` on hard-cap breaches.

## 5. Walkthrough
1. **Interactive Studio Adding**: Users can click "+ Add Track" in the timeline footer or "Add Track" in Empty State.
2. **Soft-Cap Awareness**: When overlay tracks reach 6, ambient warning badges appear on track headers without interrupting creative flow.
3. **Hard-Cap Guardrails**: When attempting to exceed 10 overlay tracks, the Studio presents a Liquid Glass modal warning of hardware memory impact. Users can choose to cancel or click `[Add Track Anyway]`.
4. **Autonomous Pipelines**: Headless generators in `apps/cli` validate `canAddTrack()`; if rejected, they leverage `findWhitespaceTrack()` to reuse existing track whitespace safely.
