# History Entry 367: Studio WebCodecs Hardware Decoder Quota Pool (Phase 2)

## Problem
Modern browsers enforce a hard platform limit of $\sim 16$ concurrent hardware `VideoDecoder` sessions per renderer process. In complex NLE projects with multi-track video, picture-in-picture (PIP), overlays, and transitions, instantiating an unrestricted `MediabunnyWorkerReader` per asset exhausted the hardware decoder quota, causing uncatchable `QuotaExceededError` crashes or black preview frames.

## Plan
1. Create `WebCodecsDecoderPool.ts` to strictly cap concurrent active hardware decoders at $\le 8$.
2. Implement playhead proximity priority scoring: active foreground clips receive hardware leases; distant or offscreen assets are evicted or kept on standby.
3. Add `evictHardwareDecoder()` and `reacquireHardwareDecoder()` to `MediabunnyWorkerReader.ts` to free native GPU sessions without dropping track metadata.
4. Add graceful OPFS poster frame caching and fallback in `MediabunnyWorkerReader.requestFrame()`.
5. Integrate priority leasing into `preview.worker.ts` rendering and asset synchronization lifecycles.
6. Create formal unit tests in `autogenerated-tests/webcodecs_decoder_pool.test.ts`.
