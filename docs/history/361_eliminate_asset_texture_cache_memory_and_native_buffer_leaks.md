# 361. Elimination of In-Memory Texture Caches & Native Media Buffer Leaks

## Problem
During 60fps timeline playback and interactive scrubbing in Studio, native memory usage accumulated beyond 2.5GB, resulting in browser out-of-memory (OOM) crashes and GPU context loss.
- **Root Cause**: `ImageBitmap` and `VideoFrame` instances hold native C++ / GPU memory ($\approx 8.3\text{ MB}$ per 1080p frame) while consuming only $\sim 48\text{ bytes}$ of V8 JavaScript heap. V8's generational garbage collector triggers no collections during rendering, causing hundreds of unclosed native buffers to linger.
- **In-Memory Cache Bloat**: [`AssetTextureCache.ts`](file:///c:/Users/Admin/workspace/git/acc/apps/studio/src/lib/textures/AssetTextureCache.ts) maintained 7 unbounded in-memory `Map`s holding raw DOM elements, video decoders, and object URLs.
- **Missing Immediate Post-Draw Disposal**: In [`IRCanvasCompositor.ts`](file:///c:/Users/Admin/workspace/git/acc/packages/ir/src/renderer/shared/IRCanvasCompositor.ts) and [`preview.worker.ts`](file:///c:/Users/Admin/workspace/git/acc/apps/studio/src/renderer/workers/preview.worker.ts), single-use frames decoded during sequential playback were never `.close()`'d immediately after `ctx.drawImage()`.

## Plan
Implement [Master Implementation Plan Iteration 44](file:///c:/Users/Admin/workspace/git/acc/docs/iterations/master_implementation_plan_iteration_44.md):
1. Extend `IAssetSourceResolver` with `onAssetDrawn` hook and wrap `ctx.drawImage()` in `IRCanvasCompositor.ts` in a `try...finally` block executing immediate synchronous `.close()`.
2. Refactor `PreviewFrameMemoryManager.ts` to enforce a strict 32-frame capacity ceiling with synchronous `.close()` execution on LRU eviction, key overwrite, window pruning, and cache clearing.
3. Bifurcate playback vs scrubbing in `preview.worker.ts`: sequential playback frames are tagged as single-use transient and closed immediately post-draw.
4. Refactor `AssetTextureCache.ts` to delegate all persistent storage to `ContentCacheRegistry.get()`, bound active decoders to a Hot Decoders LRU ($\le 8$ images, $\le 4$ videos), and reuse scratch canvases via `UniversalCanvasProvider.acquireScratchCanvas()`.
5. Bound `ContentHashTextureCache.ts` capacity to 32 items with immediate `.close()` on eviction.
6. Create comprehensive automated verification test suite in `autogenerated-tests/memory_native_buffer_hygiene.test.ts`.
