# 377. Studio Worker Protocol Unification, Canvas Transfer Tracker, and Strict Typing

### Problem
1. **Split Worker Infrastructure**: `@acc/studio` maintained two separate workers (`IRPreviewEngine.worker.ts` and `workers/preview.worker.ts`), creating duplicate modifier plugin registrations, loading redundant chunks (>1.1 MB), and fragmenting the worker architecture.
2. **DOM Monkey-Patching Memory Risk**: Transferred canvas elements were marked via `(canvas as any).__transferred = true`, which polluted native DOM elements, bypassed TypeScript type safety, and prevented garbage collection across component lifecycles.
3. **Loose Entity Typings**: `ExecuteModifierPayload.targetEntity` was typed as `Record<string, unknown>` and cast to `any`, and `'light_vector'` was handled at runtime but omitted from `ParamFieldType`.
4. **Implementation Plan Drift**: Analysis sections in implementation plans previously risked dropping refactoring details from concrete roadmaps.

### Plan
1. Standardize agent rule enforcing 1:1 parity between analysis sections and phased implementation roadmaps.
2. Add `'light_vector'` to `ParamFieldType` in `@acc/ir` and strongly type `SidecarTargetEntity = ResolvedTrack | ResolvedSequence`.
3. Implement `CanvasTransferTracker` in `@acc/core-web` using `WeakSet<HTMLCanvasElement>` and eliminate `__transferred` monkey-patching.
4. Merge sidecar preflight message handling into `workers/preview.worker.ts`, re-route `PreviewWorkerCoordinator`, and safely delete `IRPreviewEngine.worker.ts`.
5. Verify with autogenerated test suites and clean Vite production build.
