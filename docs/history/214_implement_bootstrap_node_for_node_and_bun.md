# Task: Implement bootstrapNode for Node and Bun Runtimes

## Problem
In `@acc/core-web/src/index.ts`, `bootstrapClient()` provides a clean, unified IoC bootstrapping function that registers the client-side canvas adapter (`WebCanvasAdapter`), media engine (`MediabunnyClientStrategy`), and cache strategies (`IndexedDbCacheStrategy`, `WebCacheStrategy`).

On the server and CLI side (Node.js / Bun), media engine registration, native canvas adapter registration, and file cache strategy registration were either fragmented across various files or required ad-hoc initializations. A symmetrical, clean, and enterprise-grade `bootstrapNode()` function was needed in `@acc/core` to initialize and register all Node/Bun-compatible services in their respective registries.

## Plan
1. Design `bootstrapNode` in [`packages/core/src/bootstrap.ts`](file:///c:/Users/Admin/workspace/git/acc/packages/core/src/bootstrap.ts) adhering to enterprise clean code and TypeScript standards:
   - Accept typed options `BootstrapNodeOptions` (`prepareFFmpeg?: boolean`, `defaultMediaEngine?: MediaEngineType`, `cacheOptions?: NativeFileCacheOptions`).
   - Register `NapiCanvasAdapter` as the default canvas adapter with `UniversalCanvasProvider`.
   - Register `NativeFileCacheStrategy` with `ContentCacheRegistry`.
   - Register server media engines (`bun-ffi`, `mediabunny-server`, `fluent-ffmpeg`) with `MediaEngineRegistry`.
   - Optionally configure default media engine or await `FFmpegManager.prepare()`.
2. Export `bootstrapNode` and its types from [`packages/core/src/index.ts`](file:///c:/Users/Admin/workspace/git/acc/packages/core/src/index.ts) and [`packages/core/src/native/index.ts`](file:///c:/Users/Admin/workspace/git/acc/packages/core/src/native/index.ts).
3. Author formal tests in [`autogenerated-tests/core_node_bootstrap.test.ts`](file:///c:/Users/Admin/workspace/git/acc/autogenerated-tests/core_node_bootstrap.test.ts) testing:
   - NapiCanvasAdapter default registration.
   - NativeFileCacheStrategy registration and CRUD operations.
   - Server media engine strategies availability and registration.
   - Default media engine configuration.
   - Idempotency across repeated invocations.
   - Optional FFmpegManager preparation execution.
4. Verify execution with `bun test` across related suites.
