# 385. TimeSpaceModifierPlugin Schema Declarations & Inspector Param Flat Serialization

## Problem
In `apps/studio`, the Right Inspector for `time_space` sequences showed `[object Object]` for a raw `params` field.
1. **Root Cause**: `TimeSpaceModifierPlugin.ts` declared only two schema fields (`templateId` and `boundary`), omitting the template arguments (`text`, `targetX`, `targetY`, `labelX`, `labelY`). In `complexSciFiDemoIR.ts`, these arguments were nested inside an opaque `params: { ... }` object.
2. When `DynamicModifierInspector.tsx` encountered this nested object without a registered sub-schema, its reflective fallback `inferFieldDescriptor` treated `params` as a generic string field (`defaultValue: String(val)`), rendering `[object Object]` in the input box.

## Solution
1. **Registered Rich Schema Fields in `TimeSpaceModifierPlugin.ts`**:
   - Declared full schema descriptors for all template parameters:
     - `templateId`: Dropdown select (`'callout_leader' | 'kinetic_title' | 'particle_ambient'`).
     - `boundary`: Dropdown select (`'loop' | 'pingpong' | 'clamp' | 'once'`).
     - `text`: String text input for callout/title text.
     - `targetX`, `targetY`: Sliders for 2D normalized target coordinates `[-1.0, 1.0]`.
     - `labelX`, `labelY`: Sliders for 2D normalized label offsets `[-1.0, 1.0]`.
2. **Flattened Demo IR & Catalog Initializers**:
   - Flattened modifier parameters in `complexSciFiDemoIR.ts`, `defaultDemoIR.ts`, and `modifierCatalog.ts` from `{ params: { text: ... } }` to direct properties (`{ text: ..., targetX: ... }`).
3. **Ergonomic Resolver in `renderClipSpace` & `renderMasterComposite`**:
   - Automatically merges `{ ...params, ...(params.params || {}) }` so both flat and nested configurations execute seamlessly.
