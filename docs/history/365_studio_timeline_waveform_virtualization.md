# History Entry 365: Studio Timeline Waveform Virtualization (Phase 1)

## Problem
In Apps/Studio, each audio clip in the timeline mounted its own `WaveSurfer.js` instance via `WaveSurferWaveform.tsx`. On projects with 30+ audio clips, this created dozens of separate DOM nodes, multiple resize observers, audio context allocations, and layout thrashing during zoom and horizontal pan operations.

## Plan
1. Implement `TrackWaveformVirtualCanvas.tsx` to provide a single, unified 2D Canvas lane per audio track sized to the visible viewport ($W_{\text{viewport}} \times \text{DPR}$).
2. Implement deterministic frustum culling: only query and draw peaks for clips intersecting $[F_{\text{start}}, F_{\text{end}}] = [\lfloor X_{\text{scroll}} / S_{px} \rfloor, \lceil (X_{\text{scroll}} + W_{\text{viewport}}) / S_{px} \rceil]$.
3. Wire `TrackWaveformVirtualCanvas` inside `DroppableTrackLane.tsx` with sticky viewport positioning (`position: sticky; left: 0; pointer-events: none`).
4. Refactor `WaveSurferWaveform.tsx` from `WaveSurfer.create()` to direct pure HTML5 `<canvas>` rendering using `WaveformLODPyramid`.
5. Create formal unit test suite in `autogenerated-tests/track_waveform_virtual_canvas.test.ts`.
