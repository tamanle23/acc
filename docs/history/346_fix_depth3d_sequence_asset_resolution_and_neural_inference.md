# 346: Fix Depth3D Sequence Asset Resolution and Neural Inference

## Problem
In Studio preview and preflight, `Depth3DPlugin` failed to trigger Hugging Face depth estimation and neural subject cutout for Video IR sequences:
1. Video IR sequences reference media assets via `sequence.assetId` (with actual URLs stored in `timeline.assets[assetId].src`), but `Depth3DPlugin.execute()` only checked `params.imagePath`. Since `params.imagePath` was undefined in timeline sequence modifiers, neural preflight was bypassed.
2. `Depth3DPlugin.execute()` gated depth estimation behind `mode === 'depth_map_3d' || mode === 'mesh_displacement' || params.autoDepth`, skipping common 3D modes such as `frame_breaker` and `parallax_25d`.
3. Cache lookup during the 60 FPS `renderClipSpace()` loop queried only `params.imagePath`, causing cache misses when `params.imagePath` was omitted.
4. `IRPreviewEngine.worker.ts` did not forward `payload.assets` to `context.assets`.
5. `resolveDepthMapData` in `@acc/effect-engines` did not return `srcCanvas`, causing `depthData?.srcCanvas` checks to evaluate to undefined.

## Plan
1. Extend `ModifierContext` and worker bridge payloads with `assets?: Record<string, { src: string; type?: string }>`.
2. Update `Depth3DPlugin.execute()` to resolve effective image path from `params.imagePath || assetDef?.src || seq?.src || assetId`.
3. Broaden `needsDepth` condition to cover all 17+ 3D depth modes (`frame_breaker`, `parallax_25d`, `volumetric_sandwich`, etc.).
4. Store resolved cutouts, depth layers, normal maps, and background plates under multi-key candidates `[effectiveImagePath, params.imagePath, assetId, seq?.id, seq?.src]`, and check across candidates in `renderClipSpace()`.
5. Return `srcCanvas: dCanvas` from `resolveDepthMapData`.
6. Guard Web Worker instantiation in `StudioSidecarCoordinator` to avoid Web Worker thread teardown panics in Node/Bun headless test environments.
