# 472. Fix Audio and Image Asset Cache Negative Caching and Dead Demo URLs

## Problem
When loading studio templates or scrubbing/playing the timeline in Studio, requests to audio assets failed and repeatedly looped:
```
AudioAssetCache.ts:158 [AudioAssetCache] Failed to decode audio asset "asset-sub-bass-drop": Error: HTTP fetch failed with status 404: https://actions.google.com/sounds/v1/science_fiction/deep_hum.ogg
    at HttpAssetBlob.arrayBuffer (AssetProtocolRegistry.ts:153:13)
    at async AudioAssetCache.ts:124:25
AssetProtocolRegistry.ts:151  GET https://actions.google.com/sounds/v1/science_fiction/deep_hum.ogg 404 (Not Found)
```
This warning was called continuously in an infinite loop, saturating network I/O, console logging, and CPU cycles during timeline scrubbing and playback.

### Root Causes
1. **Missing Negative Caching in `AudioAssetCache.ts`**:
   When `fetchAndDecode` failed (e.g. Due to network 404, invalid response, or corrupt decode), it caught the error, logged a warning, and deleted `assetId` from `this.inFlight`. However, it never recorded the failure in a negative cache.
   Because `WebAudioEngine` calls `getAudioChannels(assetId, src)` during timeline scrubbing, playhead advancement, and audio scheduling ticks, each check saw `!this.cache.has(assetId)` and `!this.inFlight.has(assetId)` as true, constantly re-dispatching `fetchAndDecode` every frame or scrub event (up to 60 times/sec).
2. **Identical Negative Caching Vulnerability in `AssetTextureCache.ts`**:
   In `AssetTextureCache.ts`, `resolveImageAssetAsync` deleted `src` from `inFlightResolutions` upon completion without recording a failed state. If an image URL returned 404 or corrupted data, `getVisualAsset` was called on every 60fps render tick, hammering the network and allocation loop indefinitely.
3. **Dead / Deprecated Sound URLs in Demo IR Documents**:
   Two sound files hosted on Google Actions sound library are no longer available (returning HTTP 404):
   - `https://actions.google.com/sounds/v1/science_fiction/deep_hum.ogg` (404 Not Found)
   - `https://actions.google.com/sounds/v1/science_fiction/scifi_engine_shut_down.ogg` (404 Not Found)
   These were referenced across 9 demo templates (`complexSciFiDemoIR`, `defaultDemoIR`, `cinemaMasteringDemoIR`, `astroTelemetryDemoIR`, `broadcastNewsDemoIR`, `cyberAudioVisualizerDemoIR`, `kineticTypographyDemoIR`, `quantumPhysicsDemoIR`, and `spatialAudioDemoIR`).

---

## Plan & Solutions

1. **Implemented Negative Caching & Cooldown in `AudioAssetCache.ts`**:
   - Added `failedAssets = new Map<string, number>()` with `FAILED_RETRY_INTERVAL_MS = 60_000` (60s cooldown).
   - Added `isFailed(key)` and `markFailed(assetId, src)`.
   - In `getAudioChannels` and `fetchAndDecode`: if an asset or src is marked failed, immediately return `null` without initiating any network or decoding promise.
   - On fetch/decode failure: call `markFailed(assetId, src)`.
   - On successful decode or `setDecodedMock`: clear failed state for self-healing.
   - In `preloadAssets`: skip assets that are failed.
   - In `clear()` / `dispose()`: purge `failedAssets`.
2. **Implemented Negative Caching in `AssetTextureCache.ts`**:
   - Added `failedUrls = new Map<string, number>()` with `FAILED_RETRY_INTERVAL_MS = 60_000`.
   - Added `isFailed(key)` and `markFailed(key)`.
   - In `getVisualAsset`: if `assetId` or `src` is failed, return the isolated placeholder canvas immediately without launching `resolveImageAssetAsync`.
   - In `resolveImageAssetAsync`: verify `res.ok`, and mark failed on HTTP non-200 or image decode errors.
   - On direct texture `set(assetId, ...)` or `dispose()`: clear failed tracking.
3. **Replaced Dead Audio URLs in Demo IR Templates**:
   - Validated live HTTP 200 replacement audio assets from Google Actions sounds library:
     - `deep_hum.ogg` -> `forboding_resonance.ogg` (HTTP 200 OK, low-frequency atmospheric resonance)
     - `scifi_engine_shut_down.ogg` -> `sci_fi_vortex.ogg` (HTTP 200 OK, sci-fi mechanical engine sweep)
   - Updated all references across all 9 demo IR files.
4. **Formal Verification Suite**:
   - Created `autogenerated-tests/studio_asset_cache_negative_cache_and_404_resilience.test.ts`.
   - Verified 7 test cases covering AudioAssetCache negative caching, AssetTextureCache render-loop suppression, recovery on mock injection, and demo IR URL integrity.
