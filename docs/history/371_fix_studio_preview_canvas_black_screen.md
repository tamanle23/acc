# 371: Fix Studio Preview Canvas Black Screen

## Problem
Following the native resource scope implementation in Iteration 45, the Studio preview canvas rendered completely black. Root cause investigation identified three intersecting issues:
1. **Uncaught Static Method Invocation in Web Worker**: In `preview.worker.ts`, line 415 invoked `Depth3DPlugin.cleanupSequence(seq)`. Because `cleanupSequence` was defined as an instance method on the plugin prototype rather than a static class method, `Depth3DPlugin.cleanupSequence` was `undefined`. This threw an uncaught `TypeError` inside `case 'updateTimeline'`, causing the worker to abort timeline initialization. As a result, `engine = new IRPreviewEngine(...)` was never initialized with the project's timeline sequences.
2. **Overzealous Playback Decoupling Gate**: In `WorkerRenderStrategy.ts` and `useViewportRenderStrategy.ts`, render frames and texture syncs were blocked whenever `isPlaying` was true. Because Studio timeline playback is driven by `StudioPlayheadController`'s high-frequency RAF subscriber on the main thread, blocking these calls prevented `renderFrame` from reaching the worker during playback.
3. **Missing Re-render Callback on Video Ping-Pong Arrival**: In `preview.worker.ts`, when `reader.requestSequentialFrame` resolved the active `OffscreenCanvas`, it updated `textureCache` but did not re-trigger `renderCurrentFrame(currentFrame)` to paint the newly ready frame, leaving the hero/starting frame blank.

## Plan
1. Add `public static cleanupSequence(sequenceIdOrSeq: any): void` to `Depth3DPlugin` and `Camera3DPlugin`.
2. Update `preview.worker.ts` to call `Depth3DPlugin.cleanupSequence(seq.id)` and `Camera3DPlugin.cleanupSequence(seq.id)`.
3. Pass `isPlaying` explicitly through `WorkerRenderOptions` so the worker distinguishes sequential playback from parked/scrubbing frames without prematurely blocking main-thread frame dispatch.
4. Remove blocking `if (isPlaying)` gates from `useViewportRenderStrategy.ts` and `WorkerRenderStrategy.ts`.
5. Ensure `preview.worker.ts` re-renders the current frame when `requestSequentialFrame` resolves its buffer.
