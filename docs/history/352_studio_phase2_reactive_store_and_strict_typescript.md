# 352: Studio Phase 2 — Reactive Store (`useSyncExternalStore`) & Strict TypeScript

## Problem
Following Phase 1's dead-code cleanup and worker/texture pipeline consolidation, `@acc/studio` (`apps/studio`) suffered from several state synchronization and type safety issues:
1. **Un-subscribed Stale State Bugs**:
   - `Titlebar.tsx` called `manager.getState()`, `manager.canUndo()`, and `manager.canRedo()` once during render without subscribing to `IRStateManager`, leaving the Undo/Redo toolbar buttons and template selector stale when commands were dispatched via keyboard shortcuts or the inspector.
   - `ModifierControlStrategies.tsx` (`NumberControlStrategy`) called `IRStateManager.getInstance().getState().timeline?.currentFrame ?? 0` un-subscribed, even though `ResolvedTimeline` does not own `currentFrame` (`StudioPlayheadController` does), breaking active keyframe diamond detection when scrubbing the playhead.
2. **In-Place Mutation & Async Recompile Tearing in `IRStateManager`**:
   - `dispatch()`, `undo()`, `redo()`, and `loadFromJSON()` mutated `this.state.doc` in-place before invoking async `recompile()`, preventing synchronous external store readers from immediately observing new state references.
3. **Runtime Schema Mismatch on Asset Drops in `App.tsx`**:
   - Dropping an asset onto the canvas or timeline constructed legacy `{ startFrame, timelineStartFrame, durationFrames }` objects missing canonical `type` and `time: { start, duration }`, and passed `{ videoSeq, audioSeq }` to `addLinkedAVSequences` (which expected `{ videoSequence, audioSequence }`), causing a `TypeError` on `options.videoSequence.id`.
4. **Pervasive `any` Sprawl**:
   - Over 95 explicit `any` usages across commands, timeline components, preview overlays, inspector panels, and audio/shuttle engines obscured the boundary between `IRSequence`/`IRTrack` and compiled `ResolvedSequence`/`ResolvedTrack`.

## Plan
1. Create `apps/studio/src/lib/ir/studioTypes.ts` with union types (`StudioSequence`, `StudioTrack`, `StudioAssetRecord`, `StudioDragPayload`) and pure type-safe helpers (`getSequenceStartFrame`, `getSequenceDurationFrames`, `getSequenceEndFrame`, `normalizeTracksList`, `cloneIR`, `getErrorMessage`).
2. Create `apps/studio/src/lib/ir/useStudioStore.ts` providing React 19 `useSyncExternalStore` hooks (`useIRState`, `useIRSelector`, `usePlayheadFrame`, `usePlayheadIsPlaying`).
3. Harden `IRStateManager` (`irState.ts`) and `StudioPlayheadController` (`StudioPlayheadController.ts`) with bound `subscribe`/`getSnapshot` methods and synchronous immutable state reference updates on `dispatch`, `undo`, `redo`, `switchTemplate`, and `loadFromJSON`.
4. Fix `AddLinkedAVSequenceCommand` and `App.tsx` asset drop handlers to construct valid `IRSequence` objects and support both `{ videoSequence, audioSequence }` and `{ videoSeq, audioSeq }`.
5. Replace manual `useState` + `useEffect` subscriptions and `any` annotations across `Titlebar.tsx`, `RightSidebar.tsx`, `SequenceInspector.tsx`, `TrackInspector.tsx`, `DynamicModifierInspector.tsx`, `ModifierControlStrategies.tsx`, `Timeline.tsx`, `TimelineDom.tsx`, `ClipItem.tsx`, `ClipDragProxy.tsx`, `ClipHoverHUD.tsx`, `ClipInsightCard.tsx`, `Preview.tsx`, `useGizmoTransform.ts`, `LeftSidebar.tsx`, `App.tsx`, `WebAudioEngine.ts`, `CanvasHitTester.ts`, and command classes.
