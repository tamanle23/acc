## Context & Objectives
When triggering playback in Studio (either via spacebar or the transport play button), the preview failed to advance frames and remained frozen.
1. **Root Cause Diagnosis**:
   - In `apps/studio/src/components/Timeline.tsx`, playback was driven by a `setInterval` loop with dependency array `[isPlaying, fps, irState]`. Because `currentFrame` was omitted from dependencies, it was captured as `0` in a stale closure. Every tick evaluated `onScrub(0 + 1)`, repeatedly calling `onScrub(1)` and never advancing past frame 1.
   - `isPlaying` state was isolated locally in `Timeline.tsx`, completely decoupling `Preview.tsx` and preventing viewport playback awareness.
   - `Preview.tsx` lacked interactive viewport playback controls, leaving users unable to control or inspect playback directly from the canvas viewport.
2. **Success Criteria**:
   - Establish unified playback state in `App.tsx` driving both `Preview` and `Timeline`.
   - Implement a high-resolution, wall-clock synchronized `requestAnimationFrame` loop in `App.tsx` that advances frames deterministically and loops seamlessly at `totalDurationFrames`.
   - Wire `WebAudioEngine.startPlayback` and `stopPlayback` lifecycles smoothly without multi-trigger audio corruption.
   - Add viewport status bar Play/Pause button and floating on-canvas Quick Transport bar in `Preview.tsx`.
   - Maintain 100% test pass rate across all 66 Studio unit & integration tests and achieve a clean production build.
