# 378. Universal Audio Track Processing and Dynamic Sidechain Ducking Architecture

## Problem
In `UniversalAudioMixer.ts`, audio tracks were previously partitioned into categorical buckets (`voiceTracks`, `bgmTracks`, `sfxTracks`) via brittle substring/regex inspection of track IDs and names (e.g. `track.id.includes('voice') || track.id.includes('a1')` and `track.id.includes('bgm') || track.id.includes('a2')`).
This violated the monorepo's architectural invariants:
1. Every audio track should be treated as an equal, first-class citizen without ad hoc naming assumptions.
2. Ducking behavior should be driven dynamically through modifier plugins (`sfx/dynamic_ducking`), not hardcoded track naming conventions.
3. String parsing differences between `mixTimeline` and `syncFromTimeline` led to classification drift and silent/missing audio tracks during export.

## Plan & Execution
1. Refactored `UniversalAudioMixer.mixTimeline`:
   - Followed the master bus architecture.
   - Identified ducking relationships dynamically by scanning for `sfx/dynamic_ducking` modifiers and extracting `targetBus`.
   - Rendered control/direct audio clips directly to `masterBuffer` while routing control signals into `voiceBuffer` for envelope analysis.
   - Generated `duckingEnvelope` via `DynamicAudioDuckingEngine`.
   - Modulated duckable target clips by `duckingEnvelope` before summing into `masterBuffer`.
   - Eliminated `voiceTracks`, `bgmTracks`, and `sfxTracks` string pattern matching.
2. Refactored `UniversalAudioMixer.syncFromTimeline`:
   - Removed ad hoc string heuristics (`pilot`, `voice`, `bgm`, `a1`, `a2`).
   - Treated all clips uniformly with their assigned volume, pan, and modifier configurations.
3. Added verification suite:
   - Created `autogenerated-tests/equal_audio_track_modifier_pipeline.test.ts` to test arbitrary track naming (`track-dialogue-lead`, `track-soundbed-heavy`) with dynamic sidechain ducking.
