# 393. Eliminate DndContext and Infinite Update Depth in Viewport Gizmo Direct Manipulation

## Problem
When manipulating the 2D transform gizmo in the Studio viewport (dragging the body or resizing/rotating via handles), React crashed with:
```
react-dom_client.js?v=d11da819:3610 Maximum update depth exceeded. This can happen when a component calls setState inside useEffect, but useEffect either doesn't have a dependency array, or one of the dependencies changes on every render.
getRootForUpdatedFiber    @    react-dom_client.js?v=d11da819:3610
enqueueConcurrentHookUpdate    @    react-dom_client.js?v=d11da819:3591
dispatchReducerAction    @    react-dom_client.js?v=d11da819:6920
onMove    @    @dnd-kit_core.js?v=d11da819:2746
handleMove    @    @dnd-kit_core.js?v=d11da819:1378
```

### Root Causes
1. **Nested DndContext and Ping-Pong Re-Measurement Loop**:
   - `App.tsx` provides a top-level `@dnd-kit` `<DndContext>` for dragging library presets into the timeline or canvas.
   - `Preview.tsx` nested a second `<DndContext>` inside `TransformGizmoOverlay.tsx` containing 9 `@dnd-kit` draggables (`TransformBodyDraggable` and 8 corner/edge/rotation handles).
   - During dragging, `@dnd-kit`'s internal pointer sensor dispatched `onMove` -> `onDragMove`.
   - `handleTransformDragMove` computed the new delta and called `setTransform(newTransform)`.
   - `setTransform` dynamically modified the DOM styles (`left`, `top`, `transform`) of `TransformBodyDraggable` and its child handle nodes.
   - `@dnd-kit`'s internal `useRect` mutation and resize observers detected DOM element translation, triggering immediate synchronous node rect re-measurement (`measureRect` -> `setRect`).
   - The updated rect altered `scrollAdjustedTranslate`, firing `@dnd-kit`'s internal effect dependencies `useEffect([scrollAdjustedTranslate.x, scrollAdjustedTranslate.y])` immediately in the same cycle.
   - This re-invoked `onDragMove` -> `setTransform` -> DOM updated -> `measureRect` -> `setRect` recursively, hitting React's 50-update ceiling (`Maximum update depth exceeded`).
2. **Architectural Mismatch of `@dnd-kit` for Viewport Canvas Gizmos**:
   - `@dnd-kit` is designed for sorting lists, grid reordering, and dropzone containment with DOM collision detection.
   - 2D/3D viewport transform gizmos operate in continuous sub-pixel Cartesian coordinates requiring 60–120 FPS high-frequency pointer capture, ephemeral canvas overlays, and snap guide rasterization. Wrapping 9 handles in synthetic draggable hooks caused unnecessary DOM rect observations and synthetic sensor allocations.
3. **Spurious Re-Render Allocations in Viewport Hook**:
   - `Preview.tsx` was passing `assetsMap: irState.doc?.assets || {}` to `useViewportRenderStrategy`, instantiating a new object reference on every render and triggering redundant texture checks.

---

## Plan
1. **Decouple Viewport Handles from `@dnd-kit` (`TransformHandles.tsx`)**:
   - Replace `@dnd-kit` `useDraggable` hooks with native W3C pointer events (`onPointerDown`, `onPointerMove`, `onPointerUp`, `onPointerCancel`).
   - Remove unused sensor attributes and listeners.
2. **Eliminate Nested DndContext in `TransformGizmoOverlay.tsx`**:
   - Remove `<DndContext>` wrapper from `TransformGizmoOverlay.tsx`.
   - Route pointer events directly to `TransformBodyDraggable` and all 8 edge/corner and rotation `TransformHandle`s.
3. **Refactor `useGizmoTransform.ts` to Native Pointer Capture**:
   - Implement `handlePointerDown`, `handlePointerMove`, and `handlePointerUp` utilizing `e.currentTarget.setPointerCapture(e.pointerId)` and `releasePointerCapture`.
   - Compute deltas directly from screen coordinates (`e.clientX - startCoords.clientX`) and feed into `Gizmo2DTransformation.computeDragTransform`.
   - Safeguard sequence modifier synchronization with `if (isDragging) return;` to avoid clobbering interactive transforms.
   - Maintain `latestTransformRef` to guarantee atomic modifier commit on pointer release without React state race conditions.
   - Eliminate obsolete `@dnd-kit` imports, sensors, and legacy handlers.
4. **Wire Native Handlers & Stabilize Empty Fallbacks in `Preview.tsx`**:
   - Pass `onHandlePointerDown`, `onHandlePointerMove`, `onHandlePointerUp`, and `onHandlePointerCancel` to `TransformGizmoOverlay`.
   - Define module-scoped `EMPTY_ASSETS = {}` to stabilize `useViewportRenderStrategy` dependency references.
5. **Unit Verification (`autogenerated-tests/viewport_gizmo_projection.test.ts`)**:
   - Verify `Gizmo2DTransformation.computeDragTransform` translates, scales, and rotates accurately without DOM re-measurement loops.

## Walkthrough
1. **Body Translation**:
   - Pointer down on gizmo body initiates pointer capture on the element and records start screen coordinates.
   - Mouse move updates ephemeral transform override in `IRPreviewEngine` and triggers immediate single-pass frame render at 60 FPS without DOM re-measurement ping-pong.
   - Pointer up releases pointer capture and commits the final transform state atomically to `IRStateManager`.
2. **Corner & Edge Resizing**:
   - Corner handles (`tl`, `tr`, `bl`, `br`) and edge stretch handles (`tc`, `bc`, `ml`, `mr`) capture pointer events independently, recalculating aspect ratio and snapping guides smoothly.
3. **Rotation Knob**:
   - Rotation knob captures pointer events and computes angle deltas smoothly without `@dnd-kit` sensor interference.
