# 409: Enhanced Unified PostgreSQL Architecture for Workflow Engine (Iteration 61)

## Problem
During development sandbox startup (`pnpm dev:sandbox`) and clustered PostgreSQL deployments, `WorkflowEngineConfiguration` detected PostgreSQL product metadata and wired `PostgresJdbcPersistenceAdapter`. However, because `schema-postgres.sql` was never registered in the `acc-db` or `acc-sandbox` Liquibase migration pipeline, `SystemTaskWorkerPool` repeatedly logged:
```
DEBUG: Error polling domain system:http: Failed to poll tasks from PostgreSQL: relation "task_queue" does not exist
```
Additionally, `SystemTaskWorkerPool` relied on a 200ms `@Scheduled` busy-polling loop across 5 reserved domains (`25 queries/sec` at idle) and shared the primary HikariCP connection pool with HTTP traffic.

## Plan
Implement the **"Best of Both Worlds" Enhanced Unified PostgreSQL Architecture** defined in [`master_implementation_plan_iteration_61.md`](../iterations/master_implementation_plan_iteration_61.md) and companion [`implementation_plan_54.md`](../../apps/api/doc/implementation_plan_54.md):
1. **Phase 1 (Core Liquibase Migration)**: Create `changelog-000.000.00019.xml` in `acc-db` declaring the 6 workflow tables, `idx_task_queue_poll`, autovacuum storage tuning (`autovacuum_vacuum_scale_factor = 0.05`), and the `trg_unipost_task_queued` `pg_notify` trigger. Include it in `acc-db` and `acc-sandbox` master changelogs.
2. **Phase 2 (Defensive Self-Healing)**: Add `initializeSchemaIfMissing()` to `PostgresJdbcPersistenceAdapter` and sync `/db/schema-postgres.sql`.
3. **Phase 3 (Dedicated Pool & Reactive Listener)**: Provision `HikariPool-WorkflowEngine` (min 2, max 4 connections), implement `PostgresNotificationListener` on an unpooled virtual-thread socket (`LISTEN unipost_task_queue`), and add `AtomicBoolean drainScheduled` storm coalescing in `SystemTaskWorkerPool` with a relaxed 5000ms fallback watchdog.
4. **Phase 4 (SQLite Deprecation)**: Mark `SqliteJdbcPersistenceAdapter` `@Deprecated` and set `sqlite-jdbc` to `<optional>true</optional>`.
