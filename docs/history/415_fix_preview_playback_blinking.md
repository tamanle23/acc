# 415: Fix Studio Preview Playback Blinking and Black Strobe

## Problem
During timeline playback in Studio Preview, the canvas continuously flashed and blinked on every frame. Users experienced severe visual strobing where frames appeared interspersed with black screens and jittering overlay gizmos. Exported videos had zero issues because export processes frames sequentially and synchronously.

Root causes identified:
1. **Unawaited Floating Frame Resolution & Recursive Re-render Loop**: In `preview.worker.ts`, `reader.requestSequentialFrame` was wrapped in an unawaited floating `.then()` chain. On each tick, the worker wiped the canvas and rendered *before* the video frame was resolved, then received the frame ~5–10ms later and triggered an unthrottled recursive re-render.
2. **Premature Canvas Viewport Clearing in Preview Worker**: `preview.worker.ts` and `MainThreadRenderStrategy.ts` synchronously called `ctx.fillRect(0, 0, w, h)` (black fill) before video frames were resolved and before passing the context to `IRPreviewEngine`.
3. **Transform Gizmo Overlay Jittering**: `TransformGizmoOverlay` in `Preview.tsx` was displayed during active playback. Because React synchronized frame state at a throttled low frequency (~4–15 Hz) while the canvas updated at 60 FPS, gizmo bounding boxes and handles repeatedly snapped and fluttered over the playing video.
4. **Hardcoded Canvas Aspect Ratio**: `ViewportCanvasLayer.tsx` enforced a fixed `aspectRatio: '16/9'` on canvas elements, conflicting with vertical (9:16) and square (1:1) viewport presets.

## Plan
- Refactor `preview.worker.ts` to await active video frames with `Promise.all` directly inside `renderCurrentFrame` before any rendering commands are executed.
- Eliminate premature `ctx.fillRect` / `ctx.clearRect` calls from `preview.worker.ts` and `MainThreadRenderStrategy.ts`.
- Keep `IRCanvasCompositor.ts` 100% pure and decoupled from preview runtime quirks (preserving canonical Painter's Algorithm step 1).
- In `Preview.tsx`, hide `TransformGizmoOverlay` during active playback (`!isPlaying`).
- In `ViewportCanvasLayer.tsx`, remove hardcoded `aspectRatio: '16/9'`.
- Update regression test `autogenerated-tests/preview_playback_smoothness.test.ts` to reflect decoupled project resolution canvas sizing.

## Changes
- `apps/studio/src/renderer/workers/preview.worker.ts`:
  - Awaited active video frames in parallel via `Promise.all(frameResolutions)` before drawing.
  - Eliminated unawaited floating promises and removed recursive re-render loop inside `.then()`.
  - Removed premature `ctx.fillRect` before `engine.renderFrameAsync`.
  - Maintained `currentClearColor` across worker ticks and passed `isSequentialPlayback: true` in `playbackLoop`.
- `apps/studio/src/renderer/strategies/MainThreadRenderStrategy.ts`:
  - Removed redundant front-buffer canvas clearing before `this.engine.renderFrame`.
- `packages/ir/src/renderer/shared/IRCanvasCompositor.ts`:
  - Maintained canonical, unmodified 1:1 Painter's Algorithm rendering.
- `apps/studio/src/components/Preview.tsx`:
  - Guarded `TransformGizmoOverlay` with `!isPlaying` to suppress editing bounding boxes and handles during playback.
- `apps/studio/src/components/preview/ViewportCanvasLayer.tsx`:
  - Removed hardcoded `aspectRatio: '16/9'` style rules from primary and overlay canvases.
- `autogenerated-tests/preview_playback_smoothness.test.ts`:
  - Updated scratch canvas assertion to verify decoupled canvas sizing (`const scratchW = width;`).
- `autogenerated-tests/ir_canvas_compositor_phase2.test.ts`:
  - Fixed module import for `UniversalCanvasProvider` and registered `NapiCanvasAdapter` in `beforeAll`.

## Walkthrough
During timeline playback:
1. Playhead advances frame $N$.
2. Worker prewarms lookahead clips and awaits sequential video textures for active sequences via `Promise.all`.
3. `IRCanvasCompositor` renders the frame canonically using Painter's Algorithm.
4. Canvas updates seamlessly with zero intermediate black strobe, and transform gizmos remain hidden until playback is paused.
