# [127] Phase 3: CLI Dispatcher & Unified Registry with Dry-Run Support

## 1. Problem Statement
The CLI dispatcher needed full support for dry-run AST validation (`--dry-run` / `-n`), seamless delegation to the central `PipelineRegistry`, and consistent handling of canonical pipeline identifiers and aliases across both the CLI runtime and testing harnesses.

## 2. Implementation Plan & Changes
1. **CLI Argument Parser Enhancements (`apps/cli/src/index.ts`)**:
   - Added `--dry-run` and `-n` boolean flag support in `parseCliArgs`.
   - Propagated `dryRun` flag into `defaultPipelineRegistry.execute(idOrAlias, input, { outDir, format, dryRun })`.
   - Formatted dry-run CLI output to display summary metrics without invoking costly video transcoding.
2. **Canonical Pipeline Identifier Alignment**:
   - Standardized `GenerativeStoryPipeline.id` to `'story'` while registering aliases `['4', 'generative-storytelling', 'storyteller']`.
   - Aligned scaffolding and end-to-end tests to accept canonical IDs and aliases uniformly.
3. **Unified Auto-Registration**:
   - Confirmed `registerAllPipelines()` registers all 6 pipelines dynamically on module import.
