# 426: Refactor AI-Supervisor for Electrobun Architecture and Clean Separation of Concerns

## Problem
`apps/ai-supervisor` suffered from several architectural defects and technical debt:
1. `src/bun/index.ts` was a 530-line monolith coupling REST endpoints, Server-Sent Events (SSE), static file routing, native Win32 FFI calls, window lifecycle management, system tray management, hardware profiling, and fleet lifecycle management.
2. Several pre-existing TypeScript compiler defects broke `tsc --noEmit`: missing module exports (`HardwareTierOption`), type mismatches in `configStore.ts`, invalid `.output()` call on `Subprocess` in `portScanner.ts`, duplicate function declarations in `StartupManager.ts`, missing `provision()` method alias in `RuntimeManager.ts`, missing `exitCode` property in `IProcessRunner.ts`, and missing `@acc/proto` workspace dependency.
3. Automated test suites (`supervisor_engine.test.ts` and `supervisor_solid_ui.test.ts`) were failing due to outdated expectations regarding the purged `ollama` service and legacy pre-Electrobun custom UI build paths (`dist/ui/app.js`).

## Plan
1. Fix all TypeScript compilation defects across core supervisor files and declare `*.css` module typings.
2. Extract the desktop presentation layer into modular classes (`WindowManager.ts`, `TrayManager.ts`, `DesktopApplication.ts`) under `src/bun/desktop/`.
3. Extract embedded HTTP and telemetry streaming into modular routes and an encapsulated server (`types.ts`, `telemetryRoutes.ts`, `serviceRoutes.ts`, `ttsRoutes.ts`, `staticRoutes.ts`, `HttpServer.ts`) under `src/bun/server/`.
4. Refactor `src/bun/index.ts` into a concise, declarative bootstrapper and shutdown coordinator.
5. Modernize and expand automated tests in `autogenerated-tests/` to verify the consolidated 3-service fleet, Electrobun views bundling, and modular HTTP server endpoints.
6. Verify clean typecheck (`tsc --noEmit`), 100% test pass rate (`bun test`), and Electrobun production build (`electrobun build`).

## Changes

### 1. Core Fixes & Typings
- `apps/ai-supervisor/src/bun/HardwareProfiler.ts`: Exported `HardwareTierOption = "auto" | HardwareTier`, added `driverVersion?: string` to `GpuInfo`, and exported `type SystemProfile = HardwareProfile`.
- `apps/ai-supervisor/src/bun/configStore.ts`: Updated `hardwareTierOverride` in `ControlPlaneConfig` to use `HardwareTierOption`.
- `apps/ai-supervisor/src/bun/portScanner.ts`: Replaced invalid `Bun.spawn().output()` with streaming reader `new Response(proc.stdout).text()` and `await proc.exited`.
- `apps/ai-supervisor/src/bun/StartupManager.ts`: Renamed internal duplicate function `getWindowsStartupStatus` to `checkWindowsStartupStatus`, retaining the public export shim.
- `apps/ai-supervisor/src/bun/RuntimeManager.ts`: Added `provision()` method alias delegating to `ensureRuntime()`.
- `apps/ai-supervisor/src/bun/IProcessRunner.ts`: Added `exitCode?: number | null;` to `ManagedProcess` interface and implemented the getter on `BunManagedProcess`.
- `apps/ai-supervisor/src/ui/components/TelemetryGrid.tsx`: Added safe optional chaining for `wm().activeJobId`.
- `apps/ai-supervisor/src/env.d.ts`: Created CSS module declarations for TypeScript.
- `apps/ai-supervisor/package.json`: Added `"@acc/proto": "workspace:*"` dependency and ran `pnpm install`.
- `apps/ai-supervisor/tsconfig.json`: Added `"ignoreDeprecations": "6.0"`.

### 2. Desktop Layer (`src/bun/desktop/`)
- `WindowManager.ts`: Encapsulated `BrowserWindow` singleton lifecycle, window restoration, explicit `win.webview.loadURL()`, and Win32 `bringNativeWindowToForeground` via user32 FFI.
- `TrayManager.ts`: Encapsulated system tray initialization, status color icon resolution, menu configuration, and action dispatching.
- `DesktopApplication.ts`: Orchestrates window and tray interactions, `--minimized` launch flag, and status change subscriptions.

### 3. Server & Routing Layer (`src/bun/server/`)
- `routes/types.ts`: Defined `CORS_HEADERS` and `RouteHandler` type.
- `routes/telemetryRoutes.ts`: Encapsulated SSE stream (`/api/telemetry/stream`), snapshot (`/api/telemetry/snapshot`), worker heartbeat (`/api/worker/heartbeat`), ingest sink (`/api/telemetry/ingest`), and audit history (`/api/telemetry/audits`).
- `routes/serviceRoutes.ts`: Encapsulated status/profile (`/api/status`), VRAM purge (`/api/vram/purge`), fleet restart (`/api/service/all/restart`), service control (`/api/service/:name/:action`), log stream buffer (`/api/logs/:service`), update checks (`/api/update/*`), and config management (`/api/config`).
- `routes/ttsRoutes.ts`: Encapsulated interactive neural TTS playground proxy (`/api/tts/test`) via gRPC protobuf.
- `routes/staticRoutes.ts`: Robust static file handler serving Electrobun view bundles (`index.html`, `index.js`, `index.css`, tray icons) with defensive multi-path resolution.
- `HttpServer.ts`: Clean server facade encapsulating `Bun.serve`, CORS preflight, error handling, and pipeline routing.

### 4. Entrypoint (`src/bun/index.ts`)
- Refactored monolithic entrypoint down to ~130 lines of clear, declarative initialization logic.

### 5. Automated Tests (`autogenerated-tests/`)
- `autogenerated-tests/supervisor_engine.test.ts`: Updated fleet expectations for the consolidated 3-service fleet (`python-backend`, `worker`, `studio`).
- `autogenerated-tests/supervisor_solid_ui.test.ts`: Updated to verify Electrobun views bundling (`index.html`, `index.js`, `index.css`) in `build/dev-win-x64/.../views/main`.
- `autogenerated-tests/ai_supervisor_server.test.ts`: Added unit/integration test suite covering `HttpServer` endpoints, CORS, status, telemetry, worker heartbeats, and 404 responses.

## Walkthrough
1. Running `pnpm --filter @acc/ai-supervisor build` invokes Electrobun's compiler, bundling `src/ui/index.tsx` into `index.js`, compiling Tailwind CSS into `index.css`, and bundling the main Bun process into `Resources/main.js`.
2. When starting, `main()` initializes directories and boot watchdog, resolves port collisions dynamically, profiles system hardware, starts `HttpServer`, creates `DesktopApplication` with Electrobun `BrowserWindow` and `Tray`, and starts the supervised services (`python-backend`, `worker`, `studio`).
3. Teardown handles `SIGINT` and `SIGTERM` gracefully by stopping stream consumers, tray, window, fleet services, and HTTP server.
