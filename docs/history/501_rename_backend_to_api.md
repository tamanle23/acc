# 501 — Rename `apps/backend` → `apps/api` and `@acc/backend` → `@acc/api`

## Problem

The workspace package `apps/backend` was named `@acc/backend`, inconsistently with the convention used by all other workspace members (`@acc/console`, `@acc/ui`, etc.) which use their directory basename. The directory and package name both needed to be renamed to `apps/api` / `@acc/api` to reflect that this module exposes a RESTful API surface and to align with the workspace naming convention.

## Plan

1. Physically rename the directory `apps/backend` → `apps/api` using a copy+remove approach (required on Windows due to permission issues with git mv on directories containing `.turbo` or long paths).
2. Update `apps/api/package.json` name and description.
3. Update all references in: root `package.json`, `turbo.json`, `.agents/rules/`, `docs/`, `.github/workflows/`, `scripts/`, `infra/`, `apps/console/src/`, `apps/console/playwright.config.ts`, `autogenerated-tests/`, `apps/api/acc-sandbox/README.md`, `apps/api/doc/`, `apps/console/doc/`.
4. Run `pnpm install --no-frozen-lockfile` to relink the workspace.
5. Create this history document and commit.

## Notes

- **Windows workaround**: `git mv apps/backend apps/api` and `Rename-Item` both fail with "Permission denied" on Windows due to `.turbo/` directory locks and long-path issues. Resolution: delete `.turbo`, use `Copy-Item -Recurse`, `git add apps/api`, `git rm -r -f --cached apps/backend`, `Remove-Item -Recurse -Force apps/backend`. Git correctly identifies these as renames.
- **Java class/package names** (`com.acc.*`) were NOT modified — only the Node/pnpm workspace name changes.
- **`deloyment` typo** in `apps/api/acc-ms-aio/deloyment/` is a pre-existing directory name typo; not fixed in this task.
