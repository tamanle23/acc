# 365: Eliminate Continuous Playback Memory Accumulation & Native Buffer Leaks

## Problem
During continuous timeline playback in `@acc/studio`, memory steadily climbed from baseline up past 1 GB within seconds of playback. While initial startup idle memory was bounded after eliminating eager ONNX WebAssembly model preloading, continuous playback suffered from rapid native media buffer accumulation in the rendering loop:
1. **Per-Frame Cutout and Depth Map Re-Resolution in `Depth3DPlugin`**:
   In `Depth3DPlugin.renderClipSpace()`, `resolveSubjectCutout()` and `resolveDepthMapData()` were being called asynchronously on every single 33ms frame tick (30 FPS) for active 3D sequences (`seq-holo-subject` and `seq-holo-drone`). On each tick:
   - `resolveSubjectCutout()` ingested bytes from `ContentCacheRegistry` and called `CanvasAssetLoader.loadImage()`, generating an unclosed 1080p `ImageBitmap` (8.3 MB).
   - `resolveDepthMapData()` allocated a fresh 1080p canvas via `UniversalCanvasProvider.createCanvas()`, called `CanvasAssetLoader.loadImage()`, and allocated an 8.3 MB `Uint8ClampedArray` from `getImageData()`.
   - `frame-breaker.ts` failed to find `(subjectImg as any)._bbox` (because `subjectImg` was re-created fresh every frame), repeatedly allocating unpooled canvases to recalculate bounding boxes.
   - At 30 FPS across 2 sequences, this churned over 1.5 GB to 3.0 GB of unclosed native buffers per second, completely overwhelming Chromium's garbage collector.
2. **`inFlightRequests` Map Promise Leak in `MediabunnyWorkerReader`**:
   When the concurrency ceiling (`activeDecodes >= 2`) was reached, `requestFrame()` returned `null` synchronously before the `try...finally` block, bypassing `this.inFlightRequests.delete(frame)`. Concurrency-rejected frames remained stuck as permanent resolved `Promise<null>` closures in the Map.
3. **Late-Resolving Cache Miss Frames in `preview.worker.ts`**:
   When sequential playback incurred a lookahead cache miss, `reader.requestFrame()` decoded asynchronously. By the time it resolved, the playhead had already moved past that frame. The decoded frame was stored into `textureCache` without being marked transient or closed.

## Plan
1. **Sequence-Scoped 3D State Reuse (`Depth3DPlugin`)**:
   Cache the resolved static `cutout` and `depthLayersData` directly on the active sequence node as `(sequence as any)._depth3dState`. On subsequent frames of that sequence, reuse the state directly without re-reading blobs, re-creating canvases, or decoding bitmaps.
2. **Static Sequence Cleanup Method (`Depth3DPlugin.cleanupSequence`)**:
   Provide a deterministic cleanup helper that closes `subjectImg`, `srcCanvas`, and `depthCanvas`, and removes `_depth3dState` when sequences end or timelines are updated.
3. **Canvas Scratch Pooling in `frame-breaker.ts`**:
   Replace `UniversalCanvasProvider.createCanvas()` with `acquireScratchCanvas()` and release it in a `finally` block.
4. **Intermediate Bitmap Closure in `resolveDepthMapData`**:
   Synchronously invoke `.close()` on intermediate `ImageBitmap` instances loaded from cache immediately after `drawImageCover()` blits them to the canvas.
5. **Deduplication Map Hygiene in `MediabunnyWorkerReader`**:
   Chain `.finally(() => this.inFlightRequests.delete(frame))` to the decode promise so `inFlightRequests` is guaranteed to be cleaned up under all conditions.
6. **Late-Resolving Playback Frame Disposal in `preview.worker.ts`**:
   If a frame decodes after the playhead has already passed its timestamp during playback, close it immediately.

## Changes
- `packages/ir/src/plugins/vfx/Depth3DPlugin.ts`:
  - Added sequence-scoped `_depth3dState` caching in `renderClipSpace()`, eliminating per-frame re-resolution and 50MB/frame allocations.
  - Implemented `Depth3DPlugin.cleanupSequence(sequence)` to synchronously close native ImageBitmaps and canvases.
- `packages/effect-engines/src/depth3d/frame-breaker.ts`:
  - Swapped `createCanvas()` to `UniversalCanvasProvider.acquireScratchCanvas()` with `releaseScratchCanvas()` in `finally`.
- `packages/effect-engines/src/depth3d/index.ts`:
  - Added explicit `.close()` on intermediate `dm` bitmaps loaded during depth map rasterization.
- `apps/studio/src/renderer/workers/MediabunnyWorkerReader.ts`:
  - Chained `.finally(() => this.inFlightRequests.delete(frame))` onto the returned promise to prevent closure leaks.
- `apps/studio/src/renderer/workers/preview.worker.ts`:
  - Added playhead lookbehind check in asynchronous `reader.requestFrame()` resolution to close late frames immediately.
  - Wired `Depth3DPlugin.cleanupSequence()` into `updateTimeline` sequence eviction.
