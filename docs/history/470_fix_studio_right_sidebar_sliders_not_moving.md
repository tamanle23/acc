# 470. Fix Studio RightSidebar Sliders Not Moving

## Problem
In `apps/studio/src/components/RightSidebar.tsx` and across child inspectors (`DynamicModifierInspector.tsx`, `SequenceInspector.tsx`, `TrackInspector.tsx`, `ParameterControls.tsx`), numeric sliders did not move when users dragged them. Clicking a point on the slider would position it once, but dragging continuously failed to update the slider.

### Root Causes
1. **`<Match>` Unmounting on Referential Identity Mutation**:
   In `RightSidebar.tsx`, the inspector routing was configured as:
   ```tsx
   <Match when={resolved().selectedSeq}>
     <SequenceInspector selectedSeq={resolved().selectedSeq!} ... />
   </Match>
   ```
   When the user interacted with a slider, `notifyChange` dispatched an update to `IRStateManager`, creating an immutable clone of `doc`. This produced a new `selectedSeq` object reference. In SolidJS, when `<Match when={object}>` sees a new object reference, it treats the condition as changed, unmounts the existing `<SequenceInspector>`, and mounts a new instance.
   Consequently, the slider's DOM node captured in the closure of the active pointer drag was immediately detached from the document, causing `getBoundingClientRect()` to return `{ width: 0, height: 0, left: 0 }` during subsequent `pointermove` events and locking the drag.
2. **Kobalte Synchronous Memo Evaluation Inversion**:
   In `@kobalte/core/slider`'s `SliderPrimitive.Root`, `onSlideMove` called `state.setThumbPercent` and immediately followed with `local.onChange?.(state.values())`. Because `state.values()` was backed by a memo tracking `props.value`, and Solid signals do not flush synchronously mid-call-stack, `state.values()` returned the pre-drag value, resetting the slider immediately.
3. **Transient Coordinate Invalidation**:
   In `slider.tsx`, `getValueFromPointer` dynamically measured `trackRef.getBoundingClientRect()` on every move without caching initial track geometry, making it vulnerable to any layout shifts or temporary zero-width rect evaluations.

## Plan & Solutions
1. **Stabilize Inspector Mounting in `RightSidebar.tsx`**:
   - Switched `<Match>` conditions from transient object references to boolean/mode expressions:
     ```tsx
     <Match when={currentMode() === 'sequence' && Boolean(resolved().selectedSeq)}>
       <SequenceInspector selectedSeq={resolved().selectedSeq!} ... />
     </Match>
     ```
   - This ensures `<SequenceInspector>` remains persistently mounted across property modifications.
2. **Track Geometry Caching in `slider.tsx`**:
   - Implemented `capturedGeo` in `handlePointerDown` to cache `start`, `length`, and `isVertical` at the pointerdown event.
   - In `onPointerMove`, `getValueFromPointer` utilizes the captured geometry, ensuring continuous, silky-smooth 60/120fps dragging without zero-width drops.
3. **Optimistic Visual State**:
   - Leveraged `dragValue` so the slider thumb immediately tracks pointer coordinates during active drags.
4. **Formal Verification**:
   - Validated live Chrome mouse dragging via Chrome DevTools Protocol (`Input.dispatchMouseEvent`).
   - Verified bidirectional dragging (rightwards and leftwards) moves values from `-15` to `82` and back down to `-82`.

## Changes
- `apps/studio/src/components/RightSidebar.tsx`:
  - Replaced object `<Match when={resolved().selectedSeq}>` with `<Match when={currentMode() === 'sequence' && Boolean(resolved().selectedSeq)}>`.
- `apps/studio/src/components/ui/slider.tsx`:
  - Cached `TrackGeometry` on pointerdown and utilized it during `onPointerMove`.
  - Replaced Kobalte slider with native SolidJS slider primitive with pointer capture.
- `apps/studio/src/components/inspector/strategies/PrimitiveControlStrategies.tsx`:
  - Supplied `defaultValue={defaultVal()}` and direct `value={numericVal()}` to `<Slider>`.
- `apps/studio/src/components/inspector/ParameterControls.tsx`:
  - Supplied `defaultValue={props.defaultValue}` and direct `value={props.value}` to `<Slider>`.
- `autogenerated-tests/studio_slider_properties_interaction.test.ts`:
  - Added tests for `getTrackGeometry`, `capturedGeo`, and persistent `<SequenceInspector>` mounting.
