# History Entry 368: Studio Lock-Free AudioWorklet SPSC RingBuffer (Phase 3)

## Problem
In high-performance video editing workflows, standard Web Audio buffer scheduling (`AudioBufferSourceNode`) triggers intermittent audio dropouts and pops due to garbage collection spikes on the main JavaScript thread, cross-thread message passing jitter, and memory reallocation during rapid scrubbing and high-speed J-K-L playback.

## Plan
1. Implement a lock-free Single Producer Single Consumer (SPSC) circular queue (`SharedArrayRingBuffer.ts`) backed by `SharedArrayBuffer` and synchronized via `Atomics` memory barriers.
2. Structure the memory layout with a 64-byte `Int32Array` control block (`READ_PTR`, `WRITE_PTR`, `CAPACITY`, `FLAGS`) followed by contiguous planar stereo `Float32Array` buffers.
3. Support split boundary wraparound math without copying or allocations.
4. Implement `SpscAudioWorkletProcessor.ts` to execute on the real-time high-priority Web Audio render thread every 128 samples (~2.9ms).
5. Integrate with `WebAudioEngine.ts` with automated capability detection and transparent non-isolated origin fallback.
6. Create comprehensive automated verification in `autogenerated-tests/shared_array_ring_buffer.test.ts`.

## Changes
- `apps/studio/src/lib/audio/SharedArrayRingBuffer.ts`: New lock-free SPSC circular queue with `Atomics` memory barriers and split circular boundary handling.
- `apps/studio/src/lib/audio/worklets/SpscAudioWorkletProcessor.ts`: Web Audio AudioWorkletProcessor module and idempotent registration helper.
- `apps/studio/src/lib/audio/UniversalAudioStreamWorklet.ts`: Streaming transport controller with 5ms cosine cross-fade on seek.
- `apps/studio/src/lib/audio/WebAudioEngine.ts`: Initialized `AudioWorkletNode` when `SharedArrayBuffer` is active; fallback to chunk scheduling.
- `apps/studio/src/lib/audio/index.ts`: Exported `SharedArrayRingBuffer` and `SpscAudioWorkletProcessor`.
- `autogenerated-tests/shared_array_ring_buffer.test.ts`: Added 5-suite formal concurrency and split boundary test.
- `apps/studio/doc/implementation_plan_38.md` & `apps/studio/doc/walkthrough_38.md`.
