# 209. Master Integration Plan (Iteration 3) Phase 3: Standalone Worker App (`apps/worker`)

**Date:** 2026-10-16  
**Status:** Completed  
**Scope:** `apps/worker`, `apps/ai-supervisor/src/bun/SupervisorEngine.ts`, `packages/core/src/conductor`

---

## 1. Overview & Objectives

Phase 3 of **Master Integration Plan (Iteration 3)** establishes `apps/worker` as an independent standalone workspace package:
1. **Decoupled Workflow Polling**: Replaced strict external Conductor OSS requirements with a pluggable `ITaskPoller` interface.
2. **Zero-Dependency Sandbox Poller (`SandboxTaskPoller.ts`)**: Implemented an internal task generator for local desktop workflows, allowing seamless drop-in integration with custom workflow engines.
3. **Pluggable Backend Hypervisor & VRAM Arbitrator (`BackendHypervisor.ts`)**:
   - `OllamaBackendAdapter`: Monitors Ollama health, routes LLM requests, and triggers active VRAM eviction via `keep_alive: 0`.
   - `PythonBackendAdapter`: Routes Kokoro TTS synthesis, queries gRPC/port availability, and falls back gracefully when `ACC_AI_OFFLINE=1`.
   - Pre-flight mutual VRAM eviction: Before executing high-priority jobs, requests peer adapters purge warm allocations.
4. **Core Task Commands Registered in `TaskWorkerFactory`**:
   - `acc.story.generate_script`: LLM-powered narrative script generation with fallback.
   - `acc.tts.synthesize_speech`: Speech synthesis with audio buffer output.
   - `acc.ir.compose_video`: Canonical Video IR AST composition and track compilation.
5. **SupervisorEngine Integration**:
   - Updated `SupervisorEngine.startWorker` to invoke `apps/worker/src/index.ts` passing `--sandbox`, `--python-port`, and `--ollama-port`.
