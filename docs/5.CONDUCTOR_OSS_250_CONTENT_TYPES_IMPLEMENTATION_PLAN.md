## 1. Executive Summary & Conductor OSS Architectural Vision

### 1.1 Architectural Principle: Stateless Content Engine Workers
The fundamental paradigm of this implementation is the strict separation between **Workflow Orchestration (Netflix Conductor OSS)** and **Deterministic Media Execution (ACC Engine)**.

* **ACC Engine as Stateless Conductor Task Workers:** The ACC application contains **ZERO Business Logic** (no user billing, no campaign management, no human review UI, no authorization policies). ACC acts purely as a high-performance, stateless pool of Conductor OSS Task Workers.
* **Conductor OSS as Workflow State Engine & Human Gatekeeper:** Netflix Conductor OSS owns the DAG (Directed Acyclic Graph) workflow state, scheduling, retry exponential backoff, rate limiting, and human-in-the-loop task pauses (`HUMAN_REVIEW` / `WAIT_FOR_SIGNAL` task nodes).
* **External Human UI (Out of Scope for ACC):** When human intervention is required (`Before`, `In the Middle`, or `After`), Conductor pauses the workflow. An external Human UI allows humans to inspect/alter content parameters or story JSON configs. Upon submission, the Human UI signals Conductor to complete the task with updated parameters, resuming downstream ACC task workers seamlessly.

```text
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                                Netflix Conductor OSS                                   │
│  (Workflow State Machine, Task Scheduling, Retries, Human Pause/Resume Gates)          │
└───────────┬──────────────────────────────────────────┬─────────────────────────────────┘
            │ Polls & Executes Tasks                   │ Triggers Human Task Gate
            ▼                                          ▼
┌─────────────────────────────────────────┐  ┌──────────────────────────────────────────┐
│   ACC Stateless Task Worker Pool        │  │     External Human Review UI             │
│   (Bun / Node / FFI Zero-Copy Engine)   │  │     (Modifies JSON Config / Payload)     │
│                                         │  └────────────────────┬─────────────────────┘
│  ├── acc.scraper.fetch                  │                       │
│  ├── acc.llm.summarize                  │                       │ Resumes Conductor Workflow
│  ├── acc.canvas.render_cards            │                       │ with Updated Payload
│  ├── acc.ffmpeg.compose_video           │                       │
│  ├── acc.tts.synthesize_speech          │                       │
│  └── acc.exporter.dispatch              │◄──────────────────────┘
└─────────────────────────────────────────┘
```

## 2. Design Patterns Architecture Blueprint

To ensure **zero regressions, high cohesion, and trivial maintenance** when supporting 250 content types across 6 canonical pipelines, the ACC Conductor Worker architecture strictly mandates six fundamental design patterns:

```text
                                DESIGN PATTERNS MAP
┌─────────────────────────────────────────────────────────────────────────────────────────┐
│ 1. Factory Pattern: TaskWorkerFactory instantiates workers dynamically by task type name│
│ 2. Command Pattern: Worker operations wrapped in idempotent IConductorTaskCommand       │
│ 3. Strategy Pattern: Content exporters & media processing implemented via IStrategy     │
│ 4. Flyweight Pattern: Shared AI models (vLLM, Whisper, Kokoro) managed in AssetContext  │
│ 5. Middleware Pattern: PipelineRunner chains worker execution stages defensively        │
│ 6. Decorator Pattern: Audio ducking and VFX overlays dynamically wrap base commands     │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

### 2.1 Pattern Definitions & Code Contracts

#### A. Command Pattern (`IConductorTaskCommand`)
Every atomic worker operation executed for Conductor is an idempotent Command that receives a Conductor `Task` payload, validates arguments, executes deterministic transformations, and returns a standardized `TaskResult`.

```typescript
// packages/core/src/conductor/interfaces/IConductorTaskCommand.ts
export interface ConductorTaskInput<T = Record<string, unknown>> {
  taskId: string;
  workflowInstanceId: string;
  taskDefName: string;
  inputData: T;
}

export interface ConductorTaskOutput<T = Record<string, unknown>> {
  status: 'COMPLETED' | 'FAILED' | 'IN_PROGRESS';
  outputData: T;
  logs?: string[];
  reasonForIncompletion?: string;
}

export interface IConductorTaskCommand<TInput = any, TOutput = any> {
  readonly taskDefName: string;
  validate(input: ConductorTaskInput<TInput>): void;
  execute(input: ConductorTaskInput<TInput>): Promise<ConductorTaskOutput<TOutput>>;
  rollback?(input: ConductorTaskInput<TInput>, error: Error): Promise<void>;
}
```

#### B. Strategy Pattern (`IContentTaskStrategy`)
Generators for all 250 content variations implement strategy interfaces isolated in `@acc/effect-engines` and `@acc/exporters`. Adding a 251st content variant requires **zero changes** to the Conductor worker polling loop.

```typescript
// packages/core/src/conductor/interfaces/IContentTaskStrategy.ts
export interface IContentTaskStrategy<TInput, TOutput> {
  readonly contentTypeId: string; // e.g. "static_web_001", "video_101", "audio_151"
  readonly pipelineId: string;    // "1" through "6"
  process(ctx: UnifiedPipelineContext<TInput>): Promise<TOutput>;
}
```

#### C. Factory Pattern (`TaskWorkerFactory`)
Central registry mapping Conductor task definition names (`acc.scraper.ingest`, `acc.video.render_depth3d`, `acc.exporter.dispatch`) to their respective `IConductorTaskCommand` implementations.

```typescript
// packages/core/src/conductor/TaskWorkerFactory.ts
import { IConductorTaskCommand } from './interfaces/IConductorTaskCommand';

export class TaskWorkerFactory {
  private static registry = new Map<string, IConductorTaskCommand>();

  public static register(command: IConductorTaskCommand): void {
    this.registry.set(command.taskDefName, command);
  }

  public static getCommand(taskDefName: string): IConductorTaskCommand {
    const cmd = this.registry.get(taskDefName);
    if (!cmd) {
      throw new Error(`[TaskWorkerFactory] Unregistered Conductor task command: ${taskDefName}`);
    }
    return cmd;
  }
}
```

### 3.1 Unifying Conductor Input Payload with `UnifiedPipelineContext<TInput>`
ACC's core architecture relies on `UnifiedPipelineContext<TInput>` in `@acc/core` to hold shared state, `AssetContext`, `BoundedQueue`, and `ModelHandleRegistry`.

The Conductor task worker integrates with this context using the **Adapter Pattern (`ConductorPipelineAdapter`)**:

```typescript
// packages/core/src/conductor/ConductorPipelineAdapter.ts
import { UnifiedPipelineContext, AssetContext } from '@acc/core';
import { ConductorTaskInput } from './interfaces/IConductorTaskCommand';

export class ConductorPipelineAdapter {
  /**
   * Adapts a raw Conductor task input payload into a strongly-typed UnifiedPipelineContext
   */
  public static createContext<TInput>(taskInput: ConductorTaskInput<TInput>): UnifiedPipelineContext<TInput> {
    const assetContext = new AssetContext({
      storyId: taskInput.workflowInstanceId,
      workDir: `./scratch/conductor/${taskInput.workflowInstanceId}/${taskInput.taskId}`
    });

    return {
      input: taskInput.inputData,
      assetContext,
      metadata: {
        taskId: taskInput.taskId,
        workflowInstanceId: taskInput.workflowInstanceId,
        taskDefName: taskInput.taskDefName,
        startTime: Date.now()
      },
      outputs: {}
    };
  }
}
```

### 3.2 Dual-Execution Mode: Stage-by-Stage vs Monolithic Pipeline Execution
The Conductor task worker command layer supports two distinct orchestration execution modes depending on whether human intervention is required mid-pipeline:

#### Mode A: Fine-Grained Stage Execution (For Pipelines with Human Review Gates)
When a pipeline requires mid-execution human intervention (e.g. Pipeline 4 `GenerativeStoryPipeline`), each task command invokes a specific stage of `VideoEditPipelineOrchestrator` or `PipelineRunner`:

```typescript
// packages/core/src/conductor/commands/p4/ComposeVideoTaskCommand.ts
import { IConductorTaskCommand, ConductorTaskInput, ConductorTaskOutput } from '../../interfaces/IConductorTaskCommand';
import { ConductorPipelineAdapter } from '../../ConductorPipelineAdapter';
import { VideoEditPipelineOrchestrator } from '@acc/effect-engines';
import { ExtendedPipelineIR } from '@acc/ir';

export class ComposeVideoTaskCommand implements IConductorTaskCommand {
  readonly taskDefName = 'acc.p4_story.compose_video';

  validate(input: ConductorTaskInput): void {
    if (!input.inputData?.storyConfig) {
      throw new Error('[ComposeVideoTaskCommand] Missing storyConfig in task inputData');
    }
  }

  async execute(input: ConductorTaskInput): Promise<ConductorTaskOutput> {
    const ctx = ConductorPipelineAdapter.createContext(input);
    const storyIR = input.inputData.storyConfig as ExtendedPipelineIR;

    // Direct integration with existing VideoEditPipelineOrchestrator!
    const orchestrator = new VideoEditPipelineOrchestrator();
    const renderResult = await orchestrator.executeIR(storyIR, ctx);

    return {
      status: 'COMPLETED',
      outputData: {
        videoPath: renderResult.outputFilePath,
        durationSeconds: renderResult.durationSeconds,
        renderedScenesCount: renderResult.renderedScenesCount
      }
    };
  }
}
```

#### Mode B: Coarse-Grained Pipeline Execution (For Tier A 100% Zero-Touch Pipelines)
For deterministic pipelines (e.g. Pipeline 2 Bar Chart Race, Pipeline 5 Math Solver, Pipeline 1 Weather Briefing), a single Conductor worker command dispatches the entire pipeline via `PipelineRunner`:

```typescript
// packages/core/src/conductor/commands/p2/RenderBarChartRaceTaskCommand.ts
import { IConductorTaskCommand, ConductorTaskInput, ConductorTaskOutput } from '../../interfaces/IConductorTaskCommand';
import { defaultPipelineRegistry } from '@acc/core';

export class RenderBarChartRaceTaskCommand implements IConductorTaskCommand {
  readonly taskDefName = 'acc.p2_db.render_barchart_race';

  validate(input: ConductorTaskInput): void {
    if (!input.inputData?.timeSeriesData) {
      throw new Error('[RenderBarChartRaceTaskCommand] Missing timeSeriesData in task input');
    }
  }

  async execute(input: ConductorTaskInput): Promise<ConductorTaskOutput> {
    // Delegates directly to the existing DBTemplatingPipeline in PipelineRegistry!
    const pipeline = defaultPipelineRegistry.get('2'); // '2' = DBTemplatingPipeline
    const result = await pipeline.run(input.inputData);

    return {
      status: 'COMPLETED',
      outputData: {
        artifactUrls: result.exportedUrls,
        pipelineDiagnostics: result.diagnostics
      }
    };
  }
}
```

## 4. Conductor OSS Workflow Contracts & Human Intervention State Machine

### 4.1 Conductor Task Definition Schema
All ACC tasks registered in Conductor OSS follow a uniform naming taxonomy:
`acc.<pipeline_id>.<stage_name>` (e.g., `acc.p1_scraper.fetch`, `acc.p4_story.compose_video`).

### 4.2 Human Intervention Workflow State Machine
Conductor OSS manages human intervention states cleanly using the `HUMAN_REVIEW` task gate. ACC workers never pause or wait; Conductor handles workflow pauses.

```text
[ Conductor Workflow Start ]
             │
             ▼
[ ACC Task Worker: acc.p4_story.generate_script ]
             │
             ▼
      (Intervention Stage Check)
             │
             ├── Requires Human Intervention ("In the Middle")
             │        │
             │        ▼
             │   [ Conductor Task: HUMAN_REVIEW (Status: IN_PROGRESS / PAUSED) ]
             │        │
             │        ▼  <-- External Human UI alters Story Config JSON
             │   [ Human UI signals Conductor: /tasks/complete ]
             │        │
             └────────┴─────────────────┐
                                        ▼
             [ ACC Task Worker: acc.p4_story.compose_video ]
                                        │
                                        ▼
             [ ACC Task Worker: acc.exporter.dispatch ]
                                        │
                                        ▼
                          [ Conductor Workflow Complete ]
```

## 6. Super Detailed Phase-by-Phase Implementation Roadmap

### Phase 1: Conductor OSS Communication & Poller Architecture (`packages/core/src/conductor`)

#### Implementation Code Details:
Implement `ConductorWorkerPoller.ts` in `@acc/core` using Bun native HTTP long-polling to fetch tasks continuously from Conductor OSS:

```typescript
// packages/core/src/conductor/ConductorWorkerPoller.ts
import { TaskWorkerFactory } from './TaskWorkerFactory';
import { ConductorTaskInput } from './interfaces/IConductorTaskCommand';

export class ConductorWorkerPoller {
  private isPolling = false;

  constructor(
    private conductorServerUrl: string,
    private taskDefNames: string[],
    private workerId: string = `acc-worker-${process.pid}`
  ) {}

  public start(): void {
    this.isPolling = true;
    for (const taskDefName of this.taskDefNames) {
      this.pollLoop(taskDefName);
    }
  }

  private async pollLoop(taskDefName: string): Promise<void> {
    while (this.isPolling) {
      try {
        const task = await this.pollTask(taskDefName);
        if (task) {
          const command = TaskWorkerFactory.getCommand(taskDefName);
          command.validate(task);
          const result = await command.execute(task);
          await this.updateTask(task.taskId, result);
        }
      } catch (err: any) {
        console.error(`[ConductorPoller] Error in task ${taskDefName}:`, err?.message);
        await new Promise((r) => setTimeout(r, 2000)); // Backoff delay
      }
    }
  }

  private async pollTask(taskDefName: string): Promise<ConductorTaskInput | null> {
    const res = await fetch(`${this.conductorServerUrl}/tasks/poll/${taskDefName}?workerid=${this.workerId}`);
    if (res.status === 204 || res.status === 200) {
      const body = await res.json();
      return body?.taskId ? body : null;
    }
    return null;
  }

  private async updateTask(taskId: string, result: any): Promise<void> {
    await fetch(`${this.conductorServerUrl}/tasks`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ taskId, ...result, workerId: this.workerId })
    });
  }
}
```

## 7. Omnichannel Multi-Format Publishing Architecture (1-to-N Fan-Out)

A key architectural capability of the Conductor OSS + ACC engine is that **a single Content Type / Input Seed is NOT limited to a single output format**. 

A single ingestion event (e.g., *Daily Tech Digest*, *Book Summary*, or *Creepypasta Story*) can be processed once by ACC and simultaneously fanned out to **all 5 publishing formats** in parallel using Conductor OSS `FORK_JOIN` workflow nodes.

```text
                               1-TO-N MULTI-FORMAT FAN-OUT DAG
                               ┌──────────────────────────────┐
                               │ Conductor Seed Ingestion Task│
                               │  (acc.p1_scraper.fetch / IR) │
                               └──────────────┬───────────────┘
                                              │
                                              ▼
                               ┌──────────────────────────────┐
                               │  Conductor FORK_JOIN Node    │
                               └──────┬────┬──────┬────┬──────┘
                                      │    │      │    │
            ┌─────────────────────────┘    │      │    └─────────────────────────┐
            ▼                              ▼      ▼                              ▼
 ┌───────────────────────┐      ┌─────────────┐  ┌─────────────┐      ┌──────────────────────┐
 │  Format 1: Static Web │      │Format 2:Soc.│  │Format 3:Video│      │  Format 4: Audio     │
 │  Markdown / Ghost CMS │      │X Thread Card│  │TikTok 9:16  │      │  Podcast MP3 Brief   │
 └──────────┬────────────┘      └──────┬──────┘  └──────┬──────┘      └──────────┬───────────┘
            │                          │                │                        │
            └──────────────────────────┴───────┬────────┴────────────────────────┘
                                               ▼
                               ┌──────────────────────────────┐
                               │ Conductor JOIN / Export Task │
                               │   (acc.exporter.dispatch)    │
                               └──────────────────────────────┘
```
