## 1. Context & Problem
In the Visual Storytelling Generator monorepo, both native server pipelines (`apps/cli`, `packages/core/src/ffmpeg-ffi`, `packages/effect-engines`) and browser client runtime (`apps/studio`) share common IR and computational stages.
However, platform-dependent native libraries (`@napi-rs/canvas`, `bun:ffi`, `dlopen`, native FFmpeg C shared libraries) were historically imported directly into multi-purpose pipeline modules and utility files.
This leads to:
1. **Bundler Breakage**: Vite/Rollup build errors when C++ `.node` binaries or `bun:ffi` symbols leak into client build trees.
2. **Platform Tight-Coupling**: Direct imports of `@napi-rs/canvas` or `bun:ffi` in feature code prevent easy substitution with pure Web APIs (`OffscreenCanvas`, `WebCodecs`, `WebAudio`).
3. **Fragile Maintenance & Regressions**: Unmanaged native calls can cause runtime segfaults or silent divergences between server-rendered and browser-rendered video frames.

---

## 2. Proposed Design
Adhere to the approved architectural blueprint:
1. **Monorepo Package Boundary Splitting**:
   - `@acc/core-isomorphic`: Pure TypeScript interfaces (`ICanvasInstance`, `ICanvasAdapter`, `IMediaEngineStrategy`, `IVideoDecoder`) and abstract factories (`UniversalCanvasProvider`, `MediaEngineRegistry`). Zero native C or Node/Bun dependencies.
   - `@acc/core-native`: Encapsulates all server-only native bindings (`@napi-rs/canvas`, `bun:ffi`, `FFmpegManager`, `NapiCanvasAdapter`, `BunFFIEngineStrategy`).
   - `@acc/core-web`: Encapsulates browser implementations (`HTMLCanvasElement`, `OffscreenCanvas`, `WebCanvasAdapter`, `MediabunnyClientStrategy`).
2. **Abstract Factory & Strategy Pattern**:
   - Universal Canvas and Media Engines exposed via registries (`UniversalCanvasProvider`, `MediaEngineRegistry`).
   - Clean up ~20 legacy direct imports of `@napi-rs/canvas` across CLI pipelines, effect engines, and exporters to use `UniversalCanvasProvider.createCanvas()`.
3. **Inversion of Control (IoC) Bootstrap Lifecycle**:
   - Native adapters register at CLI/server entrypoints; Web adapters register at Studio/browser entrypoints.
4. **Dual-Layer Regression Guardrails**:
   - Compile-time: ESLint / dependency-cruiser rules banning direct native imports outside `@acc/core-native`.
   - Runtime: Parity test suite validating identical drawing buffers, bounding boxes, and container durations.

---

## 3. Acceptance Criteria
- [ ] **Contract Extraction**: Extract pure isomorphic contracts (`ICanvasInstance`, `ICanvasContext2D`, `ICanvasAdapter`, `IVideoDecoder`) into isomorphic core with zero native dependencies.
- [ ] **Native Adapter Encapsulation**: Restrict `@napi-rs/canvas` and `bun:ffi` imports strictly to `@acc/core-native` (or designated adapter modules).
- [ ] **Pipeline Direct Import Migration**: Replace direct `@napi-rs/canvas` imports in `apps/cli/src/pipelines/`, `packages/effect-engines/`, and `packages/exporters/` with `UniversalCanvasProvider.createCanvas()`.
- [ ] **Compile-Time Linter & Bundler Guardrail**: Configure import restriction rules and verify Vite production build (`apps/studio`) succeeds with zero Rollup native warnings.
- [ ] **Runtime Parity Test Suite**: Add comprehensive `bun:test` under `/autogenerated-tests/` asserting cross-engine drawing and decoding parity.
