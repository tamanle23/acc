## Context & Problem
We have successfully implemented the Headless Prober Chain (Phase 1), Classifier Strategies (Phase 2), PipelineIR Builder & Director Preset Factory (Phase 3), and Legacy Bridge Adapter (Phase 4).

However, these decoupled engines need a unified, clean orchestrating **Facade** (`AutoConfigEngineFacade`) that encapsulates the end-to-end scaffolding lifecycle for all consumers (CLIs, conductor workers, REST APIs). Furthermore, the root `auto-config.ts` CLI should be modernized into an intuitive, interactive wrapper powered by `@clack/prompts`, while supporting dual-mode emission (`pipeline-ir.json`, `omnichannel-config.json`, and `story-config.json`) and non-interactive `--yes` automation.

---

## Proposed Design
Implement **Phase 5 of Universal Auto-Config**:
1. **`AutoConfigEngineFacade` (GoF Facade Pattern)** in `packages/core/src/autoconfig/AutoConfigEngineFacade.ts`:
   - `scaffoldDirectory(dirPath, options)`:
     - Chains Prober -> Classifier Registry -> PipelineIR Builder -> Director Preset Factory -> Legacy Bridge Adapter.
     - Supports dry-run and dual file emission (`pipeline-ir.json`, `omnichannel-config.json`, `story-config.json`).
     - Returns `AutoScaffoldResult`.
   - `inspectDirectory(dirPath)`:
     - Fast non-mutating preview of manifest and heuristic classifier scoring.
2. **Interactive CLI Modernization (`auto-config.ts`)**:
   - Modernized UI showing discovered assets summary, heuristic classification confidence, and modality selections.
   - Preserves flags (`-y`, `--yes`, `--pipeline`, `--aspect`, `--fps`, `--dry-run`).
   - Retains 100% backward compatibility for all scripts invoking `bun run auto-config.ts <dir>`.
3. **Exports & Verification**:
   - Re-export `AutoConfigEngineFacade` in `packages/core/src/autoconfig/index.ts` and `@acc/core`.
   - Comprehensive unit and integration tests in `autogenerated-tests/autoconfig/facade-and-cli.test.ts`.
