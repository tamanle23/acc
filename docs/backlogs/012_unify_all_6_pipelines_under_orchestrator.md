## 1. Context & Problem Statement
Prior to this enhancement, while `EditingPipelineOrchestrator` was used by Pipeline 4 (`GenerativeStoryPipeline`), Pipelines 1 (`Scraper`), 2 (`DB Templating`), 3 (`Repurposing`), 5 (`Rule Logic`), and 6 (`Ambient Stream`) executed procedural logic directly within monolithic `run()` methods. Furthermore, the generic middleware orchestrator (`PipelineRunner`) in `@acc/core` was not universally wired across all 6 pipelines.

## 2. Proposed Design & Implementation Strategy
- Defined `UnifiedPipelineContext<TInput>` and `IPipeline<TInput, TOutput>` interface in `@acc/core`.
- Enhanced `PipelineRunner` with execution timing, stage error isolation, and graceful fallback execution.
- Implemented reusable middleware stages (`createExporterDispatcherMiddleware`).
- Decomposed all 6 pipelines (`01-scraper`, `02-db-templating`, `03-repurposing`, `04-generative-story`, `05-rule-logic`, `06-ambient-stream`) into modular middleware stages.
- Created central `PipelineRegistry` and updated CLI to dispatch pipelines via the standard orchestrator interface.
- Added comprehensive end-to-end verification in `autogenerated-tests/all_6_pipelines_orchestrator.test.ts`.

## 3. Acceptance Criteria & Implementation Results
- [x] Universal `UnifiedPipelineContext` and `IPipeline` interface established in `packages/core`.
- [x] `PipelineRunner` supports stage diagnostics, timings, and resilient fallback execution.
- [x] All 6 pipelines implement `IPipeline` and assemble discrete middleware stages via `PipelineRunner`.
- [x] Central `PipelineRegistry` provides unified pipeline discovery and execution.
- [x] CLI dispatcher routes all pipeline invocations through the orchestrator.
- [x] Comprehensive test suite passes in `autogenerated-tests/all_6_pipelines_orchestrator.test.ts`.
