# 317. Decompose TimelineOverlayHUD & Refactor TimelineClipHoverHUD with Shadcn HoverCard

## Context & Problem
1. `TimelineOverlayHUD.tsx` previously conflated multiple completely unrelated timeline concerns in a single monolith file:
   - Magnetic snapping guidelines (`activeSnapGuideline`)
   - Razor/scissors tool cut position indicator (`razorHoverFrame`)
   - Floating timecode drag/trim delta badge (`timecodeHUD`)
   - Floating sequence hover HUD card (`hoveredClip`)
2. The sequence hover HUD previously relied on custom coordinate calculations (`position: absolute; bottom: ${topPx}px`) inside the virtualized scroll container, causing it to clip against container boundaries (`overflow-y-auto`) and get hidden or fail to render above sticky track headers.

## Solution & Architectural Refactor
1. **Decomposed `TimelineOverlayHUD.tsx` into Single-Responsibility Subcomponents**:
   - `TimelineSnapGuideline.tsx`: Dedicated to rendering the magnetic snap guideline (cyan for playhead/grid, emerald for abutting clip seams).
   - `TimelineRazorGuideline.tsx`: Dedicated to rendering the razor cut line and SMPTE cut frame tag.
   - `TimelineTimecodeBadge.tsx`: Dedicated to rendering floating drag & trim timecode badges.
2. **Refactored `TimelineClipHoverHUD.tsx` to Use Shadcn/Radix `HoverCard`**:
   - Replaced custom layout boilerplate with `HoverCard`, `HoverCardTrigger`, and `HoverCardContent`.
   - Extracted presentational telemetry into `TimelineClipInsightCard.tsx` (SMPTE in/out points, duration, dialogue cues, and active modifier badges).
   - `TimelineClipItem.tsx` wraps each clip in `TimelineClipHoverHUD` with `asChild`, ensuring native hover lifecycle handling without custom coordinate calculations.
   - Uses Radix's floating portal (`HoverCardPortal`), automatic collision avoidance (`avoidCollisions={true}`), and `z-[100]`, completely eliminating clipping beneath sticky headers or scroll containers.
