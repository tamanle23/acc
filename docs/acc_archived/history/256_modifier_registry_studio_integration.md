# Task 256: Dynamic Modifier Discovery in Studio RightSidebar via ModifierPluginRegistry

## Context & Objectives
Previously, `RightSidebar.tsx` in `apps/studio` defined its available effects list statically in `ALL_AVAILABLE_MODIFIERS`. Any newly registered modifiers or custom plugins in `ModifierPluginRegistry` were inaccessible through the Studio interface without manual code duplication.

This task connected `ModifierPluginRegistry` directly to `RightSidebar.tsx`:
1. Provided `listPlugins()` on `ModifierPluginRegistry` for dynamic plugin introspection.
2. Implemented `registerClientModifierPlugins()` in `@acc/ir/client` to register core modifiers in a client-safe manner without Node/FFI native binary imports.
3. Connected `apps/studio/src/main.tsx` to bootstrap the registry on client boot.
4. Refactored `RightSidebar.tsx` to dynamically query the registry, enrich plugins with UI presentation metadata from `MODIFIER_PRESENTATION_CATALOG`, and provide dynamic fallbacks for custom plugins.

## Implementation Details
- `packages/ir/src/plugins/ModifierPluginRegistry.ts`: Added `listPlugins()`.
- `packages/ir/src/plugins/clientRegistry.ts`: Created client-safe registration function with audio DSP plugins and visual/editorial strategy stubs.
- `packages/ir/src/client.ts`: Exported `registerClientModifierPlugins`.
- `apps/studio/src/main.tsx`: Called `registerClientModifierPlugins()` on launch.
- `apps/studio/src/components/RightSidebar.tsx`:
  - Replaced hardcoded array with `MODIFIER_PRESENTATION_CATALOG` and `getAvailableModifiersFromRegistry()`.
  - Dynamically evaluated `relevantModifiers` based on selected track type and registered plugins.
- `autogenerated-tests/modifier_plugin_registry_studio_integration.test.ts`:
  - Unit tests verifying isolated registry discovery, core plugin population, track type filtering, and custom plugin fallback.
