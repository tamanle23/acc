# [288] fix(studio): OffscreenCanvas Lifecycle & Remount Isolation in Timeline

**Date:** 2026-10-21  
**Scope:** `apps/studio`  

## Context & Problem
In `Timeline.tsx`, `TimelineWorkerBridge` initializes an OffscreenCanvas background track renderer by transferring control of an `HTMLCanvasElement` to a dedicated Web Worker via `canvas.transferControlToOffscreen()`.

According to the W3C HTML Canvas specification:
> `transferControlToOffscreen()` can only be called once per `HTMLCanvasElement` instance over its entire lifetime. Calling it multiple times throws an `InvalidStateError`.

When React Strict Mode double-invokes effects in development, or when navigating away and back in production, or when `Timeline` unmounts and remounts:
1. `workerBridgeRef.current.dispose()` terminates the worker thread and resets `bridge.isTransferred = false`.
2. On remount, the existing DOM `<canvas>` node from `offscreenCanvasRef.current` was passed again to `bridge.init(canvas, ...)`.
3. Calling `canvas.transferControlToOffscreen()` threw:
   ```
   [TimelineWorkerBridge] OffscreenCanvas transfer failed, falling back to main-thread canvas: 
   InvalidStateError: Failed to execute 'transferControlToOffscreen' on 'HTMLCanvasElement': 
   Cannot transfer control from a canvas for more than one time.
   ```
4. This set `this.isSupported = false` on the bridge, leaving the timeline background canvas unrendered with no active worker.

## Changes Made
1. **Defensive DOM Transfer Guard in `TimelineWorkerBridge`**:
   - Tagged transferred canvas elements with `(canvas as any).__transferred = true`.
   - Added pre-check in `TimelineWorkerBridge.init()`: if `(canvas as any).__transferred` is already true, safely abort without throwing `InvalidStateError`.
2. **React Key Lifecycle Binding in `Timeline.tsx`**:
   - Added `canvasKey` state (`const [canvasKey, setCanvasKey] = useState(0)`).
   - Attached `key={canvasKey}` to `<canvas ref={offscreenCanvasRef} key={canvasKey} ... />`.
   - If `bridge.init()` detects a canvas that was transferred in a prior lifecycle, it increments `setCanvasKey((k) => k + 1)`, ensuring React replaces the DOM node with a clean, un-transferred `<canvas>` element.
3. **Automated Verification**:
   - Added lifecycle guard test in `autogenerated-tests/timeline_worker_and_virtualization.test.ts` verifying that already-transferred canvas DOM nodes are intercepted and protected from `InvalidStateError`.
