# Architectural Comparison: `videoConfig` vs. `story-config.json`

## 1. Executive Summary

In the **Visual Storytelling Generator (ACC)** ecosystem, video generation can be driven through two distinct configuration entry points:

1. **`story-config.json`**: The canonical, human-curated storyboard manifest for Pipeline 4 (Generative Storytelling), where every visual asset, audio narration, 3D depth effect, and transition is explicitly defined per scene.
2. **`videoConfig` (`FineGrainedVideoDirectorConfig`)**: The polymorphic, programmatic director envelope supplied within task inputs for the 250 concrete omnichannel content strategies (Pipelines 1–6), designed for automated, intent-driven video synthesis and coordinated multi-modal fan-out.

Both configuration models converge into the same canonical AST—**`VideoIRDocument`**—and execute on the exact same zero-copy, deterministic rendering engine (`IRMasterRenderer`).

## 2. Fundamental Architectural Philosophy

```

│             story-config.json                │       │     videoConfig (Omnichannel Input)          │

│ • Static & Asset-First                       │       │ • Dynamic & Intent-First                     │

                       │                                                      │

                                              │
                                              ▼
                                    Canonical VideoIRDocument
                                              │

```

## 3. Core Dimension Comparison Matrix

| Architectural Dimension | `story-config.json` | `videoConfig` (`FineGrainedVideoDirectorConfig`) |
| :--- | :--- | :--- |
| **Primary Consumer** | Pipeline 4 (`GenerativeStoryPipeline`) | Omnichannel Task Strategies (Items 1–250 across Pipelines 1–6) |
| **Entry Point & Lifecycle** | Standalone JSON file on disk (e.g. `./sample-story/story-config.json`) | Sub-block inside task execution input (`input.videoConfig`) |
| **Output Scope** | Single standalone video deliverable (`.mp4`) | Coordinated fan-out (Video deliverable alongside Social, Audio, Web) |
| **Asset Binding** | **Explicit Path**: Scenes bind directly to files (`image: "1.png"`, `audio: "1.mp3"`) | **Procedural/Semantic**: Assets derived from `PipelineIR` chunks or generated by pipeline stages |
| **Director Hierarchy** | **Flat 2-Tier**: Global `settings` + Per-scene `scenes[]` overrides | **Hierarchical 3-Tier**: Global Canvas $\rightarrow$ Domain Archetype $\rightarrow$ Role & Segment Directives |
| **Timeline Resolution** | Scene array length equals exact output clip count | Dynamic: Chunks determined by content length; director rules match by **narrative role** or **index** |
| **Domain-Specific Knobs** | Generic visual/audio properties only | Polymorphic knobs (`chartVisuals`, `cryptoVisuals`, `talkingHead`, `narrativeStory`) |
| **IR Adapter** | `StoryConfigToUniversalIRAdapter` | `PipelineIRToUniversalIRAdapter` (v2.0.0) |
| **Target Audience** | Human video creators, visual storytellers, artists | Automated workflows, Conductor worker agents, programmatic bots |

## 4. Deep-Dive Comparison by Feature Subsystems

### A. Global Canvas & Resolution
- **`story-config.json`**:
  - Defined in `settings`: `width`, `height`, `fps`, `platform` (e.g., `'tiktok'`, `'youtube'`).
  - Codec flags (`videoCodec`: `'libx264'`, `'hevc_nvenc'`, `'auto'`).
- **`videoConfig`**:
  - Defined in `canvas`: `aspectRatio` (`'9:16'`, `'16:9'`, `'1:1'`, `'4:5'`), `resolution` (`'720p'`, `'1080p'`, `'4k'`), `fps`.
  - Automatically translates aspect ratio to canvas dimensions and platform targets (e.g. `9:16` $\rightarrow$ `1080x1920` for TikTok; `16:9` $\rightarrow$ `1920x1080` for YouTube).

### B. Color Grading & Atmosphere
- **`story-config.json`**:
  - `settings.colorGrading` or `scene.colorGrading` accepts `{ lutPath, contrast, saturation }`.
- **`videoConfig`**:
  - `canvas.colorGrading` accepts preset LUT names (`'cyberpunk_neon'`, `'cinematic_teal_orange'`, `'clean_tech'`), explicit `lutPath`, `contrast`, `saturation`, and `vignette`. Compiles directly into track-level `vfx/color_grading` modifier nodes.

### C. Audio Staging & Ducking
- **`story-config.json`**:
  - `settings.bgm`: `{ source, volume, loop, autoDucking }`.
  - `scenes[].sfx`: Array of explicit sound clips with `{ source, time, duration, volume }`.
- **`videoConfig`**:
  - `audioStaging`: `{ bgmTrack, autoDucking, duckingAttenuationDb, masterBgmVolume }`.
  - Stages `track_a2_bgm` automatically with ducking envelope.
  - Sound cues (`sfxCues`) can be attached to semantic roles or individual segments using logical sound tokens (`sfxType: 'impact_bass' | 'whoosh' | 'glitch'`) or custom paths, staging onto `track_a3_sfx`.

### D. Cinematography: 3D Depth & Motion
- **`story-config.json`**:
  - `scenes[].depth3d`: `{ mode: 'frame_breaker' | 'parallax_2_5d' | 'sandwich', parallaxFactor, focusDepth, ... }`.
  - `scenes[].videoSettings`: `{ pan, zoom, crop }`.
- **`videoConfig`**:
  - `depth3d`: Full parameter parity (`mode`, `parallaxFactor`, `focusDepth`, `depthMapUrl`).
  - `cameraMotion`: High-level cinematography directives (`type: 'dolly_zoom' | 'ken_burns_zoom_in' | 'pan_left'`, `intensity: 0.1-1.0`). Compiles to `transform/ken_burns` modifier.
  - Can be applied globally to roles (`roleDirectives.hook`) or to specific segment indices (`segments[i]`).

### E. Transitions
- **`story-config.json`**:
  - `settings.transition` and `scenes[].transition`: `{ type: 'xfade' | 'wipe', duration }`.
- **`videoConfig`**:
  - `transition`: `{ type: 'crossfade' | 'glitch' | 'wipeleft' | 'match_cut', durationMs, easing }`.
  - Compiles into DAG overlap sequences and `transition/*` modifier nodes.

### F. Typography & Subtitles
- **`story-config.json`**:
  - `scenes[].captions`: Static array of timed caption chunks `{ text, start, end }`.
  - `settings.captions`: Style preset (`preset: 'tiktok' | 'karaoke'`).
- **`videoConfig`**:
  - `typography`: Global preset (`'3d_sandwich'`, `'tiktok_karaoke_glow'`, `'minimal_editorial'`), `highlightColor`, `primaryColor`, `placement` (`'top' | 'center' | 'bottom'`).
  - Automatically matches text from `PipelineIR` chunks and generates timed text sequences with styling modifiers on `track_t1_captions`.

### G. Domain Archetype Polymorphism
- **`story-config.json`**:
  - None. Only knows scenes, images, audio, and transitions.
- **`videoConfig`**:
  - `archetypeDirectives`: Exposes polymorphic visual knobs for specialized content categories:
    - `chartVisuals`: Animation curve, camera zoom on leader change, glow lines.
    - `cryptoVisuals`: Floating HUD vs ticker tape, bull/bear sentiment color scheme.
    - `talkingHead`: Smart speaker-switch auto-reframe, punch-in cuts on emphasis, waveform style.
    - `narrativeStory`: Atmospheric fog density, 2.39:1 letterbox bars, ambient dust particles.

## 6. How Both Configurations Converge in Video IR

Regardless of which configuration was provided, the respective adapter transforms the configuration into a **`VideoIRDocument`**:

```
                       ┌───────────────────────────────┐
                       │        VideoIRDocument        │
                       └──────────────┬────────────────┘
                                      │
         ┌────────────────────────────┼────────────────────────────┐
         ▼                            ▼                            ▼
┌──────────────────┐         ┌──────────────────┐         ┌──────────────────┐
│  Track: Video    │         │  Track: Audio    │         │  Track: Text     │
│  (track_v1_main) │         │  (Narration/BGM) │         │(track_t1_captions│
├──────────────────┤         ├──────────────────┤         ├──────────────────┤
│ Modifiers:       │         │ • Voiceover Seq  │         │ • Kinetic Cues   │
│ • vfx/depth3d    │         │ • BGM Seq        │         │ • 3D Sandwich    │
│ • transform/     │         │   (ducking node) │         │   Styling Node   │
│   ken_burns      │         │ • SFX Seqs       │         └──────────────────┘
│ • vfx/           │         │   (gain nodes)   │
│   color_grading  │         └──────────────────┘
└──────────────────┘
```

Both paths compile down to identical nodes:
- `depth3d` becomes `ModifierNode { type: 'vfx/depth3d', params: { mode, parallaxFactor, ... } }`.
- `colorGrading` becomes `ModifierNode { type: 'vfx/color_grading', params: { lutPath, contrast, ... } }`.
- `cameraMotion` becomes `ModifierNode { type: 'transform/ken_burns', params: { type, intensity } }`.
- `transition` becomes `ModifierNode { type: 'transition/*', params: { durationFrames, overlapTarget } }`.

## 7. When to Use Which: Decision Matrix

| Scenario | Recommended Approach | Rationale |
| :--- | :--- | :--- |
| **Manual Artistic Storytelling** | `story-config.json` | Gives full granular control over exact image assets, manual voiceovers, and per-slide timings. Ideal for curated short films and picture books. |
| **Automated Omnichannel Publishing** | `videoConfig` in Task Input | Decouples content generation from format constraints. A single task produces video, social tweets, audio podcast, and web pages from unified data. |
| **Data-Driven & Dynamic Content** (e.g. Financial alerts, sports digests, chart races) | `videoConfig` in Task Input | The number of scenes or data points is unknown prior to execution. Role-based staging (`hook`, `body`, `outro`) adapts automatically. |
| **Headless Conductor Worker Pipelines** | `videoConfig` in Task Input | Integrates natively with Conductor task payloads and `UniversalStrategyTaskCommand`. |
| **Legacy Pipeline 4 CLI Tooling** (`bun run cli.ts ./sample-story`) | `story-config.json` | Preserves 100% backward compatibility with existing command-line workflows. |
