## Context & Problem
In Iteration 13, studio timeline scaling required addressing DOM rendering overhead for projects with 100+ tracks and 1,000+ sequences, high waveform decoding overhead on zoom, and non-discrete audio scrub drift.
Per user directive, battle-tested industrial libraries (`@tanstack/react-virtual` and `wavesurfer.js`) were selected to provide headless 2D windowing and peak decoding/caching, paired with a frame-accurate discrete J-K-L shuttle state machine.

---

## Proposed Design
See master specification in [`docs/master_integration_plan_iteration13.md`](../master_integration_plan_iteration13.md):
- **Pillar 1: Dependencies Addition**: `@tanstack/react-virtual` (^3.13.0) and `wavesurfer.js` (^7.8.0).
- **Pillar 2: Vertical & Horizontal Virtualization (`Timeline.tsx`)**: TanStack `useVirtualizer` for tracks, horizontal sequence viewport windowing retaining active `@dnd-kit` drag session.
- **Pillar 3: WaveSurfer Waveforms (`WaveSurferWaveform.tsx`)**: Peak caching and responsive canvas rendering.
- **Pillar 4: Frame-Accurate J-K-L Shuttle Engine (`useShuttleEngine.ts`)**: Discrete frame advancement (`frame = Math.round(timeSec * fps)`), speed state machine (`[-8x, -4x, -2x, -1x, 0x, 1x, 2x, 4x, 8x]`), single frame step (Arrow Left/Right), and hardware audio pitch preservation (up to 2x) with high-speed / reverse muting.
