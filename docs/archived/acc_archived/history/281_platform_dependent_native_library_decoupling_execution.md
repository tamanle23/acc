## 1. Context & Motivation
Direct imports of `@napi-rs/canvas`, `bun:ffi`, and native C shared libraries across domain stages (CLI pipelines, effect engines, exporters, vision models) previously created serious risks of bundler breakage (Vite / Rollup in Studio), tight platform coupling, and runtime regressions.

Following the approved architectural blueprint (`docs/master_integration_plan_iteration14.md`), we executed the 4-pillar isolation and decoupling roadmap:
1. Monorepo Package Boundary Splitting (`@acc/core-isomorphic`, `@acc/core-native`, `@acc/core-web`).
2. Contract-based Abstract Factory + Strategy Pattern (`ICanvasInstance`, `ICanvasAdapter`, `UniversalCanvasProvider`, `MediaEngineRegistry`).
3. IoC Dynamic Registration & Bootstrapping Lifecycle (`bootstrapServer` in CLI, `bootstrapClient` in Studio).
4. Dual-Layer Regression Guardrails (Static import linter script `scripts/check-native-imports.ts` and automated runtime parity suite `autogenerated-tests/platform_native_parity.test.ts`).

## 2. Changes Summary

### Phase 1: Isomorphic Core Contract Extraction
- Created pure TypeScript contracts in `packages/core/src/isomorphic/canvas/types.ts`:
  - `ICanvasInstance`: Abstract canvas surface supporting `getContext('2d')`, `toBuffer(mimeType)`, `toDataURL()`, `toBlob()`, `data()`, and `getRawCanvas()`.
  - `ICanvasContext2D`: Standard 2D rendering context operations.
  - `ICanvasAdapter`: Pluggable adapter interface (`name`, `environment: 'web' | 'node' | 'custom'`, `isSupported()`, `createCanvas()`, `loadImage()`).
  - Backward compatibility aliases: `CanvasInstance`, `CanvasContext2D`, `CanvasAdapter`, `CanvasEnvironment`.
- Implemented `UniversalCanvasProvider`:
  - Pure TypeScript abstract factory with zero native C or Node/Bun dependencies.
  - Dynamic strategy registration (`registerAdapter`, `registerLazy`, `setEngine`, `getAdapter`, `createCanvas`).
- Implemented `CanvasAssetLoader`:
  - Pure isomorphic image loader delegating to the registered `ICanvasAdapter.loadImage()`, with fallback to web standards (`createImageBitmap`, `HTMLImageElement`, `Blob`).
- Created package wrappers and path mappings:
  - `@acc/core-isomorphic` (`packages/core-isomorphic/package.json` & `packages/core-isomorphic/src/index.ts`).
  - Added conditional exports `./isomorphic`, `./native`, and `./web` in `packages/core/package.json`.
  - Added path mappings in root `tsconfig.json` and `apps/studio/vite.config.ts`.

### Phase 2: Native & Web Adapter Encapsulation
- Created `packages/core/src/native/canvas/NapiCanvasAdapter.ts`:
  - Encapsulated `@napi-rs/canvas` strictly behind `ICanvasAdapter`.
  - Implemented `createCanvas` and `loadImage` with high-performance buffer handling.
- Created `packages/core/src/web/canvas/WebCanvasAdapter.ts`:
  - Encapsulated `OffscreenCanvas` / `HTMLCanvasElement` behind `ICanvasAdapter` with zero native dependencies.
- Created server bootstrap in `apps/cli/src/bootstrap.ts` and client bootstrap in `apps/studio/src/bootstrap.ts`.
- Refactored `FFIVideoDecoder` (`packages/core/src/ffmpeg-ffi/FFIVideoDecoder.ts`):
  - Completely removed `@napi-rs/canvas` import.
  - Implemented `IVideoDecoder` using `UniversalCanvasProvider.createCanvas()` and `ICanvasInstance`.
  - Added `getNextFrame(): Promise<DecodedVideoFrame | null>`.
- Refactored `FFISceneEngine` (`packages/core/src/ffmpeg-ffi/FFISceneEngine.ts`):
  - Replaced `@napi-rs/canvas` direct imports with `UniversalCanvasProvider` and `CanvasAssetLoader`.
- Refactored `ImageProberHandler` (`packages/core/src/autoconfig/probers/ImageProberHandler.ts`):
  - Replaced dynamic `@napi-rs/canvas` import with `CanvasAssetLoader.loadImage()`.

### Phase 4: Static & Parity CI Verification
- Added static CI boundary scanner `scripts/check-native-imports.ts` wired into `package.json` (`bun run lint`), hardened to catch dynamic imports and require calls.
