# 101 - Fix Subject Bounding Box Calculation & Metadata Persistence

**Date**: 2026-10-01  
**Author**: Principal Software Engineer (Antigravity)  
**Status**: ✅ Completed  

---

## 1. Context & Problem Statement
The user observed that when running real-world vision segmentation on arbitrary images, the subject bounding box was previously miscalculating or defaulting to the full canvas bounds rather than the actual salient object size. This occurred due to:
1. An uninitialized variable reference (`maskWidth` instead of `mW`) in `createCutoutRgba`.
2. Low alpha thresholding ($>30$) catching edge transparency artifacts.
3. Lack of explicit bounding box metadata persistence alongside the generated subject cutout PNG files.

---

## 2. Solution & Architectural Implementation

### Robust Salient Object Bounding Box Pipeline
1. **Fix Bounding Box Calculation in `utils.ts`**:
   - Corrected coordinate scaling to use `mW` and `mH`:
     ```typescript
     const bbox: BoundingBox = fgPixels > 0
       ? {
           x: minX / mW,
           y: minY / mH,
           width: (maxX - minX + 1) / mW,
           height: (maxY - minY + 1) / mH,
           confidence: 0.95
         }
       : { x: 0.2, y: 0.2, width: 0.6, height: 0.6, confidence: 0.5 };
     ```
2. **Companion Metadata JSON Persistence**:
   - When `SubjectSegmentationContext.segment` generates a subject cutout, it persists both the `.png` mask and companion `.json` metadata containing the exact salient object bounding box and strategy name (`${baseName}_subject_${segStratName}_${imageChecksum}.json`).
3. **High-Confidence Alpha Thresholding in `FrameBreakerEngine`**:
   - Accepts pre-computed `subjectBBox` directly in `FrameBreakerState`.
   - Fallback scan uses high-confidence thresholding ($\text{alpha} \ge 80$) with boundary exclusion ($x, y \ge 2$) to eliminate halo/edge noise.
