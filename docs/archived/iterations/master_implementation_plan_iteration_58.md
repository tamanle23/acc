# Master Implementation Plan - Iteration 58
# Two-Tier Safeguard Architecture for Acc Backend Sandbox Platform & Seamless In-Process PGlite WASM Integration

## 1. Executive Summary
During local execution of `pnpm dev:sandbox`, Spring Boot initialization failed with:
`Caused by: org.postgresql.util.PSQLException: FATAL: database "acc" does not exist`

Investigation revealed that `acc-sandbox` attempted dynamic reflection for `io.roastedroot.pglite4j.jdbc.PgLiteDriver`, which was missing from the runtime classpath due to an artifact mismatch (`io.github.jakvbs:pglite-spring-boot-test` was declared instead with `<optional>true</optional>`). The configuration caught `ClassNotFoundException` and fell back to an external PostgreSQL instance on `localhost:5432/acc`, which failed when the database did not exist.

Following interactive `/grill-me` alignment, this iteration permanently resolves this defect by establishing:
1. **Seamless In-Process WebAssembly PostgreSQL**: Adding `io.roastedroot:pglite4j:0.0.3` directly to `acc-sandbox` and removing all external PostgreSQL fallbacks (`localhost:5432/acc`), enforcing pure in-process fail-fast database initialization.
2. **Level 1 Runtime Safeguard**: Early `EnvironmentPostProcessor` (`SandboxEnvironmentPostProcessor`) registered via `META-INF/spring.factories` (verified via adaptive research that Spring Boot 3 retains `spring.factories` for early lifecycle processors) that executes prior to any bean instantiation or database connectivity, immediately aborting startup with `SecurityException` if `application.sandbox.enabled=true` under `prod`, `production`, `sit`, or `uat` profiles.
3. **Level 2 Build-Time Safeguard**: Maven profile-driven dependency omission in `acc-ms-aio/pom.xml` (conditional on `<profile><id>sandbox</id>`), omitting `acc-sandbox` when building with `-Pprod`, `-Psit`, `-Puat`, or `-DexcludeSandbox`, exposed via convenient `pnpm build:prod` scripts.
4. **Dual Verification Suite**: Bun test suite in `autogenerated-tests/backend_sandbox_safeguards.test.ts` plus JUnit 5 test in `acc-sandbox/src/test/java/com/acc/sandbox/config/SandboxEnvironmentPostProcessorTest.java`.

## 2. Trade-off Matrices

| Dimension | Option A: Auto-Create External Postgres DB | Option B: H2 PostgreSQL Compatibility Mode | Option C: Pure In-Process PGlite WASM (Selected) |
| :--- | :--- | :--- | :--- |
| **External Dependency** | Requires active PostgreSQL on host/Docker (Port 5432) | None (Pure JVM in-memory) | None (Pure WebAssembly in JVM) |
| **PostgreSQL Feature Parity** | 100% full parity | Partial (Lacks PostgreSQL JSONB operators & RLS session settings) | 100% full PostgreSQL 17 engine parity |
| **Row-Level Security (RLS)** | Full support (`SET LOCAL app.current_tenant_id`) | Incompatible / Not supported | Full support |
| **Fail-Fast Predictability** | Fragile (Fails if port 5432 busy or credentials mismatch) | High (Zero setup) | Absolute (Strict fail-fast; zero silent fallbacks) |
| **Production Decoupling** | High | High | Supreme (Excluded at build time via Maven profiles) |

## 4. Mathematical/Algorithmic Specifications

### 4.1 Profile Exclusion Predicate
Let $\mathcal{P}_{active}$ be the set of active Spring profiles:
$$\mathcal{P}_{restricted} = \{\text{"prod"}, \text{"production"}, \text{"sit"}, \text{"uat"}\}$$
Let $E_{sandbox} \in \{0, 1\}$ be the boolean value of `application.sandbox.enabled`.

The runtime safety invariant $\mathcal{S}_{runtime}$ is defined as:
$$\mathcal{S}_{runtime} = \neg (E_{sandbox} = 1 \land \exists p \in \mathcal{P}_{active}: p \in \mathcal{P}_{restricted})$$

If $\mathcal{S}_{runtime} = 0$, startup is immediately aborted during `EnvironmentPostProcessor` execution:
$$\text{EnvironmentPostProcessorResult} = \begin{cases} \text{Proceed to context refresh}, & \text{if } \mathcal{S}_{runtime} = 1 \\ \text{throw SecurityException}, & \text{if } \mathcal{S}_{runtime} = 0 \end{cases}$$

### 4.2 Build-Time Maven Dependency Selection
Let $\mathcal{M}_{build}$ be the active Maven profiles and properties. The dependency set $\mathcal{D}_{aio}$ for `acc-ms-aio` is:
$$\mathcal{D}_{aio} = \begin{cases} \mathcal{D}_{base} \cup \{\text{acc-sandbox}\}, & \text{if } \text{"excludeSandbox"} \notin \mathcal{M}_{build} \land \mathcal{M}_{build} \cap \{\text{prod}, \text{sit}, \text{uat}\} = \emptyset \\ \mathcal{D}_{base}, & \text{otherwise} \end{cases}$$

### 5.4 `apps/backend/acc-sandbox/src/main/java/com/acc/sandbox/config/SandboxEnvironmentPostProcessor.java`
```java
package com.acc.sandbox.config;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.env.EnvironmentPostProcessor;
import org.springframework.core.env.ConfigurableEnvironment;

public class SandboxEnvironmentPostProcessor implements EnvironmentPostProcessor {
    public static final Set<String> RESTRICTED_PROFILES = Set.of("prod", "production", "sit", "uat");

    @Override
    public void postProcessEnvironment(ConfigurableEnvironment environment, SpringApplication application) {
        boolean sandboxEnabled = environment.getProperty("application.sandbox.enabled", Boolean.class, false);
        if (sandboxEnabled) {
            for (String profile : environment.getActiveProfiles()) {
                if (RESTRICTED_PROFILES.contains(profile.toLowerCase())) {
                    throw new SecurityException("CRITICAL VIOLATION: acc-sandbox cannot be enabled under restricted profile: " + profile);
                }
            }
        }
    }
}
```

## 6. Phased Roadmap

### Phase 1: In-Process PGlite WASM Dependency & Strict Driver Configuration
- Update `apps/backend/pom.xml` and `apps/backend/acc-sandbox/pom.xml` with `io.roastedroot:pglite4j:0.0.3`.
- Remove `io.github.jakvbs:pglite-spring-boot-test`.
- Refactor `PgLiteDatasourceConfiguration.java`:
  - Enforce `io.roastedroot.pglite4j.jdbc.PgLiteDriver` for in-memory and file-backed database modes.
  - Remove all fallback code to `localhost:5432/acc` and throw `IllegalStateException` on driver failure.

### Phase 2: Safeguard Level 1 — Early Runtime EnvironmentPostProcessor
- Implement `com.acc.sandbox.config.SandboxEnvironmentPostProcessor`.
- Register in `apps/backend/acc-sandbox/src/main/resources/META-INF/spring.factories`.
- Ensure `application.sandbox.enabled: false` is explicitly defined in `application-prod.yml`, `application-sit.yml`, and `application-uat.yml`.
- Add JUnit 5 test `SandboxEnvironmentPostProcessorTest.java`.

### Phase 3: Safeguard Level 2 — Build-Time Maven Packaging Exclusion
- Move `acc-sandbox` dependency in `apps/backend/acc-ms-aio/pom.xml` under profile `sandbox` (active when `!excludeSandbox`).
- Configure profiles `prod`, `sit`, `uat` in `apps/backend/pom.xml` and `acc-ms-aio/pom.xml` to set `<excludeSandbox>true</excludeSandbox>`.
- Add convenience npm scripts (`pnpm build:prod`, `pnpm build:no-sandbox`) in `package.json` and `apps/backend/package.json`.
- Create formal verification test suite `autogenerated-tests/backend_sandbox_safeguards.test.ts`.

## 8. Risk/Rollback Mitigations

- **Risk**: Build failure in CI if `-Pprod` profile configuration causes compilation errors in `acc-ms-aio`.
  - **Mitigation**: `acc-ms-aio/src/main/` contains zero direct imports of `com.acc.sandbox.*`. Spring Boot loads `acc-sandbox` purely via `AutoConfiguration.imports`. Removing the dependency at build time compiles cleanly.
- **Risk**: Existing unit tests in `acc-sandbox` break due to driver changes.
  - **Mitigation**: Run `PgLiteRlsIntegrationTest` to ensure in-memory and file-backed modes instantiate valid data sources without exception.
- **Rollback**: Standard git revert to commit `abed66da`.
