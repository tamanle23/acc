# 241. Eliminate Node APIs from Depth3D Engine

## Problem
[`packages/effect-engines/src/depth3d/index.ts`](file:///Users/anle/workspace/acc/packages/effect-engines/src/depth3d/index.ts) historically contained 12 dynamic `require(...)` calls importing Node.js built-ins (`fs`, `path`, `crypto`). This violated monorepo boundaries because `@acc/effect-engines` is consumed in isomorphic environments, browser applications (`@acc/console`), and Web Workers (`visionWorker.ts`). Furthermore, ad-hoc filesystem access bypassed the central caching and asset streaming abstractions provided by `@acc/core-isomorphic`.

## Plan
1. Introduce pure isomorphic path utilities (`normalizePath`, `getPathDir`, `getPathBase`, `joinPaths`, `isAbsolutePath`, `resolvePath`) in `depth3d/index.ts` to replace Node's `path` module.
2. Introduce an asynchronous `loadAssetBytes` helper coordinating transparently through `ContentCacheRegistry` and `AssetProtocolRegistry` to load binary assets across Node, Bun, and browser environments.
3. Replace all disk reads (`fs.promises.readFile`), access checks (`fs.promises.access`), and JSON file parsing with `loadAssetBytes`, `checkExists`, and standard `TextDecoder`.
4. Replace `crypto.createHash('md5')` with pure-TS `fastChecksum()`.
5. Verify zero `require("fs")`, `require("path")`, or `require("crypto")` calls remain in `packages/effect-engines/src/depth3d/index.ts`.
6. Run full verification test suite and native import linter guardrails.

## Changes
- **`packages/effect-engines/src/depth3d/index.ts`**:
  - Implemented pure isomorphic path helpers and `loadAssetBytes()`.
  - Refactored `checkExists`, `getStoryRootAndCacheDir`, `renderDepth3DScene`, `resolveSubjectCutout`, and `resolveDepthMapData` to eliminate all `require("fs")`, `require("path")`, and `require("crypto")`.
  - Standardized cache keys on pure-TS `fastChecksum()`.
- **`autogenerated-tests/depth_strategies_benchmark.test.ts`**:
  - Adjusted timeout for `DptLargeStrategy` download benchmark to 90s.
