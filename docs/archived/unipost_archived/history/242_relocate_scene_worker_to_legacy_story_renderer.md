# 242. Relocate SceneWorker to Legacy Story Renderer

## Problem
`SceneWorker.ts` and `SceneWorkerPool` were housed in `packages/core/src/SceneWorker.ts`. However, following the architectural modularization and quarantine of legacy multi-pass disk pipelines, `apps/legacy-story-renderer` became the sole consumer of `SceneWorkerPool`. Keeping Node `worker_threads` worker loop logic inside `@acc/core` cluttered the core library surface and coupled it to the legacy story renderer's specific concurrency model.

## Plan
1. Move `packages/core/src/SceneWorker.ts` to `apps/legacy-story-renderer/src/SceneWorker.ts`.
2. Refactor worker thread bootstrap in `SceneWorker.ts` to call `bootstrapNode()` from `@acc/core` instead of duplicated manual adapter registrations.
3. Remove `SceneWorker` from `packages/core/src/index.ts`.
4. Update `LegacyDiskStoryRenderer.ts` to import `SceneWorkerPool` locally from `./SceneWorker`.
5. Export `SceneWorker` from `apps/legacy-story-renderer/src/index.ts`.
6. Run test suites and verify zero regressions.

## Changes
- **`packages/core/src/SceneWorker.ts`**:
  - Removed file from `@acc/core`.
- **`packages/core/src/index.ts`**:
  - Removed `export * from './SceneWorker';`.
- **`apps/legacy-story-renderer/src/SceneWorker.ts`**:
  - Created standalone file in legacy story renderer package with simplified `bootstrapNode()` worker boot.
- **`apps/legacy-story-renderer/src/LegacyDiskStoryRenderer.ts`**:
  - Updated import to `./SceneWorker`.
- **`apps/legacy-story-renderer/src/index.ts`**:
  - Re-exported `SceneWorker`.
