# Video Intermediate Representation (IR) Specification

## V1.0-Stable: The Extensible Entity-Component Model

This document outlines the final, future-proof architecture for the Video Intermediate Representation (IR) schema. Designed for large-scale, automated rendering pipelines, the schema adheres to the **Open-Closed Principle**: it is open for extension via a plugin-based modifier system, but rigidly closed for core modification, ensuring zero regressions as new rendering features are introduced.

### 1. Architectural Core: The Entity-Component Paradigm

To prevent schema bloat and infinite version migrations, the IR separates structural data from processing instructions.

- **The Core (Rigid):** Defines strictly _What_ is playing (Assets) and _When_ it plays (Time Topology). This includes Tracks, Sequences, and Relational Timestamps.

- **The Modifiers (Extensible):** Defines _How_ the media is processed. All visual effects, audio processing, color grading, animations, and transitions are abstracted into generic `modifiers` arrays.

This abstraction allows legacy rendering engines to gracefully ignore unsupported new features without crashing the pipeline.

### 2. Time Topology: Relational Execution

Absolute frame integers fail in automated pipelines where dynamic content (like Text-to-Speech) changes duration. The schema utilizes a two-pass relational compiler to resolve time dynamically.

- **`after`:** Triggers a sequence immediately following the completion of a targeted sequence. Supports `overlapFrames` for transitions.

- **`syncWith`:** Aligns the start time of a sequence with another sequence across different tracks.

- **`matchLengthOf`:** Dynamically stretches or shrinks a sequence's duration to match a target sequence (e.g., locking an image's duration to a variable-length audio clip).

### 4. Validation Pipeline: Polymorphic Type Checking & Modular Schemas

To guarantee pipeline safety while maintaining an open-ended `modifiers` array, the schema utilizes JSON Schema Draft-07 **Polymorphic Validation** decoupled into two synchronized schemas:
- `schema/video-ir.schema.json`: Root structural schema validating document topology, track-sequence compatibility, and relational time constraints.
- `schema/modifiers.schema.json`: Modular modifier catalog schema validating strict parameter schemas, temporal easing curves, and domain targets.

#### Core Structural Enhancements:
1. **Explicit Sequence Types (`seq.type`)**: Strictly required property `'video' | 'image' | 'audio' | 'text' | 'overlay'`. Validated with rigid track-containment rules:
   - `video` tracks can host only `video`, `image`, or `overlay` sequences.
   - `audio` tracks can host only `audio` sequences.
   - `timed_text` tracks can host only `text` sequences.
2. **Explicit Modifier Targets (`modifier.target`)**: Strictly required property `SequenceType | SequenceType[]`. Defines which sequence types the modifier applies to and enforces track-domain boundary compatibility.
3. **Global Document Modifiers (`doc.modifiers`)**: Root post-composition modifier chain applied during master output pass (e.g., master LUT color grades, master audio limiter).
4. **Dual-Level Blend Modes (`blendMode`)**: Available at both `IRSequence` and `IRTrack` (`'normal' | 'screen' | 'multiply' | 'overlay' | 'add' | 'color_dodge' | 'soft_light'`), with sequence-level overriding track-level.

### 5. Distributed Plugin Execution & Visual Extensions

By isolating operational logic into discrete modifier plugins, rendering backends function as runtime aggregators rather than monolithic processors. When a worker node processes a sequence, it extracts the `modifiers` array and maps the `type` strings to local execution functions (e.g., executing a C++ Skia transformation for `transform/scale` or an FFmpeg audio filter for `audio/compressor`).

#### Canonical Visual Modifiers (Iteration 5):
1. **`vfx/depth3d`**:
   - `mode`: 17+ depth renderers (`frame_breaker`, `parallax_25d`, `wigglegram`, etc.)
   - `relighting`: `{ enabled: boolean, lightPosition: [x, y, z], diffuse: number, specular: number, rimIntensity: number, lightColor: string }`
2. **`vfx/camera_3d`**:
   - `keyframes`: Cubic Catmull-Rom & Bezier 3D trajectories (`time`, `position: [x,y,z]`, `target: [tx,ty,tz]`, `roll`, `fov`, `focalZ`, `focalAperture`)
   - `rackFocus`: Multi-tier focal crossfades (`foreground`, `midground`, `background`, `custom`)
3. **`overlay/canvas_particles`**:
   - `type`: `rain`, `snow`, `dust`, `embers`, `fire`, `matrix_rain`, `sci_fi_hud`, etc.
   - `useSIMD`: Vectorized high-throughput particle state updating in `Float32Array`.
   - `shaders`: Post-processing pipeline (`chromaticAberration`, `bloom`, `anamorphicFlare`).

As engineering teams develop new features—such as proprietary AI upscaling or dynamic 3D camera mapping—they simply append a new definition to the `$defs` registry. The core DAG topology and routing logic remain completely isolated from these feature expansions, establishing a highly scalable continuous integration environment for video generation.
