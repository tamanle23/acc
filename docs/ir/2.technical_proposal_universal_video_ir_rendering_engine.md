# Technical Proposal: Universal Video IR Rendering Engine

**Document Version:** 2.1.0-PROPOSAL

**Target Specification:** Video IR Schema V1.0-Stable (Extensible Entity-Component Architecture)

**Status:** Architecture Review & Core Engine Implementation Blueprint

## 1. Executive Summary

Modern automated video generation pipelines face a fundamental scalability bottleneck: tightly coupled, monolithic architectures. As schemas evolve to accommodate complex sound design, stylized visual treatments, director-level editing techniques, and multi-layer composites, legacy rendering workers continually regress or fail.

This proposal specifies the design and implementation of the **Universal Video IR Rendering Engine**, a headless, platform-agnostic media compilation and execution runtime. Built upon a **Track-First Entity-Component Model**, this engine decouples temporal topology (the "When") from media processing (the "How").

### Scope Delineation

* **In Scope:** The standalone, headless execution runtime: asset ingestion and metadata probing, two-pass topological DAG compilation, the open-closed modifier plugin registry, audio DSP filtergraph compilation, GPU/Skia frame rasterization, and FFmpeg muxing.

* **Out of Scope:** Distributed orchestration platforms, job queuing layers, workflow managers (such as Temporal, Inngest, or SQS), and high-level business logic. The engine operates purely as an idempotent, deterministic media compiler and rasterizer that consumes an IR document via CLI, standard input, or IPC and outputs verified media streams.

### Core Architectural Pillars

1. **Deterministic Relational Compilation:** A two-pass topological graph compiler that resolves dynamic dependencies (`after`, `syncWith`, `matchLengthOf`, `paddingFrames`, `overlapFrames`) into exact global frame integers before any rendering compute is allocated.

2. **Open-Closed Modifier Plugin Architecture:** Dynamic dispatching of effects, transitions, audio filters, and compositing modes via a registered plugin pattern, eliminating monolithic conditionals (`if/else` or `switch` blocks).

3. **Comprehensive Editorial & Artistic Capability:** First-class plugin primitives for advanced VFX, procedural sound design (SFX), director's cut editorial techniques (J/L cuts, rhythm snapping), and multi-layer alpha/matte compositing.

4. **Multi-Target Dispatch Pipeline:** Translating abstract IR primitives into high-performance, native backends: **FFmpeg** for demuxing and complex audio DSP graphs, **Skia / Canvas 2D** for GPU-accelerated rasterization, and **Skottie** for Lottie vector motion.

## 2. High-Level Engine Architecture

The rendering engine operates as a standalone unidirectional pipeline divided into four decoupled stages:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        Phase 1: Ingestion & Probing                    │
│      (Validates JSON Schema, probes asset streams, extracts metadata)   │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                     Phase 2: Relational DAG Compiler                   │
│   (Topological Sort, Relational Constraint Solving, Global Frame Map)  │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│             Phase 3: Modifier Plugin Dispatch & Context Binding        │
│   (VFX, SFX, Director's Cut Logic, Compositing / Overlay Envelopes)    │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│                 Phase 4: Low-Level Target Plan Generation              │
│    (FFmpeg Complex Filtergraphs, Skia Render Trees, Audio Mixing DAG)  │
└────────────────────────────────────────────────────────────────────────┘
```

## 3. Detailed Phase Specifications

### Phase 1: Ingestion & Asset Probing

Before temporal topology can be evaluated, variable-length assets (e.g., dynamic TTS audio, remote video clips) must have their physical dimensions and sample durations established.

* **Schema Guard:** Validates the incoming IR against the Draft-07 Polymorphic JSON Schema using high-speed native validation (e.g., Rust-based `jsonschema` or native Ajv).

* **Metadata Prober:**

  * For local/cached assets: Reads headers directly via `libavformat` bindings.

  * For remote cloud assets (S3 / HTTP): Executes HTTP byte-range requests to parse container headers (`moov` atom in MP4, RIFF header in WAV) without streaming full payloads.

  * Honors `sourceTrim` bounds defined in the asset registry.

* **Output:** An immutable `Map<AssetId, AssetMetadata>` containing exact frame durations, channel layouts, pixel formats, and intrinsic sample rates.

### Phase 2: Relational DAG Compiler (Two-Pass Resolution)

The compiler converts an abstract, non-linear relational specification into an absolute frame-indexed timeline.

#### Graph Dependency Resolution

Every sequence block's temporal boundaries are represented as nodes in a Directed Acyclic Graph (DAG):

1. **Duration Evaluation:**

   * **Explicit:** Evaluates integer `durationFrames`.

   * **Asset Matched:** Resolves `matchAssetDuration` against Phase 1 probe metadata.

   * **Relational:** Resolves `matchLengthOf: "<TargetSequenceId>"`. If `paddingFrames` is defined:

     $$
     \text{Duration} = \text{Duration}_{\text{target}} + \text{Padding}
     $$

2. **Start Frame Evaluation:**

   * **Explicit:** Static frame integer.

   * **Synchronized (`syncWith`):** Snaps start frame to the target sequence's resolved `startFrame` plus optional `offsetFrames`.

   * **Chained (`after`):** Evaluates based on target sequence's resolved `endFrame`:

     $$
     \text{Start} = \text{End}_{\text{target}} - \text{Overlap}
     $$

#### Cycle & Deadlock Detection

The compiler executes Kahn's Topological Sorting algorithm. If circular dependencies are discovered (e.g., Sequence A starts after B, while Sequence B matches the length of A), the compiler immediately halts with a descriptive cycle trace before rendering resources are consumed.

### Phase 3: Modifier Plugin Architecture (Open-Closed Pattern)

The engine rejects hardcoded effect interpreters in favor of a **Polymorphic Plugin Registry**.

```typescript
export interface ModifierContext {
  targetType: 'track' | 'sequence';
  targetEntity: ResolvedTrack | ResolvedSequence;
  timeline: ReadonlyMap<string, ResolvedSequence>;
  renderPlan: RenderPlan;
  fps: number;
  canvas: { width: number; height: number };
}

export interface ModifierPlugin<TParams = Record<string, unknown>> {
  readonly type: string;
  readonly targetScope: 'track' | 'sequence' | 'both';
  validate?(params: unknown): params is TParams;
  execute(context: ModifierContext, params: TParams): Promise<void> | void;
}
```

#### Plugin Registration & Graceful Degradation

* **Registration:** Plugins register their unique URI (e.g., `vfx/camera_shake`, `sfx/spatial_panner`, `editorial/j_cut`).

* **Degradation Policy:** When the executor encounters a modifier type absent from the registry:

  1. Emits a structured diagnostic log with level `WARN`.

  2. Bypasses the modifier and proceeds with pipeline compilation without failing the job.

* **Fault Containment:** If a registered plugin throws a runtime exception during evaluation, the engine catches the error, tags the artifact with an `ExecutionFault`, and completes rendering uncorrupted tracks when configured in fault-tolerant mode.

## 4. Deep-Dive: Comprehensive Plugin Specifications

To support broadcast-grade automation and AI-driven cinematography, the engine specifies four core plugin domains: **Visual Effects (VFX)**, **Sound Effects (SFX)**, **Director's Cut Techniques**, and **Overlay & Compositing Systems**.

### 4.1 Visual Effects (VFX) Plugins

VFX plugins execute across two distinct scopes: clip-level (sequences) and stream-level (tracks). They manipulate frame geometry, lighting, lens characteristics, color matrices, and temporal noise.

```
┌────────────────────────────────────────────────────────────────────────┐
│                             VFX Pipeline                               │
│                                                                        │
│  [Source Frame] ──► [Geometry / Transform] ──► [Lens & Color Shader]  │
│                                                       │                │
│  [Final Output] ◄── [Temporal / Grain Pass] ◄─────────┘                │
└────────────────────────────────────────────────────────────────────────┘
```

#### 4.1.1 Hierarchical Execution Order (Sequence-Level vs. Track-Level)

When VFX plugins exist simultaneously on a track and on an individual sequence within that same track, the engine executes them in a strict **Bottom-Up Order of Operations**:

```
[ Raw Asset Frame ]
         │
         ▼
 1. Sequence-Level VFX (Clip Space)
    ↳ Local crop, chroma keying, clip spatial transforms, optical distortion
         │
         ▼
[ Sequence Frame Buffer ]
         │
         ▼
 2. Track Timeline Assembly (Concatenation / Temporal Blitting)
         │
         ▼
 3. Track-Level VFX (Track Stream Space)
    ↳ Global camera shake, film grain, track-wide LUT, motion blur
         │
         ▼
[ Track Output Buffer ]
         │
         ▼
 4. Master Canvas Compositing (Blend modes, alpha over, bus routing)
```

##### Architectural Rationale

1. **Scope and Coordinate Decoupling:**
   * **Sequence VFX operates in Local Clip Space:** Keyframes, dimensions, and transformations are strictly bounded by the asset's relative timeline ($t_{\text{rel}} \in [0, \text{duration}]$). Operations like corner pinning, subject masking, or isolated chromatic aberration must execute while the clip is an isolated entity.
   * **Track VFX operates in Continuous Stream Space:** Track-level modifiers evaluate across the global time axis, treating incoming sequence outputs as a unified, seamless video stream.

2. **Physical and Visual Realism:**
   * **Film Grain & Texture Fidelity:** If track-level film grain were evaluated *before* sequence-level zoom or scaling, the clip transform would enlarge the grain particles during that sequence, producing low-resolution digital noise artifacts. By running Sequence VFX first, the asset scales smoothly, and the Track VFX subsequently applies uniform, resolution-consistent grain across the entire track.
   * **Camera Shake Consistency:** When a track applies Simplex noise shake to simulate a physical camera, it must displace the aggregate visual output. If track shake ran prior to sequence scaling, clip-level scale and position transforms would distort the shake vectors unevenly across edit seams.
   * **Chroma Key Integrity:** Green-screen despill and alpha matte extraction require unmodified source pixels. A track-level color grade or 3D LUT applied beforehand alters green hue coordinates, degrading keyer accuracy.

##### Low-Level Execution Mapping

* **FFmpeg Filtergraph Formulation:** Input pads pass through sequence filters before concatenation, followed by track filters:

  ```text
  # 1. Sequence-level processing (isolated per stream)
  [0:v] scale=1920:1080, chromaprint_or_lensdistortion [seq_1_vfx];
  [1:v] scale=1920:1080, eq=contrast=1.2 [seq_2_vfx];

  # 2. Track concatenation
  [seq_1_vfx][seq_2_vfx] concat=n=2:v=1:a=0 [track_v1_raw];

  # 3. Track-level processing (applied to aggregate stream)
  [track_v1_raw] lut3d='slog3_to_rec709.cube', noise=c1s=8:allf=t [track_v1_final];
  ```

* **Skia / Canvas 2D Pipeline:**
  1. **Sequence Pass:** The engine allocates an isolated offscreen surface (`SkSurface`), applies the sequence's local affine matrix transforms, draws the source asset, and evaluates local shader uniforms.
  2. **Track Pass:** The rendered sequence surface blits into the track's layer buffer at its resolved global frame position. The track's post-processing shaders (color grading, fullscreen noise) then execute over the composite track surface before master canvas integration.

---

#### 4.1.2 Plugin Definitions

##### 1. Procedural Camera Shake (`vfx/camera_shake`)

Simulates handheld or high-impact physical camera physics without static keyframe sets.

* **Parameters:**

  * `intensity` (float): Amplitude multiplier ($[0.0, 10.0]$).

  * `frequency` (float): Speed of oscillation in cycles per second.

  * `octaves` (int): Layered noise complexity (1–4).

  * `decay` (enum: `"none" | "exponential" | "linear"`): Used for impact tremors that diminish over time.

* **Target Execution:** Generates high-order Perlin or Simplex noise vectors evaluated per frame. Injects dynamic affine translation and rotation matrices ($X, Y, \theta$) directly into the Skia canvas matrix stack or FFmpeg's `crop` and `rotate` expression filters.

##### 2. Chromatic Aberration & Lens Distortion (`vfx/chromatic_aberration`)

Simulates optical lens imperfection, dynamic impact distortion, and chromatic fringing.

* **Parameters:**

  * `radialOffset` (float): Radial distance of channel divergence.

  * `redShift` (vec2: $[x, y]$), `blueShift` (vec2: $[x, y]$): Directional shift vectors for color channels.

  * `barrelDistortion` (float): Curvature coefficient ($k_1$) for spherical lens distortion.

* **Target Execution:** Translated into custom Skia SKSL (Skia Shading Language) fragment shaders or FFmpeg's `lenscorrection` filter, sampling R, G, and B color planes independently with radial coordinate offsets.

##### 3. Directional Motion Blur (`vfx/motion_blur`)

Applies synthetic velocity blur to spatial transforms and high-speed cuts.

* **Parameters:**

  * `shutterAngle` (float): Simulation angle in degrees (e.g., $180^\circ$ for standard film cadence).

  * `samples` (int): Number of intermediate sub-frame samples (4–16).

* **Target Execution:** Interpolates intermediate transformation matrices between frame $t$ and frame $t+1$. Skia accumulates sub-frame rasterizations with a decaying weighted alpha curve before buffer presentation.

##### 4. Cinematic Film Grain & Halation (`vfx/film_grain`)

Replaces sterile digital rendering with organic analog characteristics.

* **Parameters:**

  * `iso` (int): Grain intensity baseline (100–3200).

  * `particleSize` (float): Average radius of grain clusters.

  * `monochrome` (boolean): Whether grain affects luma only or includes chroma noise.

  * `halationIntensity` (float): Red bleed threshold across high-exposure highlights.

* **Target Execution:** Compiled into an SkSL fragment shader applying a pseudo-random seed function:

  $$
  \text{Seed}(x, y, t) = \text{Fract}(\sin(x \cdot 12.9898 + y \cdot 78.233 + t \cdot 43.123) \cdot 43758.5453)
  $$

  Halation utilizes a downsampled luminance blur pass composited with a reddish transfer curve.

### 4.2 Sound Effects (SFX) & Audio Design Plugins

SFX plugins handle procedural audio synthesis, acoustic space simulation, dynamic envelopes, and surround/stereo imaging.

```
┌────────────────────────────────────────────────────────────────────────┐
│                              SFX Pipeline                              │
│                                                                        │
│  [Source Audio] ──► [Spatial Panner] ──► [Convolution Reverb]          │
│                                                  │                     │
│  [Output Bus]   ◄── [Dynamic Ducking Matrix] ◄───┘                     │
└────────────────────────────────────────────────────────────────────────┘
```

#### 1. Convolution Acoustic Reverb (`sfx/convolution_reverb`)

Places speech, footsteps, or music into realistic physical environments using impulse response (IR) profiles.

* **Parameters:**

  * `impulseAssetId` (string): Asset pointer to a calibrated WAV impulse response (e.g., cathedral, small studio, bathroom).

  * `wetMix` (float): Ratio of reverberated signal ($[0.0, 1.0]$).

  * `dryMix` (float): Ratio of direct original signal ($[0.0, 1.0]$).

  * `predelayMs` (float): Initial delay before reflections activate.

* **Target Execution:** Translates directly into FFmpeg's `afir` (audio FIR filter) complex filtergraph segment:

  ```
  [aud_in][ir_stream]afir=wet=0.35:dry=0.85:dry_channel=0[aud_out]
  ```

#### 2. Azimuth & Binaural Spatial Panning (`sfx/spatial_panner`)

Moves sound sources across the stereo or surround sound field synchronized with on-screen visual coordinates.

* **Parameters:**

  * `azimuth` (float / animation): Horizontal angle in degrees ($-90^\circ$ left, $+90^\circ$ right).

  * `distance` (float): Perceived distance in meters, governing attenuation and high-frequency air dampening.

  * `interpolation` (enum: `"linear" | "spherical"`): Easing between keyframes.

* **Target Execution:** Compiles into FFmpeg's `stereotools` and `lowpass` filters, or generates multi-channel audio phase delays calculating interaural time differences (ITD) and interaural level differences (ILD).

#### 3. Procedural Whoosh & Impact Generator (`sfx/procedural_whoosh`)

Generates cinematic swooshes and impact hits for transitions without requiring manual pre-rendered audio files.

* **Parameters:**

  * `durationMs` (int): Total sound duration.

  * `peakPosition` (float): Relative timing of highest frequency and volume ($[0.0, 1.0]$).

  * `frequencyStartHz` (float), `frequencyEndHz` (float): Pitch sweep trajectory.

  * `subBassBoost` (boolean): Appends an 808-style 40 Hz sub-bass sine burst at the peak point.

* **Target Execution:** Synthesizes audio buffers in memory via native DSP code (pink noise generator modulated through a dynamic resonant bandpass filter) or injects an FFmpeg `anoisesrc` + `asweep` pipeline.

#### 4. Multitrack Dynamic Ducking Envelope (`sfx/dynamic_ducking`)

Advanced sidechain compression that attenuates background music and sound effects relative to dialogue intelligibility.

* **Parameters:**

  * `controlTrackId` (string): The master dialogue track providing the reference envelope.

  * `attenuationDb` (float): Amount of gain reduction applied to target (e.g., `-18.0 dB`).

  * `attackMs` (float): Time taken to lower volume once voiceover begins (e.g., `20ms`).

  * `holdMs` (float): Hold duration preventing rapid volume "pumping" between sentence pauses (e.g., `250ms`).

  * `releaseMs` (float): Smooth recovery time back to unity gain (e.g., `500ms`).

* **Target Execution:** Compiles to FFmpeg's `sidechaincompress` filter with calibrated detection levels:

  ```
  [bgm][dialogue]sidechaincompress=threshold=0.08:ratio=6:attack=20:release=500[bgm_ducked]
  ```

### 4.3 Director's Cut Editorial Plugins

Director's Cut plugins introduce cinematic editorial conventions, translating non-linear editorial language into mathematical sequence constraints.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        Director's Cut Techniques                       │
│                                                                        │
│  J-Cut:       Audio [   Sequence A   ]──►[      Sequence B      ]      │
│               Video [       Sequence A       ]──►[   Sequence B   ]    │
│                                                                        │
│  L-Cut:       Audio [       Sequence A       ]──►[   Sequence B   ]    │
│               Video [   Sequence A   ]──►[      Sequence B      ]      │
└────────────────────────────────────────────────────────────────────────┘
```

#### 1. J-Cut & L-Cut Split Edits (`editorial/split_edit`)

Decouples visual and audio transition points between consecutive sequences to maintain dialogue continuity.

* **Mechanics:**

  * **J-Cut:** Audio from Sequence $B$ begins *before* the video of Sequence $A$ cuts away.

  * **L-Cut:** Video cuts to Sequence $B$, while the audio of Sequence $A$ *continues playing* under Sequence $B$.

* **Parameters:**

  * `mode` (enum: `"j_cut" | "l_cut"`).

  * `splitDurationFrames` (int): Length of the temporal offset (e.g., 24 frames).

  * `crossfadeAudio` (boolean): Applies an equal-power ($3\text{ dB}$) audio crossfade across the seam.

* **Target Execution:** Evaluated during Phase 2 (Compiler). The DAG compiler desynchronizes the `startFrame` calculation for the audio stream relative to its paired video stream, extending boundaries while validating overlap limits.

#### 2. Smash Cut (`editorial/smash_cut`)

Abrupt, high-contrast transition between two scenes with drastically different volume and visual energy.

* **Parameters:**

  * `targetSequenceId` (string): Outgoing sequence boundary.

  * `audioDropThresholdMs` (float): Hard zero-crossing audio cut-off speed ($< 5\text{ ms}$) preventing speaker pops.

  * `visualFlashFrame` (boolean): Optional single-frame white exposure hold on the cut line.

* **Target Execution:** Enforces zero frame padding or blending. Inserts immediate gain envelopes to zero dB at the frame seam and bypasses default audio cross-fade smoothing.

#### 3. Rhythmic Beat-Snapping (`editorial/rhythm_cut`)

Locks visual cuts to the rhythmic transients of a designated audio music track.

* **Parameters:**

  * `musicTrackId` (string): Reference audio track containing the song.

  * `bpm` (float, optional): Exact tempo if known.

  * `snapToleranceFrames` (int): Maximum distance (e.g., $\pm 4$ frames) an edit will shift to snap to the nearest downbeat.

  * `division` (enum: `"1/1" | "1/2" | "1/4" | "1/8"`): Musical grid resolution.

* **Target Execution:** Phase 2 evaluates transient markers or calculates temporal beat grids:

  $$
  \text{BeatIntervalFrames} = \frac{\text{GlobalFPS} \times 60}{\text{BPM}} \times \text{Division}
  $$

  Snaps target sequence boundaries to the nearest mathematical grid node.

#### 4. Whip Pan Match Cut (`editorial/whip_pan_transition`)

Combines rapid camera acceleration, directional motion blur, and a matched incoming angle to create a seamless cut between disparate locations.

* **Parameters:**

  * `direction` (enum: `"left" | "right" | "up" | "down"`).

  * `durationFrames` (int): Total transition time (typically 8–16 frames).

  * `motionBlurIntensity` (float): Vector blur magnitude.

  * `pairedSFX` (boolean): Automatically triggers a synthesized `sfx/procedural_whoosh` at the seam point.

* **Target Execution:** Phase 4 generates an affine translation ramping exponentially:

  $$
  X(t) = \text{Width} \times \left(\frac{t}{\text{Duration}}\right)^3
  $$

  Both outgoing and incoming frames are blended with directional Skia motion blur along the specified axis.

### 4.4 Advanced Overlay & Compositing Plugins

Overlay plugins govern multi-layer blending, matte extraction, chroma keying, and dynamic coordinate layouts.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        Compositing / Overlay Tree                      │
│                                                                        │
│   [Base Track (V1)] ────────────────────────────────┐                  │
│                                                     ▼                  │
│   [Overlay Track (V2)] ──► [Chroma Key / Matte] ──► [Blend Mode Blit]  │
│                                                     │                  │
│   [Final Composited Surface] ◄──────────────────────┘                  │
└────────────────────────────────────────────────────────────────────────┘
```

#### 1. Mathematical Blend Modes (`overlay/blend_mode`)

Controls the algebraic pixel interaction between higher video tracks and lower base tracks.

* **Supported Modes:**

  * `multiply`: $C_{\text{result}} = C_{\text{top}} \times C_{\text{bottom}}$ (Darkening shadows, texture transfers).

  * `screen`: $C_{\text{result}} = 1 - (1 - C_{\text{top}}) \times (1 - C_{\text{bottom}})$ (Light leaks, explosions, sparks).

  * `overlay`: Preserves highlights and shadows of base while shifting midtones.

  * `color_dodge`, `color_burn`, `soft_light`.

* **Target Execution:** Bound directly to Skia's `SkBlendMode` enum during rasterization, or compiled to FFmpeg's `blend` filter (`blend=all_mode='screen'`).

#### 2. Track Matte & Alpha Masking (`overlay/track_matte`)

Uses the luminance or alpha transparency of a target track to mask the visibility of another track.

* **Parameters:**

  * `matteTrackId` (string): Track identifier serving as the stencil.

  * `matteType` (enum: `"alpha" | "luma" | "inverted_alpha" | "inverted_luma"`).

* **Target Execution:** Translates to Skia compositing layers utilizing `SkClipOp` and `SkBlendMode::kDstIn`, or FFmpeg's `maskedmerge` filter:

  ```
  [video_stream][matte_stream]maskedmerge[composited_stream]
  ```

#### 3. Real-Time Chroma Keying (`overlay/chroma_key`)

Extracts greenscreen or bluescreen backgrounds from subject footage with edge softening and despill compensation.

* **Parameters:**

  * `keyColor` (hex string): Target color to remove (e.g., `#00FF00`).

  * `similarity` (float): Color distance threshold ($[0.0, 1.0]$).

  * `smoothness` (float): Softness ramp applied to edges to eliminate hard aliasing.

  * `spillSuppression` (float): Compensates for green/blue bounce lighting reflecting onto subject skin and hair.

* **Target Execution:** Implemented in FFmpeg via `colorkey` + `despill` filters, or executed via custom Skia GPU shaders evaluating Euclidean distance in YCbCr color space.

#### 4. Picture-in-Picture (PiP) and Responsive Grid Layouts (`overlay/pip_box`)

Places supplementary footage or dynamic screen recordings into rounded, bordered windows over the main sequence.

* **Parameters:**

  * `position` (enum: `"top_left" | "top_right" | "bottom_left" | "bottom_right" | "custom"`).

  * `coordinates` (vec2: $[x, y]$, if `custom`).

  * `width` (int / percentage): Width of the PiP viewport.

  * `cornerRadius` (int): Corner smoothing in pixels.

  * `border` (object: `{ width: 2, color: "#FFFFFF" }`).

  * `shadow` (object: `{ blur: 15, opacity: 0.4, offsetY: 6 }`).

* **Target Execution:** Skia constructs a rounded clipping path (`addRoundRect`), paints the underlying shadow pass with a Gaussian blur kernel, renders the video frame into the clipped region, and draws the bounding vector stroke.

## 6. Headless Runtime & Execution Architecture

The engine is engineered as a standalone, deterministic media execution worker. It can be invoked via CLI, standard input/output pipes, or embedded as a shared C++/Rust/Node.js library. External orchestration engines are decoupled from this architecture.

```
┌────────────────────────────────────────────────────────────────────────┐
│                   Universal IR Rendering Engine Core                   │
│                                                                        │
│   Input: Video IR Payload (JSON / stdin / file descriptor)             │

│   ┌────────────────────────────────────────────────────────────────┐   │
│   │   1. Relational Timeline Compiler (DAG Solver & Validator)     │   │
│   └──────────────────────────────┬─────────────────────────────────┘   │
│                                  │                                     │
│   ┌──────────────────────────────┴─────────────────────────────────┐   │
│   │   2. Modifier Plugin Dispatcher (VFX, SFX, Overlay, Cuts)      │   │
│   └──────────────────────┬─────────────────────────┬───────────────┘   │
│                          │                         │                   │
│        Generates Graphic │                         │ Generates Complex │
```

### High-Performance Data Streaming

1. **Zero-Copy Memory Transfers:** For native deployments (Rust/C++), decoded frame surfaces from Skia are shared directly with the encoder via hardware surface handles (e.g., DMA-BUF on Linux, Metal textures on macOS, NVMM on NVIDIA platforms).

2. **Deterministic CLI Execution:** The runtime executes with pure determinism:

   ```bash
   video-ir-render --input ./payload.json --output ./master.mp4 --concurrency 8
   ```

3. **Decoupled Failure Propagation:** Plugin-level non-fatal failures emit POSIX standard error (`stderr`) telemetry while the primary multiplexer continues generating media, ensuring uninterrupted batch operations.

## 7. Implementation Roadmap

```
[Phase A: Core Compiler] ────────► [Phase B: Editorial & Overlays] ────────► [Phase C: VFX, SFX & Hardening]
- Relational DAG Solver           - J-Cut / L-Cut Desync Engine             - Shader Engine & SkSL Filters
- Asset Metadata Prober           - Blend Modes & Alpha Mattes              - Audio DSP / Convolver Pipeline
- Basic Plugin Registry           - Chroma Keyer Integration                - Zero-Copy GPU Buffer Streaming
```

### Milestone Deliverables

* **Milestone 1: Deterministic DAG Compiler (Weeks 1–2)**

  * Full two-pass graph compiler resolving relational timestamps (`after`, `syncWith`, `matchLengthOf`, `paddingFrames`, `overlapFrames`).

  * Kahn's topological sort with circular dependency protection and strict error traces.

* **Milestone 2: Editorial & Overlay Engine (Weeks 3–4)**

  * Implementation of split edits (J/L-cuts) through decoupled stream time-mapping.

  * Integration of mathematical blend modes, track mattes, and Skia-based PiP viewports with drop shadows.

* **Milestone 3: Advanced VFX & Sound Design (Weeks 5–6)**

  * Hierarchical VFX execution engine resolving sequence-level versus track-level filter chains.

  * Custom SkSL fragment shaders for chromatic aberration, camera shake, and film grain.

  * Audio DSP integration: impulse response convolution reverb, azimuth spatialization, and multitrack dynamic ducking.

* **Milestone 4: Native Pipeline Integration & Profiling (Weeks 7–8)**

  * Zero-IPC frame streaming between Skia rasterization buffers and FFmpeg encoder pipelines.

  * High-load stress testing against complex 4K compositions and dynamic multilingual workloads.

## 8. Architectural Sign-off Recommendation

The **Universal Video IR Rendering Engine** establishes a pure, headless runtime that cleanly isolates media generation from external orchestration layers. By formalizing an extensible **Entity-Component Model**, this architecture ensures that creative editorial patterns—ranging from complex VFX shaders and cinematic sound design to J-cuts and multi-layer composites—can scale infinitely without breaking regression boundaries. 

The engine provides deterministic, high-throughput media synthesis suitable for enterprise-grade autonomous video generation.
