# Phase 30 Implementation Plan: Replace @dnd-kit with @neodrag/react in Studio Timeline Clips & Trimming (Phase 2)

## 1. Problem Statement
The Studio Timeline previously wrapped the track and clip hierarchy in a nested `@dnd-kit` `<DndContext>`. During horizontal clip sliding and trim dragging, `@dnd-kit` triggered high-frequency context reconciliations and synthetic pointer events. In addition, cross-track lane jumping lacked validation for media-type compatibility (e.g. video/image clips could erroneously jump to audio tracks).

## 2. Proposed Architecture
1. **Track & Sequence Compatibility (`trackCompatibility.ts`)**:
   - Establish strict domain rules (`isTrackCompatibleWithSequence`) forbidding audio on non-audio tracks and visual media on audio/timed-text tracks.
2. **`TrimHandle.tsx`**:
   - Migrate to `@neodrag/react` with horizontal axis clamping (`axis: 'x'`).
   - Add `data-trim-handle={handle}` attribute to cleanly isolate trim handle clicks and drags from parent clip events.
3. **`ClipItem.tsx`**:
   - Migrate to `@neodrag/react` with `cancel: '[data-trim-handle]'`.
   - Forward typed drag and trim callbacks directly to the timeline controller.
4. **`DroppableTrackLane.tsx`**:
   - Expose `data-track-lane-id` and `isDropTarget` highlight states.
5. **`Timeline.tsx`**:
   - Remove `<DndContext>` and `@dnd-kit` sensor descriptors.
   - Implement point-in-rect vertical track lane hopping with compatibility checks.
   - Suppress hover HUDs during active drag sessions.

## 3. Verification Plan
- Unit test `trackCompatibility.ts` via `bun test autogenerated-tests/timeline_track_compatibility.test.ts`.
- Run Vite production bundle check: `pnpm --filter @acc/studio exec vite build`.
