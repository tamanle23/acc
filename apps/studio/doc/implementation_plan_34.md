# Implementation Plan - Studio Viewport Pipeline & Architecture Modernization (Iteration 34)

## Problem Statement
`apps/studio/src/components/Preview.tsx` currently contains ~852 lines of code coupling 5 separate concerns:
1. Web Worker lifecycle & OffscreenCanvas transfer.
2. High-frequency playhead tick coalescing & rAF subscription.
3. Texture decoding & ImageBitmap synchronization.
4. Transform gizmo pointer events, bounding box calculations, and magnetic snapping.
5. Canvas HUD telemetry, safe guides, and spacebar panning controls.

In addition, two duplicate `AssetTextureCache.ts` files exist (`src/renderer/` and `src/lib/textures/`), and worker responsibilities between OffscreenCanvas rendering (`preview.worker.ts`) and AI Sidecar preflight (`IRPreviewEngine.worker.ts`) lack standard contracts.

## Proposed Changes
1. **Consolidate Texture Caches**: Standardize on `apps/studio/src/lib/textures/AssetTextureCache.ts` as the single authoritative singleton. Transform `apps/studio/src/renderer/AssetTextureCache.ts` into a lightweight backward-compatible adapter that re-exports and delegates to it (dropping ContentCacheRegistry for now to prevent serialization overhead on high-frequency CanvasImageSource textures).
2. **Abstract Render Strategy (`IPreviewRenderStrategy`)**: Wrap Web Worker OffscreenCanvas vs MainThread fallback behind a unified strategy interface (`WorkerRenderStrategy` and `MainThreadRenderStrategy`) with runtime auto-negotiation and seamless fallback.
3. **Decompose `Preview.tsx` (Colocated in `apps/studio/src/components/preview/`)**:
   - `components/preview/useViewportRenderStrategy.ts`
   - `components/preview/useGizmoTransform.ts`
   - `components/preview/useViewportPanZoom.ts`
   - `components/preview/usePreviewHotkeys.ts`
   - `components/Preview.tsx` (streamlined declarative orchestrator, < 180 lines)
