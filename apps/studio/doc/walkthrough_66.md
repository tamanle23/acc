# Walkthrough 66: Studio RightSidebar Slider Continuous Movement & Precision Control Engine

## Overview
This walkthrough demonstrates the comprehensive diagnosis and resolution of the slider drag issue in `RightSidebar.tsx`.

## Root Cause Deep-Dive
1. **`<Match>` Lifecycle Churn**:
   In `RightSidebar.tsx`, routing used `<Match when={resolved().selectedSeq}>`. Because modifier property dispatch creates an immutable copy of `VideoIRDocument`, `resolved().selectedSeq` returned a new object identity on every update. Solid's `<Match>` treated the condition as changed, destroying and re-mounting `<SequenceInspector>`. This detached the slider's DOM node mid-drag, causing `trackRef.getBoundingClientRect()` to collapse to `{ width: 0, height: 0 }` during subsequent `pointermove` events.
2. **Dynamic Geometry Measurement Sensitivity**:
   Without caching initial track geometry at pointerdown, transient DOM updates could cause `getValueFromPointer` to evaluate against a zero-width rect, freezing slider movement.

## Key Changes
1. **`apps/studio/src/components/RightSidebar.tsx`**:
   - Switched to `<Match when={currentMode() === 'sequence' && Boolean(resolved().selectedSeq)}>` to retain `<SequenceInspector>` persistently across reactive store changes.
2. **`apps/studio/src/components/ui/slider.tsx`**:
   - Implemented `getTrackGeometry` caching at pointerdown (`capturedGeo`), preserving continuous drag calculations without zero-width drops.
   - Replaced buggy Kobalte slider with a high-performance native SolidJS component featuring pointer capture and precision step rounding.
3. **`autogenerated-tests/studio_slider_properties_interaction.test.ts`**:
   - Added tests verifying persistent component mounting, geometry caching, and reactive parameter propagation.
