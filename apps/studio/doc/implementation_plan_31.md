# Implementation Plan - Iteration 37 / Milestone 31: VideoIR Sequence & Track ID Governance, Hierarchical Authoring, and Referential Integrity

## Problem Statement
In VideoIR documents, tracks and sequences previously lacked a formalized separation between unique system identifiers (`id`) and human-editable display labels (`name`). As users reorder tracks or move sequences between tracks, volatile track-bound identifiers (e.g. `seq_v1_1` on track 1) either break relational DAG links (`after`, `syncWith`, `matchLengthOf`, `editorial/av_link`, `transition/crossfade`) or lead to misleading names when moved to track 2. Additionally, `VideoIRSchemaValidator` did not enforce global uniqueness of sequence IDs across all tracks or validate referential integrity against dangling or self-referential relations.

## User Review Required
> [!NOTE]
> All changes are backward compatible with existing valid VideoIR documents while strictly rejecting malformed documents containing duplicate IDs, dangling relational targets, or self-referencing links.

## Proposed Changes
1. **Core Schema & Types (`packages/ir`, `schema/`)**:
   - Add `name?: string;` to `IRSequence` in `packages/ir/src/types/VideoIR.ts` and `schema/video-ir.schema.json`.
   - Add `nextSequenceIndex?: number;` to `IRMeta` in `packages/ir/src/types/VideoIR.ts` and `schema/video-ir.schema.json`.
2. **Schema Validator (`VideoIRSchemaValidator.ts`)**:
   - Enforce global sequence ID uniqueness across all tracks.
   - Enforce type checking for `track.name` and `sequence.name`.
   - Pass 2 referential integrity validation verifying that all relational targets (`after`, `syncWith`, `matchLengthOf`, `linkedSequenceId`, `overlapTarget`, `outgoingSeqId`) exist in the document and do not self-reference.
3. **Universal Authoring Engine (`VideoIRAuthoringEngine.ts` in `packages/ir`)**:
   - Provide deterministic, track-move immune ID generation: `seq_<modality>_<slug>_<globalIndex>`.
   - Monotonic high-water mark counter tracking in `doc.meta.nextSequenceIndex` (with automatic max-scan fallback for legacy documents).
   - Razor split lifecycle: Part 1 keeps original sequence ID, Part 2 receives next monotonic index and `${orig.name || orig.id} (Part 2)`.
   - Duplicate lifecycle: Cloned sequence receives next monotonic index and `${orig.name || orig.id} (Copy)`.
   - Track ID generation: `track_v1`, `track_a1`, `track_tt1`, `track_d1`.
4. **Studio Commands Synchronization (`apps/studio/src/lib/commands/`)**:
   - Update `SplitSequenceCommand`, `DuplicateSequenceCommand`, `AddSequenceCommand`, and `AddLinkedAVSequenceCommand` to use `VideoIRAuthoringEngine`.
