# Walkthrough 75: Eliminate Playground Memory Spike with SD Quality Canvas and Complete Shiki Removal

## Overview
Permanently eliminated the $> 500\text{ MB}$ transient heap spike on `IrPluginPlaygroundModal` open by:
1. Locking the playground physical canvas backing store to **Standard Definition (SD Quality $\le 640\times 360$)**, cutting backing store buffer memory from $> 11\text{ MB}$ to $< 921\text{ KB}$ and preventing escalation into `CanvasScratchPool`'s 4K tier ($33.2\text{ MB}$).
2. Downsampling post-processing bloom extraction to a fixed low-res scratch buffer ($160\times 90 = 57.6\text{ KB}$), completely cutting the $1.32\text{ GB/sec}$ uncompressed `getImageData` allocation firehose.
3. Replacing the synchronous 5-keyframe filmstrip rendering burst on mount with a sequential 1-keyframe-per-RAF scheduler.
4. Completely removing `shiki` from the project and replacing it with an ultra-lightweight, zero-dependency, synchronous regex-based JSON syntax tokenizer and code viewer (`JsonCodeViewer`).
