# Walkthrough: Demo Schema Fixes & Multi-Domain Generator Showcases

## Overview
This walkthrough details the resolution of false-positive and actual standalone generator schema errors across the Studio demo catalog, as well as the addition of three new production-grade demo projects covering kinetic typography, cinema post-production mastering, and spatial procedural audio.

---

## 1. Schema Validator Remediation

### Root Cause Analysis
During modifier validation on sequence scopes, `VideoIRSchemaValidator.ts` previously calculated `hasStandaloneGenerator` globally across all modifiers attached to the sequence:
```ts
hasStandaloneGenerator = standaloneGenerators.length > 0;
```
When iterating through the sequence's modifiers to evaluate `isModifierAllowedOnEntity`, `hasStandaloneGenerator` was passed as `true` even when evaluating the sequence's own primary standalone generator against itself. This triggered a false-positive rejection:
`Sequence already contains a standalone generator. A sequence cannot host multiple standalone generators.`

### Fix Implementation
In `VideoIRSchemaValidator.ts`:
- The validator now isolates the **other** modifier types attached to the sequence, excluding the modifier currently under evaluation:
  ```ts
  const otherModifierTypes = modifierTypes.filter((_, idx) => idx !== i);
  const hasOtherStandalone = otherModifierTypes.some(
    (t) => registry.get(t)?.targetScope === 'standalone'
  );
  ```
- If the modifier under check is the only standalone generator on the sequence, `hasOtherStandalone` evaluates to `false`, correctly allowing the generator to exist.
- If another standalone generator exists on the sequence, `hasOtherStandalone` evaluates to `true`, correctly blocking the secondary standalone generator.
- Universal modifiers (`transform`, `motion/gsap`, `overlay/blend_mode`, `transition/*`) continue to be cleanly whitelisted.
