# Studio Implementation Plan 68 - Single-Click Timeline Replay & Boundary Wrap

## User Issue
After clicking play for the first time and playing through until finished, clicking the play button to replay required **two clicks** instead of replaying immediately on the first click.

## Root Causes
1. **Auto-Stop Boundary Condition**: When playback finished at `endFrame` (`cur >= maxBound`), the shuttle engine parked at the final frame and called `options.onScrub(endFrame)`.
2. **Circular `onScrub` Callback during Replay**: On Click 1, `togglePlay()` called `setSpeed(1)`. When `setSpeed` checked `cur >= maxBound`, it called `options.onScrub(0)`. In `App.tsx`, `handleScrub` treats all `onScrub` calls as user manual scrubs, emitting scrub audio feedback and potentially halting playback if `isPlaying` was detected.
3. **Clock Stale Initial Frame Abort**: In the clock advancement effect, reading `getCurrentFrame` occurred before seek propagation settled, causing `DeterministicTimelineClock` to initialize at `endFrame`. On the first tick (16ms later), the clock detected `targetFrame >= endFrame` and immediately halted playback (`setSpeed(0)`), causing Click 1 to abort and requiring Click 2 to actually play.

## Technical Solutions
1. **Synchronous Boundary Wrap in `useShuttleEngine.ts`**:
   - In `setSpeed`: When `newSpeed > 0 && cur >= maxBound`, synchronously seek `PlayheadController.getInstance().seek(0, true)` and set `cur = 0`.
   - Remove circular `options.onScrub(0)` and `options.onScrub(snapped)` from internal shuttle methods.
2. **Defense-in-Depth Clock Initialization**:
   - In `createEffect`, compute `startFrame = currentSpeed > 0 && initialFrame >= maxBound ? 0 : initialFrame;`.
   - Pass `startFrame` directly to `clock.play(startFrame, currentSpeed)`.
3. **Clean Auto-Stop at Boundary**:
   - In `tick()`, when `targetFrame >= endFrame && currentSpeed > 0`, seek to `discreteFrame` and call `setSpeed(0)` without invoking `options.onScrub(discreteFrame)`.
