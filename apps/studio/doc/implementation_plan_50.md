## 1. Executive Summary & Problem Formulation

As the VideoIR authoring ecosystem scales to support both human manual editing and autonomous AI video generation, timeline track sprawl introduces severe GPU out-of-memory (OOM) failures, WebGL context loss, and canvas compositing lag:
1. **Unbounded Track Bloat**: Without constraints, AI story generators or unguided operations can spawn dozens of tracks, crippling viewport performance.
2. **Lack of Semantic Role Differentiation**: Physical track types (`'video'`, `'audio'`, `'timed_text'`, `'data'`) do not distinguish functional roles: `main` (spine), `overlay` (PIP, effects, visualizer), `audio` (voiceover, BGM, SFX), `text` (subtitles/captions), `effects` (adjustment tracks), and `stickers`.
3. **Dual-Mode Governance**: Manual Studio users require ambient Liquid Glass soft-cap badges and an explicit `[Add Track Anyway]` manual override modal for hard caps, whereas autonomous AI generation agents strictly respect hard caps and fall back to temporal whitespace reuse.

## 2. Implementation Roadmap

### Phase 1: Authoring Policy & Engine Implementation (`packages/ir`)
- Implement `SemanticTrackRole`, `TrackQuotaLimit`, `TrackAuthoringPolicy`, `DEFAULT_TRACK_AUTHORING_POLICY`, and `TrackQuotaStatus` in `packages/ir/src/authoring/VideoIRAuthoringEngine.ts`.
- Implement `classifyTrackRole(track: IRTrack): SemanticTrackRole` adhering to dynamic role heuristic (handling track index, ID prefixes, name heuristics, and track modifiers).
- Implement `evaluateTrackQuotas(doc: VideoIRDocument, policy?: TrackAuthoringPolicy): Record<SemanticTrackRole, TrackQuotaStatus>`.
- Implement `canAddTrack(doc: VideoIRDocument, roleOrType: SemanticTrackRole | TrackType, policy?: TrackAuthoringPolicy, isManualOverride?: boolean): { allowed: boolean; isWarning: boolean; role: SemanticTrackRole; currentCount: number; softCap: number; hardCap: number; reason?: string }`.
- Enhance `generateNextTrackId(doc: VideoIRDocument, type: TrackType, role?: SemanticTrackRole): string` with role-specific prefixes (e.g. `track_v_overlay_`, `track_v_main_`, `track_a_`, `track_tt_`).
- Export new types and functions from `packages/ir/src/index.ts`.

### Phase 2: Authoring Engine Formal Unit Tests (`autogenerated-tests/`)
- Create `autogenerated-tests/track_soft_cap_policy.test.ts`:
  - Default semantic classification for all 6 roles.
  - Soft cap warnings (e.g., overlay $\ge 6$).
  - Hard cap rejection for non-override additions (e.g., overlay $\ge 10$).
  - Hard cap override allowance when `isManualOverride: true`.
  - Custom policy ingestion with arbitrary caps.
  - Role-specific track ID generation.

### Phase 3: Studio UI Integration (`apps/studio`)
- Create `AddTrackCommand.ts` in `apps/studio/src/lib/commands/` supporting undo/redo.
- Wire `canAddTrack` and `AddTrackCommand` into `IRStateManager.addTrack()`.
- Add explicit "Add Track" interaction in timeline (Toolbar / EmptyState / Track header lane).
- Implement Liquid Glass soft-cap badges in `TrackHeaderCard.tsx` when quota limits are approached.
- Implement `TrackQuotaModal.tsx` for hard-cap override confirmation (`[Add Track Anyway]`).

### Phase 4: AI Generation & CLI Guardrails (`apps/cli`)
- Add track quota telemetry to `apps/cli/src/studio/StudioTimelineState.ts`.
- Update `apps/cli/src/pipelines/04-generative-story/` to query `canAddTrack()` prior to allocating tracks.
- Implement whitespace reuse fallback when track addition is rejected.

### Phase 5: Full Build & Verification
- Run `pnpm --filter @acc/ir check-types` and `pnpm --filter @acc/studio check-types`.
- Execute test suites and verify production builds.
