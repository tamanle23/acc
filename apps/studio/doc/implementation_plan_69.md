# Studio Implementation Plan - Iteration 69: Single-Click Replay Audio Clock Anchor

## Problem
Clicking Play after playback completed at the timeline boundary (`frame 399`) required clicking twice. In SolidJS, calling `setSpeedState(1)` triggered the reactive effect before `WebAudioEngine.setShuttleSpeed` could start audio playback, causing `DeterministicTimelineClock` to anchor onto stale audio hardware timestamps from the previous session.

## Implementation Steps
1. In `useShuttleEngine.ts`: Call `WebAudioEngine.setShuttleSpeed` before `setSpeedState(newSpeed)` so `playbackStartAudioTime` is fresh when the reactive clock mounts.
2. In `WebAudioEngine.ts`: Synchronously reset `playbackStartAudioTime = 0` on `stopPlayback()`.
3. In `DeterministicTimelineClock.ts`: Add guard in `tick()` to re-anchor `audioStartSec` if `audioElapsed > 0.5s` on `playbackStartFrame`.
