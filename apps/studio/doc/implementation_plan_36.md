# Implementation Plan 36: Unified Isomorphic Resource & Asset Management with Blob & Streaming First-Class Support

## 1. Context & Motivation
During initial launch and timeline playback, `@apps/studio` consumed excessive memory:
- **~1GB on initial load**: Caused by `WebAudioEngine.syncFromIR()` preloading and decoding every audio preset in `assets` into uncompressed 32-bit float PCM buffers held indefinitely in `AudioAssetCache`.
- **>2.5GB during timeline preview playback**: Caused by `WorkerRenderStrategy.syncTextures()` invoking `createImageBitmap(visualAsset.source)` unconditionally on every single frame tick at 60Hz. Each 1080p frame (~8.3MB) was posted to `preview.worker.ts`, where incoming textures replaced existing ones in `textureCache` without invoking `bitmap.close()`, causing rapid native GPU memory leaks.
- **In-Memory Byte Array Thrashing**: Reading entire files into `Uint8Array` arrays across web, worker, and Node/Bun processes instead of using zero-copy streaming and native `Blob` handles.

## 2. Proposed Architecture & Interventions

### Phase 1: Core Isomorphic Cache Architecture (`@acc/core-isomorphic`)
- Extend `IContentCacheStrategy` with optional first-class methods:
  - `getBlob(key: string): Promise<Blob | null>`
  - `setBlob(key: string, blob: Blob, metadata?: Partial<CacheEntryMetadata>): Promise<void>`
  - `getStream(key: string): Promise<ReadableStream<Uint8Array> | null>`
  - `setStream(key: string, stream: ReadableStream<Uint8Array>, metadata?: Partial<CacheEntryMetadata>): Promise<void>`
  - `getMetadata(key: string): Promise<CacheEntryMetadata | null>`
- Add `streamUtils.ts` providing isomorphic conversion utilities (`uint8ArrayToStream`, `streamToUint8Array`, `blobToStream`, `streamToBlob`, `blobToUint8Array`, `computeStreamChecksumAndSize`).
- Add LRU byte ceiling (`maxSizeBytes`, default 64MB) and Blob/Stream handlers to `MemoryCacheStrategy`.
- Extend `IAssetBlob` and `AssetProtocolRegistry` to provide zero-copy `blob(): Promise<Blob>` accessors and `BlobAssetBlob` / `CachedAssetBlob`.

### Phase 2: Web & Native Strategies (`@acc/core-web`, `@acc/core`)
- Update `WebCacheStrategy` to use `response.body` (zero-copy ReadableStream), `response.blob()`, and store native `Response(blob)`.
- Update `IndexedDbCacheStrategy` to store native `Blob`s directly in IndexedDB object stores.
- Update `NativeFileCacheStrategy` to support chunked Node/Bun filesystem streams (`createReadStream` / `createWriteStream`) and Web `Blob` wrappers.

### Phase 3: Studio Memory Leaks & Texture Pipeline Optimization (`@acc/studio`)
- **WorkerRenderStrategy**: Add `syncedSources` map to deduplicate `createImageBitmap` calls, only regenerating when source element changes.
- **preview.worker.ts**: Implement `safeSetTexture()` with LRU eviction (cap at 32 bitmaps) and mandatory `existing.close()` before replacing textures.
- **AudioAssetCache & WebAudioEngine**: Bound PCM cache with LRU eviction (`MAX_CACHE_ENTRIES = 8`, `MAX_TOTAL_PCM_BYTES = 64MB`), only preloading clips within 10s of the playhead.
- **AssetTextureCache**: Add LRU bounds on `imageCache` (32), `videoCache` (6), `canvasCache` (32), `dataUrlCache` (32), `placeholderCache` (16), with proper video element pause/clean.
- **LeftSidebar**: Connect file uploads directly to `ContentCacheRegistry.get().setBlob(assetId, file)`.
