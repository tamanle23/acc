# Implementation Plan - Iteration 41: Unified Compositor Frame-Level RAII Parity & Headless Scoped Resource Engine

Companion local plan for Studio and IR rendering pipelines, establishing 100% FrameResourceScope parity between `IRPreviewEngine` (interactive Studio viewport) and `IRMasterRenderer` (headless deterministic exporter).

---

## 1. Problem Statement & Root Cause
1. `IRCanvasCompositor.ts` relied on a static scratch canvas singleton (`scratchCanvasInstance`), bypassing `NativeResourceManager`'s hard memory budget and causing potential cross-worker state bleed during concurrent chunk exports (`IRChunkWorkerPool`).
2. `IRMasterRenderer.ts` lacked sliding sequence boundary eviction, holding baked sequence textures in memory until the entire headless export terminated.
3. `IRPreviewEngine.ts` and `IRMasterRenderer.ts` did not pass a transient `FrameResourceScope` into `IRCanvasCompositor.renderFrame()`.

---

## 2. Architectural Solution
1. **Isolated & Dynamic `NativeResourceManager`**:
   - Add `NativeResourceManager.createIsolated(maxGpuBytes)` for multi-worker chunk isolation.
   - Support resolution-aware memory ceilings (64MB for <=1080p, 256MB for 4K+) and explicit `HeadlessRenderOptions.maxMemoryMb`.
2. **Unified `FrameResourceScope` in `IRCanvasCompositor`**:
   - Pass `frameScope?: FrameResourceScope` through `CanvasCompositorOptions`.
   - Both `IRPreviewEngine.renderFrame()` and `IRMasterRenderer.renderCanvasFrame()` acquire and dispose `FrameResourceScope` around each frame pass.
3. **Sliding Hybrid Lookahead Sequence Eviction**:
   - `IRMasterRenderer` computes `assetFutureUsage` lifespans and immediately evicts `SequenceResourceScope` textures at sequence out-points unless a downstream sequence reuses the same asset.
