# Walkthrough: Multi-Tier Modifier Hierarchy & Standalone Generator Invariants

## Overview
This walkthrough demonstrates the implementation of the **Declarative Self-Describing Plugin Manifest**, the **Standalone Generator Single-Source Invariant**, and the **Universal Transform Whitelisting** across `@acc/ir` and `@acc/studio`.

---

## Key Changes & Architectural Principles

### 1. Declarative Self-Describing Plugin Manifest (SSOT)
Each modifier plugin declares its operational capabilities directly within its class definition:
- `isUniversal?: boolean`: Indicates whether the modifier can be applied to any visual sequence, including procedural standalone generators. Examples: `transform`, `motion/gsap`, `overlay/blend_mode`, `transition/*`.
- `supportedTrackTypes?: readonly TrackType[]`: Specifies valid track types (e.g., `['video', 'timed_text']`).
- `instancePolicy?: 'single' | 'multiple'`: Restricts whether more than one instance of this modifier type may exist on the same entity.

The `ModifierPluginRegistry` aggregates these declarations dynamically via `getCapabilityMatrix()`, eliminating fragile hardcoded matrices across multiple files.

### 2. Standalone Generator Single-Source Invariant
When a sequence hosts a standalone source generator (`targetScope === 'standalone'`, such as `generator/radial_burst` or procedural visualizers):
- Only one standalone generator modifier is permitted per sequence.
- Attaching footage-bound VFX modifiers (such as `vfx/depth3d`, `vfx/camera_3d`, `vfx/color_grading`, `vfx/partial`) is strictly prohibited, as standalone sequences do not decode video frames or provide raster depth maps.
- **Universal Modifiers Whitelist**: Standalone sequences accept universal spatial and compositing modifiers (`transform`, `motion/gsap`, `overlay/blend_mode`, `transition/*`).

### 3. Canvas Compositor Transformation Matrix Order
In `IRCanvasCompositor`, clip-space modifiers are sorted to ensure that spatial `transform` and `motion/gsap` apply to the canvas context matrix **before** procedural generators or base media assets are drawn. This ensures proper translation, scale, and rotation for standalone procedural clips.

### 4. Studio UI & Inspector Integration
- **`RightSidebar.tsx`**: Evaluates whether `hasStandaloneGenerator` is true and collects `existingModifierTypes`. Filters the "Add Effect / Modifier" dropdown so that only permitted modifiers appear.
- **`SequenceInspector.tsx`**: Renders an ambient Liquid Glass badge `"Standalone Generator"` for clips hosting standalone source generators.
- **`irState.ts`**: Sanitizes legacy projects via `migrateLegacyModifiers` to defensively deduplicate standalone generators.

## Verification & Test Vectors

### Formal Automated Tests
Two test suites in `autogenerated-tests/` verify these guarantees:

1. `autogenerated-tests/modifier_plugin_contract_audit.test.ts`:
   - Validates that every registered modifier plugin complies with contract properties.
   - Verifies target scope integrity and universal flag assignments.
   - Verifies that `ModifierPluginRegistry.getCapabilityMatrix()` correctly compiles matrix entries without runtime errors.

2. `autogenerated-tests/standalone_generator_hierarchy_and_whitelist.test.ts`:
   - Confirms that `VideoIRSchemaValidator` rejects sequences with multiple standalone generators.
   - Confirms rejection of footage VFX (`vfx/depth3d`, `vfx/partial`) on standalone sequences.
   - Validates acceptance of universal modifiers (`transform`, `motion/gsap`, `overlay/blend_mode`) on standalone sequences.
   - Verifies `ModifierPluginRegistry.isModifierAllowedOnEntity` behavior under varying entity contexts.
   - Verifies defensive migration in `irState.ts`.
