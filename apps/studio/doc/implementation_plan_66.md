# Implementation Plan 66: Studio RightSidebar Slider Continuous Movement & Precision Control Engine

## 1. Problem Statement
Sliders in `apps/studio/src/components/RightSidebar.tsx` and its child inspectors (`DynamicModifierInspector.tsx`, `SequenceInspector.tsx`, `TrackInspector.tsx`, `ParameterControls.tsx`) were not moving when interacted with by clicking or dragging.

## 2. Root Cause
`@kobalte/core/slider`'s `SliderPrimitive.Root` suffers from an upstream synchronous memo evaluation bug. In its `onSlideMove` handler, Kobalte invokes `state.setThumbPercent` (which calls `props.onChange(nextValues)`), and immediately follows on the next synchronous line with `local.onChange?.(state.values())`. Because `state.values()` is backed by an internal `createMemo` tracking `props.value`, and SolidJS signal updates do not recompute memos synchronously in the middle of a running event listener call stack, `state.values()` returns the stale pre-drag value. Kobalte's duplicate call immediately reverts the property, snapping the slider back to its starting value and preventing visual movement.

## 3. Solution Architecture
1. Replaced `@kobalte/core/slider` with a high-performance, native SolidJS `Slider` component in `apps/studio/src/components/ui/slider.tsx`.
2. Implemented dual-layer pointer tracking via `setPointerCapture` and fallback window event listeners.
3. Implemented optimistic `dragValue` visual state to ensure thumb tracks the cursor instantaneously at 60/120fps.
4. Implemented precision step arithmetic (`clampAndStep`) eliminating floating-point rounding errors.
5. Added keyboard navigation (`ArrowRight`, `ArrowLeft`, `PageUp`, `PageDown`, `Home`, `End`) and ARIA slider semantics.
6. Updated `PrimitiveControlStrategies.tsx` and `ParameterControls.tsx` to provide `defaultValue` and direct `value` scalar access.
