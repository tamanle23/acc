# Implementation Plan - Iteration 61 (Backend Companion 54)
# Enhanced Unified PostgreSQL Architecture for Workflow Engine: Reactive Event-Driven Queue & Storage Consolidation

## 1. Overview & Motivation
This companion plan mirrors **Master Implementation Plan Iteration 61** (`docs/iterations/master_implementation_plan_iteration_61.md`) for `@acc/api`.

During `pnpm dev:sandbox`, `WorkflowEngineConfiguration` detects PostgreSQL metadata and binds `PostgresJdbcPersistenceAdapter`. Because the workflow schema (`schema-postgres.sql`) was never integrated into the `acc-db` Liquibase migration pipeline, `SystemTaskWorkerPool` repeatedly failed with:
```
DEBUG: Error polling domain system:http: Failed to poll tasks from PostgreSQL: relation "task_queue" does not exist
```

This implementation delivers the **"Best of Both Worlds" Enhanced Unified PostgreSQL Architecture**:
- **Zero-Lag Event-Driven Execution**: Replaces 200ms busy-polling with PostgreSQL `LISTEN/NOTIFY` push notifications (`unipost_task_queue`) and `FOR UPDATE SKIP LOCKED` batch drain (< 1ms pickup latency, 0 idle queries/sec).
- **Dedicated Unpooled Listener Connection**: Uses a raw unpooled `DriverManager` connection (`autocommit=true`) on a virtual thread for `LISTEN unipost_task_queue`, preventing HikariCP pool starvation and leak detection warnings.
- **Notification Storm Coalescing**: Uses `AtomicBoolean drainScheduled` compare-and-swap in `SystemTaskWorkerPool` to drain tasks until exhaustion, debouncing concurrent enqueue bursts.
- **Dedicated Workflow Connection Pool**: Provisions a bounded Hikari mini-pool (`HikariPool-WorkflowEngine`: min 2, max 4 connections) isolating short-lived worker batch claims from web traffic.
- **Formal Liquibase Governance & Autovacuum Tuning**: Provisions `changelog-000.000.00019.xml` in `acc-db` with tuned autovacuum storage parameters (`autovacuum_vacuum_scale_factor = 0.05`) on `task_queue` and registers it in both `acc-db` and `acc-sandbox` master changelogs.

## 2. Phased Implementation Roadmap (1:1 Parity with Master Iteration 61)

### Phase 1: Core Liquibase Migration Integration
- **1.1**: Create `apps/api/acc-db/src/main/resources/db/acc/changelog-000.000.00019.xml` declaring `workflow_executions`, `task_executions`, `task_queue`, `task_dlq`, `workflow_definitions`, `workflow_audit_log`, `idx_task_queue_poll`, autovacuum tuning, and `trg_unipost_task_queued` notification trigger.
- **1.2**: Register `changelog-000.000.00019.xml` in `apps/api/acc-db/src/main/resources/db/acc/changelog-master.xml`.
- **1.3**: Register `changelog-000.000.00019.xml` in `apps/api/acc-sandbox/src/main/resources/db/sandbox/changelog-master.xml`.

### Phase 2: Resilience & Defensive Self-Healing
- **2.1**: Update `PostgresJdbcPersistenceAdapter.java` with `initializeSchemaIfMissing()` and update `schema-postgres.sql` with the reactive trigger and autovacuum settings.
- **2.2**: Update `WorkflowEngineConfiguration.java` to wire `PostgresJdbcPersistenceAdapter` cleanly when PostgreSQL is detected.

### Phase 3: Dedicated Connection Pool & Reactive Listener
- **3.1**: Configure `workflowDataSource` (Hikari mini-pool: min 2, max 4 connections) in `WorkflowEngineConfiguration.java`.
- **3.2**: Implement `PostgresNotificationListener.java` managing an unpooled `DriverManager` socket with `LISTEN unipost_task_queue` and exponential backoff reconnection (1s to 16s).
- **3.3**: Implement `triggerReactiveDrain()` with `AtomicBoolean drainScheduled` storm coalescing in `SystemTaskWorkerPool.java` and relax `@Scheduled(fixedDelay)` from 200ms to 5000ms.

### Phase 4: SQLite Deprecation & Cleanup
- **4.1**: Annotate `SqliteJdbcPersistenceAdapter.java` with `@Deprecated(since = "1.0.0", forRemoval = true)` and document deprecation in `schema-sqlite.sql`.
- **4.2**: Mark `org.xerial:sqlite-jdbc` optional/deprecated in `apps/api/workflow-engine/pom.xml`.
