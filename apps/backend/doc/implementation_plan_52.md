# Backend Implementation Plan - Iteration 52: Multi-Tenancy IDOR Elimination & Workflow RBAC Hardening

## 1. Problem & Context
1. In `apps/backend/acc-ms-aio/src/main/java/com/acc/aio/controller/workflow/`, `WorkflowDefinitionController.java`, `WorkflowExecutionController.java`, and related workflow controllers declare `@RequestHeader(value = "X-Tenant-Id", required = false) String headerTenantId` and invoke local fallback `resolveTenantId(headerTenantId)`.
2. This creates an Insecure Direct Object Reference (IDOR) vector and contradicts `HeaderSanitizerFilter` which explicitly strips client-supplied tenant headers.
3. Multiple workflow controller endpoints lack `@PreAuthorize` method annotations, violating the Principle of Least Privilege and creating an inconsistent authorization surface compared to `TenantBillingController` and `MetadataController`.

## 2. Proposed Architectural Changes
- **Tenant Context Sanitization**:
  - Remove all `@RequestHeader(value = "X-Tenant-Id", ...)` parameters from workflow controllers.
  - Delete local `resolveTenantId(String headerTenantId)` methods.
  - Strictly invoke `TenantContextHolder.getRequiredTenantId()` across all controller handler methods.
- **Granular RBAC Enforcements**:
  - Annotate workflow definition and execution read endpoints with `@PreAuthorize("hasAuthority('WORKFLOW_READ') or hasRole('ADMIN')")`.
  - Annotate execution mutations (start, pause, resume, cancel, retry, migrate) with `@PreAuthorize("hasAuthority('WORKFLOW_WRITE') or hasRole('ADMIN')")`.
  - Annotate worker fleet and task worker controllers with `@PreAuthorize("hasAuthority('ROLE_SYSTEM_CUSTODIAN') or hasAuthority('platform:worker:manage')")`.
- **Formal Verification**:
  - Create `autogenerated-tests/backend_tenancy_security_rbac.test.ts` verifying AST removal of `X-Tenant-Id` parameters and 100% `@PreAuthorize` presence.
