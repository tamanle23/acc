# Walkthrough 51 - Zero-Stub Cryptographic Security, Route Unification to `/api/v1/...` & Persistence Hardening

## Overview
This walkthrough summarizes the cryptographic hardening, zero-stub enforcement, VAT invoice persistence integration, and strict `/api/v1/...` route unification executed across `@acc/backend` and synchronized with `@acc/console` in Phase 1 of Iteration 50.

## Changes Completed

### 1. Backend Security & Cryptographic Realism (`acc-fw`)
- **`PayOsBillingService.java`**:
  - **Eliminated Backdoor Bypass Tokens**: Removed `"mock_signature_ok"` and `payload.getSignature().startsWith("test_valid_sig")` checks from `verifySignature()`.
  - **Constant-Time Verification**: Replaced insecure string comparisons with `java.security.MessageDigest.isEqual()` on calculated HMAC-SHA256 hex bytes to protect against timing attacks.
  - **VAT Invoice Persistence in JSONB**: Refactored `updateVatInvoice` and `getVatInvoice` to persist VAT preferences directly into `TenantBilling.billingMetadata` JSONB (`key: "vat_invoice"`), removing the in-memory `ConcurrentHashMap`. Unconfigured tenants now return `null` honestly rather than a synthetic corporate default.
  - **Empty History Honesty**: Removed synthetic mock transaction injection (`orderCode: 1712800000000L`) in `buildBillingHistory`; returns `[]` when no database records exist.
  - **Quota Exceptions Sanitization**: Replaced hardcoded catch numbers (`schemasUsed = 3`, `recordsUsed = 1250L`) in `buildQuotaUsage` with logging warnings and clean `0L` defaults.

### 2. Spring Modulith Workflow Controllers Route Unification (`acc-ms-aio`)
- **Unified Canonical `/api/v1/...` Namespace**:
  - `WorkflowExecutionController.java`: Mapped strictly to `@RequestMapping("/api/v1/workflow/executions")`.
  - `WorkflowDefinitionController.java`: Retained canonical `@RequestMapping("/api/v1/workflow/definitions")`.
  - `WorkflowApprovalsController.java`: Unified to `@RequestMapping("/api/v1/workflow/approvals")`.
  - `WorkerFleetController.java`: Retained canonical `@RequestMapping("/api/v1/workflow/workers")`.
  - `TaskWorkerController.java`: Retained canonical `@RequestMapping("/api/v1/workflow/tasks")`.
  - `WorkflowDlqController.java`: Mapped to `@RequestMapping({"/api/v1/workflow/dlq", "/api/v1/system/dlq"})`.

### 3. Console API Alignment (`apps/console`)
- **`use-workflow-executions.ts`**:
  - Harmonized query and all mutations (`create`, `update`, `delete`, `bulkDelete`, `bulkStatus`, `bulkPriority`) to call canonical `/v1/workflow/executions`. When combined with `springApiClient`'s `baseURL: '/api'`, all requests cleanly target `/api/v1/workflow/executions`.

### 4. Tests & Formal Verification Suites
- **`PayOsBillingAndEntitlementsTest.java`**:
  - Added authentic `computeHmacSha256` cryptographic calculation to supply valid signatures in test suites.
  - Added `testBypassSignaturesStrictlyRejected_ZeroStubEnforcement` asserting that `"mock_signature_ok"`, prefix wildcards, and forged hashes are rejected.
  - Verified VAT invoice persistence in `billingMetadata` and empty billing history honesty.
- **Formal Verification Suites**:
  - `autogenerated-tests/backend_security_hmac_and_stubs.test.ts`: Verifies bit-identical HMAC-SHA256, parameter sorting, timing attack defense, and empty history invariants.
  - `autogenerated-tests/backend_workflow_routes_unification.test.ts`: Verifies canonical `/api/v1/...` route namespaces and client URL resolution.
