# Console Implementation Plan - Iteration 161: Unified Sandbox Harmonization, Dead Code Elimination & Shared Primitive Consolidation

## 1. Problem & Context
1. In `apps/console/src/features/metadata`, `mock-metadata.ts` (2,148 lines) and `MetadataServiceStrategy` in `metadata-service.ts` run a private ad-hoc mock store bypassing the Unified Sandbox Platform (`packages/sandbox`), violating `.agents/rules/02-unified-sandbox.md`.
2. In `apps/console/src/features/users`, `RegisterUserForm.tsx` and `useRegisterUserFacade.ts` are orphaned artifacts calling an unauthenticated, non-existent `/api/v2/users/register` via raw `fetch()`. They violate `NO-ORPHANED-CODE` and file naming conventions.
3. In `apps/console/src/features/metadata/api/http-metadata-service.ts`, `BASE_URL` is set to `/v1/metadata`. When used with `springApiClient` (`baseURL: '/api'`), it maps to `/api/v1/metadata`, but direct path references should be clarified and normalized.
4. Redundant table pagination and filter toolbars are duplicated between `workflow-executions-table.tsx` and `users-table.tsx` instead of consuming shared `@acc/ui` primitives.

## 2. Agreed Architectural Specifications (Phase 2)
- **Metadata Unified Sandbox Migration**:
  - Relocate mock seed data to `packages/sandbox/src/handlers/data/metadata.ts`.
  - Create `packages/sandbox/src/handlers/metadata-sandbox-handler.ts` implementing `SandboxRouteHandler` with `MetadataSandboxRepository`.
  - Tenant context resolution: Resolve tenant identity from authentication token / authenticated session context rather than trusting client-supplied headers.
  - Wire `metadataSandboxHandler` into `packages/sandbox/src/handlers/index.ts` and register in `sandboxResetRegistry`.
  - Permanently delete `apps/console/src/features/metadata/data/mock-metadata.ts` (pruning 2,148 lines).
  - Simplify `metadata-service.ts` to directly re-export `httpMetadataService` as `metadataService`, relying on `springApiClient`'s sandbox interceptor for offline dev simulation without dual-mode UI code.
- **Formal Verification**:
  - Create `autogenerated-tests/metadata_unified_sandbox_parity.test.ts` testing route matching, token-derived tenancy, schema compilation, entity records CRUD, and stateful resets.

## 3. Agreed Architectural Specifications (Phase 3: Dead Code Elimination & Shared Primitives)
- **Dead Code Elimination**:
  - Permanently delete `apps/console/src/features/users/components/RegisterUserForm.tsx` and `apps/console/src/features/users/api/useRegisterUserFacade.ts`.
  - Ensure zero residual references to `/api/v2/users/register`. Real user operations remain strictly handled by `users-action-dialog.tsx` and `use-users.ts`.
- **Shared Primitive Consolidation & Disambiguation**:
  - Disambiguate local `DataTableBulkActions` in `features/users`: renamed to `users-bulk-actions.tsx` exporting `UsersBulkActions` and composing `@/components/data-table` primitives.
  - Disambiguate local `DataTableBulkActions` in `features/workflow-executions`: renamed to `workflow-executions-bulk-actions.tsx` exporting `WorkflowExecutionsBulkActions` and composing `@/components/data-table` primitives.
  - Updated all table consumers (`users-table.tsx` and `workflow-executions-table.tsx`).
- **Formal Verification**:
  - Create `autogenerated-tests/console_dead_code_and_primitives.test.ts` verifying dead code absence, clean export signatures, shared data table primitive consumption, and WCAG accessibility standards.
