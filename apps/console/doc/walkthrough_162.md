# Walkthrough 162 - Unified Sandbox Domain Handler Consolidation & Zero-Trust Token Derivation

## Overview
This walkthrough covers Phase 1 of Iteration 52: consolidating duplicate domain handlers from `apps/console` into `packages/sandbox`, enforcing token-derived tenant resolution across all endpoints, and returning strict 401 Unauthorized errors on missing or invalid Bearer JWT tokens.

## Changes Completed

### 1. Unified Tenant Authentication Helper (`packages/sandbox`)
- Created `packages/sandbox/src/tenant-auth.ts`:
  - `extractTenantFromAuth(req)` derives tenant identity strictly from `decodeJwt(token)?.tenantId`.
  - Enforces Zero Client Trust by ignoring client `x-tenant-id` headers.
  - Returns `{ status: 401, data: { error: 'Unauthorized', message: '...' } }` when credentials are absent or invalid.
- Re-exported in `packages/sandbox/src/index.ts`.

### 2. Sandbox Handlers Hardening (`packages/sandbox`)
- Updated `users-sandbox-handler.ts`, `billing-sandbox-handler.ts`, and `workspace-sandbox-handler.ts` to enforce `extractTenantFromAuth(req)`.
- Replaced direct store reads and client header lookups with the extracted `tenantId`.

### 3. Thin Re-Export Adapters in Console (`apps/console`)
- Converted the following handlers to thin re-export adapters pointing to `@acc/sandbox`:
  - `apps/console/src/core/sandbox/handlers/billing-sandbox-handler.ts`
  - `apps/console/src/core/sandbox/handlers/users-sandbox-handler.ts`
  - `apps/console/src/core/sandbox/handlers/workspace-sandbox-handler.ts`
  - `apps/console/src/core/sandbox/handlers/auth-sandbox-handler.ts`
  - `apps/console/src/core/sandbox/handlers/apps-sandbox-handler.ts`
  - `apps/console/src/core/sandbox/handlers/chats-sandbox-handler.ts`
  - `apps/console/src/core/sandbox/handlers/system-sandbox-handler.ts`
- Pruned thousands of lines of duplicated mock logic from `apps/console`.

### 4. Formal Verification
- Created `autogenerated-tests/sandbox_handlers_consolidation.test.ts`:
  - Verified token derivation, 401 Unauthorized enforcement, multi-tenant isolation, and `sandboxResetRegistry` integration.

### 5. Phase 2: Frontend-Backend API Contract & Zero-`any` Synchronization
- **Error Extraction & Typing Helper**:
  - Created `apps/console/src/core/utils/error-extractor.ts` defining `ApiErrorResponse` and `getErrorMessage(err)`.
- **Workflow Executions API (`use-workflow-executions.ts`)**:
  - Replaced untyped `get<any>` with typed `springApiClient.get<WorkflowExecution[]>('/v1/workflow/executions')`.
  - Replaced all 6 untyped `onError: (err: any)` with `AxiosError<ApiErrorResponse> | Error` and safe toast extraction.
- **Workflows Definition API (`workflow-api.ts`)**:
  - Replaced all 6 untyped `onError: (err: any)` with typed error handlers.
- **Billing DTO Single Source of Truth (`use-billing.ts`)**:
  - Replaced local redundant interface declarations with direct imports and re-exports from `@acc/client` (`TenantBillingSummary`, `QuotaUsage`, `VatInvoiceInfo`, `BillingTransaction`, `CreatePaymentLinkPayload`, `CheckoutResponse`).
- **Formal Verification**:
  - Created `autogenerated-tests/console_api_contract_typing.test.ts` verifying zero `any` and contract synchronization.
