# Console Implementation Plan - Iteration 162: Sandbox Handler Consolidation & Zero-`any` API Contract Synchronization

## 1. Problem & Context
1. In `apps/console/src/core/sandbox/handlers/`, domain handlers (`billing-sandbox-handler.ts`, `users-sandbox-handler.ts`, `apps-sandbox-handler.ts`, `workspace-sandbox-handler.ts`, `auth-sandbox-handler.ts`, `chats-sandbox-handler.ts`, `system-sandbox-handler.ts`) duplicate logic already present in `packages/sandbox/src/handlers/`.
2. Several handlers in `apps/console` still read `req.headers['x-tenant-id']` directly instead of deriving tenant identity from JWT Bearer claims.
3. In `apps/console/src/features/workflow-executions/api/use-workflow-executions.ts` and `apps/console/src/features/workflows/api/workflow-api.ts`, API queries and mutation error callbacks rely on `any` (`<any>`, `onError: (err: any)`).
4. Billing DTOs in `apps/console/src/features/metadata/api/use-billing.ts` duplicate types rather than aligning with backend Spring contracts.

## 2. Proposed Architectural Changes
- **Unified Sandbox Consolidation**:
  - Migrate all remaining domain handler logic and state stores into `packages/sandbox/src/handlers/`.
  - Refactor files in `apps/console/src/core/sandbox/handlers/` into thin re-export adapters (matching `metadata-sandbox-adapter.ts`).
  - Standardize tenant scoping in `packages/sandbox` using Bearer JWT claim extraction (`decodeJwt(token)?.tenantId`) with store fallback.
- **Strict TypeScript & Zero `any`**:
  - Replace `springApiClient.get<any>` with typed response interfaces.
  - Replace all `onError: (err: any)` with `AxiosError<ApiErrorPayload>`.
  - Cleanly type all workflow execution filters and mutation payloads.
- **Formal Verification**:
  - Create `autogenerated-tests/sandbox_handlers_consolidation.test.ts`.
  - Create `autogenerated-tests/console_api_contract_typing.test.ts`.
