## 2024-05-18 - Prevent Unnecessary Re-Renders in `useSidebarData`
**Learning:** `useSidebarData` in `apps/console` returned a completely new object containing deeply nested navigation arrays on every single render. Since this hook is called by primary layout components like `AppSidebar` and `CommandMenu`, it caused significant unnecessary re-renders across the main layout tree.
**Action:** When creating custom hooks that return large configuration objects or arrays of UI items, always wrap the return value in `useMemo` (e.g., `useMemo(() => ({ ... }), [deps])`) to maintain referential equality across renders unless the dependencies change.

## 2024-05-24 - Debouncing React Router Table Filters
**Learning:** In the `@unipost/console` frontend, the `DataTableToolbar` was directly pushing every keystroke from its search input into the `useTableUrlState` hook, which in turn calls `navigate` from React Router. This is a significant performance bottleneck because it causes a full route re-evaluation, URL update, and potential data re-fetch on every single keypress. Furthermore, when synchronizing an internal state (`searchValue`) with external state (the URL table filter), using `useEffect` with a simple comparison `tableVal !== debouncedSearchValue` creates infinite loops because the `useEffect` runs *after* render when `tableVal` might still be stale.
**Action:** When connecting text inputs to React Router URL state, always wrap the input with a local state and debounce the synchronization using `useDebounce`. When reconciling external state (like a URL filter) with internal local state, track the *previous* incoming external value to differentiate between an internal change (the user typing) and an external reset (the user clicking a "Reset" button).

## 2026-10-07 - Context Value Object Memoization
**Learning:** In React 19 / Vite applications with context providers (`SearchProvider`, `TasksProvider`, `UsersProvider`), passing unmemoized object literals directly to `<Context value={{ open, setOpen }}>` creates a new object reference on every render, triggering unnecessary re-renders in all subscribed consumer components across the feature component tree.
**Action:** Always memoize context values with `useMemo` in provider components to maintain referential stability.

## 2026-10-11 - Pre-Indexing Array Lookups in Matrix/Grid Component Loops
**Learning:** In matrix/grid table rendering components like `RbacMatrixGrid` that iterate over $N$ items and $M$ columns, performing nested array operations like `roles.find(...)` inside table cells creates an $O(N \cdot M \cdot K)$ overhead on every render pass.
**Action:** Pre-index entity arrays into a Map with `useMemo` (`roleMap = useMemo(() => new Map(items.map(i => [i.id, i])), [items])`) before rendering the table. This reduces nested inner-loop entity lookups from $O(M)$ array scans to $O(1)$ constant time Map accesses.

## 2026-10-16 - Safe Array Sorting and Pre-Indexing in Dialog Render Loops
**Learning:** Calling `array.sort()` directly on state arrays during component render mutates the React state array in place, violating state immutability. Furthermore, repeatedly computing filtered/sorted lists and calling `.find()` inside list item mappings (`assignedProfiles.map(...)`) causes $O(N \cdot M)$ complexity and unnecessary recalculations on unrelated state updates.
**Action:** Always create a shallow copy before sorting (`[...list].sort(...)`), wrap list sorting/filtering in `useMemo`, and pre-index relational lookups into a `Map` using `useMemo` (`assignmentMap = useMemo(() => new Map(...), [assignments])`) to ensure $O(1)$ constant time lookups during list rendering.
## 2026-10-15 - Single-Pass Facet Binning & Pre-Indexed Active Filter Sets
**Learning:** In faceted search sidebars (`FacetedSearchSidebar`), running multiple `.filter()` calls on numerical/date record lists creates redundant array passes and intermediate allocations ($3\times–4\times$ iterations). Furthermore, checking active filters inside nested bucket rendering loops using `.some()` incurs $O(G \cdot B \cdot F)$ complexity on every render pass.
**Action:** Replace multiple `.filter()` passes with a single `for...of` loop pass for numeric/date range binning. Pre-index `activeFilters` into memoized `Set` lookup keys using `useMemo` so that active status checks run in $O(1)$ time instead of linear array scans.
