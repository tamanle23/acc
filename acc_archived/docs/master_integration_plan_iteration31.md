# Master Integration Plan - Iteration 31: Full Architectural Isolation of Legacy Story-Config & Scaffolding of @acc/legacy-story-renderer

## 1. Goal Description & Executive Summary

The objective of **Iteration 31** is to establish full, complete architectural isolation of the legacy `story-config.json` rendering pipeline by extracting it out of `@acc/cli` into a dedicated workspace application package: **`@acc/legacy-story-renderer`** (`apps/legacy-story-renderer`).

Following the modernization of Universal Video IR v3.0.0 (`pipeline-ir.json` / `video-ir.json`), `story-config.json` is a deprecated legacy format. While the internal rendering logic was previously quarantined inside an internal folder (`apps/cli/src/pipelines/04-generative-story/legacy/`), this iteration takes the architectural separation to the physical package level:

1. **Physical Package Quarantine (`apps/legacy-story-renderer`)**:
   - Create a dedicated workspace package `apps/legacy-story-renderer` (`@acc/legacy-story-renderer`).
   - Move all legacy disk-based multi-pass scene renderers, `SceneWorkerPool` orchestration, temporary MP4 chunking, ASS subtitle disk generation, `FFmpegFilterGraph` transition stitching, and legacy AST cut calculation (`prepareIR()`) into this dedicated package.
2. **Purification of `@acc/cli`**:
   - Permanently delete the internal legacy directory `apps/cli/src/pipelines/04-generative-story/legacy/`.
   - Keep `VideoEditPipelineOrchestrator` in `@acc/cli` strictly as a lightweight, clean routing facade that defaults to Canonical Universal Video IR (`StoryConfigToUniversalIRAdapter` -> `RelationalDAGCompiler` -> `IRChunkWorkerPool` / `IRMasterRenderer`), delegating fallback execution to `@acc/legacy-story-renderer`.
3. **Workspace Configuration & Dependency Integrity**:
   - Register `@acc/legacy-story-renderer` in the root `pnpm-workspace.yaml` / `package.json`, root `tsconfig.json` path mappings, and `@acc/cli/package.json` workspace dependencies.
   - Ensure clean Turbo build caching (`turbo run build`) across all workspace packages and apps.
4. **100% Backward Compatibility & Zero-Regression**:
   - Preserve all public entrypoints (`VideoEditPipelineOrchestrator.renderStoryVideo`, `prepareIR`, `StoryRenderer.renderStoryVideo`).
   - Ensure all autogenerated tests in `autogenerated-tests/` pass without modification.

## 3. Detailed Execution Phases

### Phase 1: Workspace Scaffolding & Configuration
- Create `apps/legacy-story-renderer/package.json` with package name `@acc/legacy-story-renderer`, private flag, and workspace dependencies (`@acc/core`, `@acc/core-isomorphic`, `@acc/ir`, `@acc/effect-engines`).
- Create `apps/legacy-story-renderer/tsconfig.json` extending root compiler options.
- Update root `tsconfig.json` path mappings:
  ```json
  "@acc/legacy-story-renderer": ["./apps/legacy-story-renderer/src/index.ts"],
  "@acc/legacy-story-renderer/*": ["./apps/legacy-story-renderer/src/*"]
  ```

### Phase 2: Relocate Legacy Components into `apps/legacy-story-renderer`
- Move `apps/cli/src/pipelines/04-generative-story/legacy/LegacyDiskStoryRenderer.ts` to `apps/legacy-story-renderer/src/LegacyDiskStoryRenderer.ts`.
- Move `apps/cli/src/pipelines/04-generative-story/legacy/LegacyIRPreparationAdapter.ts` to `apps/legacy-story-renderer/src/LegacyIRPreparationAdapter.ts`.
- Create `apps/legacy-story-renderer/src/index.ts` re-exporting:
  - `LegacyDiskStoryRenderer`
  - `LegacyIRPreparationAdapter`
  - `PipelineExecutionOptions`
- Adjust any relative imports (e.g., platforms encoding flags, upscaler plugins) to import from `@acc/cli` or encapsulate self-contained helpers.

### Phase 3: Purify `@acc/cli`
- Add `"@acc/legacy-story-renderer": "workspace:*"` to `apps/cli/package.json`.
- Delete the folder `apps/cli/src/pipelines/04-generative-story/legacy/`.
- In `apps/cli/src/pipelines/04-generative-story/VideoEditPipelineOrchestrator.ts`:
  - Import `LegacyDiskStoryRenderer` and `LegacyIRPreparationAdapter` from `@acc/legacy-story-renderer`.
  - Maintain the clean, lightweight facade pattern (~80 lines).
- In `apps/cli/src/pipelines/04-generative-story/index.ts`:
  - Re-export `VideoEditPipelineOrchestrator` and `PipelineExecutionOptions` without referencing any local legacy folders.

### Phase 4: Full-Stack Verification & Parity Audit
- Verify TypeScript compilation across the entire monorepo (`bun run typecheck` / `npx tsc --noEmit`).
- Run the targeted test suite:
  ```bash
  bun test --test-name-pattern "VideoEditPipelineOrchestrator" autogenerated-tests/systematic_editing_engine.test.ts
  bun test autogenerated-tests/phase0_scaffolding.test.ts
  bun test autogenerated-tests/video_ir_phase1_phase2.test.ts
  bun test autogenerated-tests/video_ir_phase3_plugins.test.ts
  ```
- Run Turbo build verification:
  ```bash
  bun run build
  ```
- Document historical record in `docs/history/331_scaffold_legacy_story_renderer_package.md` and index in `docs/history/README.md`.

## 4. Acceptance Criteria & Invariants
1. **Clean Directory Boundaries**: Zero legacy disk-stitching files inside `apps/cli/src/pipelines/04-generative-story/`.
2. **Physical Package Isolation**: All legacy multi-pass rendering code lives exclusively in `apps/legacy-story-renderer/`.
3. **Zero Breaking Changes**: All existing tests importing `VideoEditPipelineOrchestrator` or `StoryRenderer` pass with 100% parity.
4. **Build Hygiene**: Turbo builds pass without circular dependencies or unresolved imports.
