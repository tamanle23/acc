## 1. Context & Motivation

To transform the Visual Storytelling Generator into a cloud-ready, enterprise-grade media engine (Kubernetes clusters, distributed worker fleets, zero-trust infrastructure), the system required:
1. Standardized distributed tracing correlating Bun tasks, FFI encoder workers, and Python AI sidecars.
2. Standardized telemetry and metrics scraping conforming to Prometheus format.
3. Health check probes (`/healthz/liveness` and `/healthz/readiness`) for automated container orchestration.
4. Active zero-trust security preventing inadvertent exposure of bearer tokens, API keys, or cloud storage secrets in logs.

---

## 2. Key Architecture & Implementation Changes

### 2.1 W3C Distributed Tracing (`TraceContext`)
- **File**: `packages/core/src/telemetry/TraceContext.ts`
- Implements RFC W3C `traceparent` specification (`00-{traceId}-{spanId}-{flags}`).
- Generates 128-bit hex trace IDs and 64-bit span IDs.
- Provides `fromTraceparent` header parsing and `createChildSpan` derivation for cross-service RPC and pipeline contexts.

### 2.2 Prometheus Metrics Registry (`MetricsRegistry`)
- **File**: `packages/core/src/telemetry/MetricsRegistry.ts`
- Real-time management of Gauges, Counters, and Histograms (`acc_render_frames_per_second`, `acc_memory_rss_bytes`, `acc_render_frame_latency_ms`).
- Automatically collects V8/Bun heap usage and OS memory pressure.
- Formats metrics into standard Prometheus text format (`# HELP`, `# TYPE`, bucket quantiles).

### 2.3 Zero-Trust Security & Automated Log Redaction (`DynamicSecretsManager`)
- **File**: `packages/core/src/security/DynamicSecretsManager.ts` & `packages/core/src/logger.ts`
- Dynamically resolves environment variables and registers secrets for automated redaction.
- Pattern matching regexes automatically redact bearer tokens (`Bearer ***REDACTED***`), API keys, and sensitive tokens from all console outputs emitted by `Logger`.

### 2.4 Kubernetes Health Probes & Metrics Endpoints
- **File**: `apps/cli/src/pipelines/01-scraper/ScraperEngine.ts`
- Added HTTP routes to the built-in Bun server:
  - `GET /healthz/liveness`: Returns `200 OK` with system uptime when event loop is healthy.
  - `GET /healthz/readiness`: Queries `AdaptiveResourceGovernor` to verify memory headroom (`200 OK` if ready, `503 Service Unavailable` if memory constrained).
  - `GET /metrics`: Serves real-time Prometheus scrape payload.
