# History Record 333: Fix Legacy Story Renderer 3D Depth Resolution and Concurrency Throttling

## Context & Objectives
When running the quarantined legacy story renderer CLI (`apps/legacy-story-renderer`):
1. **3D Depth / Segmentation / Depth-Map failure**: Cutout and depth-maps were not loading from pre-generated caches or fallback inference, causing 3D scenes (`frame_breaker`, `volumetric_sandwich`, `parallax_25d`) to fall back or fail.
2. **Concurrency throttling (sequential rendering)**: The renderer was clamped to a single worker (`concurrency: 1`), causing multi-scene rendering to be extremely slow.

## Root Causes Identified
1. **Method mismatch in `SubjectSegmentationContext`**:
   - `packages/effect-engines/src/depth3d/index.ts` was calling `segContext.segmentSubject(imgBuffer)` whereas `SubjectSegmentationContext` exposed `segment(imgBuffer)`.
2. **Pre-computed disk cache lookup bypass**:
   - Refactor `42968ff3` replaced checking `depthCacheDir` files (`scene1_subject_rmbg-1_4_d8992eec.png`, `scene1_depth_...png`) with purely in-memory `ContentCacheRegistry.get()`.
   - On cache miss, it tried to run `onnxruntime-node`, which failed on macOS x64 due to missing pre-built N-API binaries (`darwin/x64/onnxruntime_binding.node`).
3. **RAM Throttling on macOS (Darwin)**:
   - `os.freemem()` on Darwin only measures unallocated inactive memory, reporting ~0.1 - 0.3 GB on 16GB systems.
   - `Math.floor(freeRamGB / 1.5)` clamped concurrency to `1` regardless of user requested concurrency (`--concurrency 2` or `auto`).
4. **CLI Concurrency argument parsing**:
   - `apps/legacy-story-renderer/src/cli.ts` forced `concurrency: typeof rawSettings.concurrency === 'number' ? rawSettings.concurrency : 1`, stripping `'auto'` or CLI flags.
5. **Worker Thread Canvas Registration**:
   - `SceneWorkerPool` running in Node worker threads lacked canvas adapter registration (`NapiCanvasAdapter`), throwing `[UniversalCanvasProvider] No canvas adapter registered for environment 'node'`.

## Changes Applied
1. **`packages/effect-engines/src/vision/SubjectSegmentationContext.ts`**:
   - Added `segmentSubject(imageBuffer, options)` alias pointing to `segment()`.
2. **`packages/effect-engines/src/depth3d/index.ts`**:
   - Restored pre-computed disk cache probing in `resolveSubjectCutout()` and `resolveDepthMapData()`, supporting both `fastChecksum` and md5 8-character hash filenames (e.g. `${baseName}_subject_${segStratName}_${md5Checksum}.png`).
   - Retained isomorphic safety: guarded Node.js `fs` lookups behind `typeof process !== 'undefined' && !!process.versions?.node`.
3. **`apps/legacy-story-renderer/src/LegacyDiskStoryRenderer.ts`**:
   - Fixed memory guard: On Darwin or systems with $\ge 8$ GB total RAM, do not clamp concurrency down to 1 worker based on `os.freemem()`.
4. **`apps/legacy-story-renderer/src/cli.ts`**:
   - Added `-c, --concurrency <number|auto>` argument parsing.
   - Registered `NapiCanvasAdapter` and `BunFFIEngineStrategy` in `cli.ts`.
5. **`packages/core/src/SceneWorker.ts`**:
   - Registered `NapiCanvasAdapter` and `BunFFIEngineStrategy` inside worker threads when `isMainThread === false`.
6. **`packages/core/src/ffmpeg-ffi/EncodingStrategies.ts` & `FluentPipeVideoSink.ts`**:
   - Added `-allow_sw 1` fallback option for Apple VideoToolbox.
