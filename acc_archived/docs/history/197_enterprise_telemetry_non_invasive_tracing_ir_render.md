# 197. Enterprise Telemetry: Non-Invasive Distributed Tracing for IR-Render Execution

## 1. Context & Motivation
Previously, `TraceContext` (implementing the W3C `traceparent` standard RFC) was added during Phase 5 Observability & Security (`docs/history/173_enterprise_telemetry_security_phase5.md`), but was not wired into actual production execution flows.

In accordance with our core engineering tenets (`NO-STUBS-ORPHANED-CODE` and `ZERO-ALLOC-FRAME-LOOP`), tracing needed to be wired into meaningful production flows—specifically starting with the **`ir-render`** command. However, intrusive modifications directly into core mathematical frame loops, renderers, or Video IR schemas would violate SRP, OCP, and risk frame rendering determinism.

## 2. Key Changes Made

### A. Ambient `Tracer` with `AsyncLocalStorage` (`packages/core/src/telemetry/Tracer.ts`)
- Implemented an enterprise-grade `Tracer` built on top of Node/Bun `AsyncLocalStorage`.
- Methods:
  - `Tracer.runWithContext(context, fn)`: executes synchronous/asynchronous code with an ambient `TraceContext`.
  - `Tracer.currentContext()`: non-invasively retrieves the current active context from any nested function call.
  - `Tracer.withSpan(name, fn, attributes)`: automatically derives child spans from ambient context, records lifecycle durations, marks status (`OK` / `ERROR`), and attaches error diagnostics without mutating arguments or data schemas.
  - `Tracer.addListener(listener)` / `clearListeners()`: allows external telemetry subscribers and metrics engines to observe span start/end events defensively.

### B. Non-Intrusive Logger Correlation (`packages/core/src/logger.ts`)
- Updated `Logger.formatMessage`: checks `Tracer.currentContext()` ambiently.
- When an active trace context exists, log lines are automatically decorated with:
  `[trace:<traceId:8> span:<spanId:8>]`
- Example output:
  `[2026-10-14T12:57:20.997Z] [trace:11112222 span:ae58f149] [IRRenderCommand] Executing two-pass topological DAG compilation...`
- Requires **zero code changes** across existing components to produce fully correlated logs.

### C. Coarse-Phase Tracing in `handleIrRenderCommand` (`apps/cli/src/commands/ir-render.ts`)
- Wrapped coarse operational phases using `Tracer.withSpan` without modifying `IRMasterRenderer`, `IRChunkWorkerPool`, or `RelationalDAGCompiler` internals:
  1. `ir.input_transform`: Config adapter discovery, AST parsing, and input validation.
  2. `ir.dag_compile`: Probing assets and two-pass topological DAG timeline compilation.
  3. `ir.render_execution`: Single-worker master render or multi-worker temporal chunk pool execution with concurrency attributes.
- Added `traceparent?: string` option to `IrRenderCliOptions`.

### D. CLI Propagation (`apps/cli/src/index.ts`)
- Added `--traceparent <header>` CLI option parsing to `parseCliArgs()` and forwarded it to `handleIrRenderCommand`.
- Documented `--traceparent` in `acc ir-render` help guide.

### E. Formal Test Suite & Regression Verification
- Created `autogenerated-tests/enterprise_ir_render_tracing.test.ts`:
  - Verified `--traceparent` CLI parsing.
  - Verified ambient context propagation and child span derivation across async call trees.
  - Verified dry-run execution capturing `ir.input_transform` and `ir.dag_compile` spans with correct root `traceId`.
- Re-verified all existing tests (`video_ir_phase6_cli_scaling.test.ts` and `enterprise_telemetry_security_phase5.test.ts`) with zero regressions.
