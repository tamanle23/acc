# Task History: [310] Worker Canvas Registration & Track Composite Non-Occlusion

## 1. Context & Root Cause Analysis
During preview rendering of multi-track timelines (such as the default demo or complex sci-fi project), sequences rendered as black or blank boxes under specific circumstances:
1. **Unregistered Canvas Adapter in Web Worker Thread:**
   `UniversalCanvasProvider.registerAdapter(new WebCanvasAdapter(), true)` and `registerCoreModifierPlugins()` were only executed in `main.tsx` on the main DOM thread. In `preview.worker.ts` (the dedicated OffscreenCanvas rendering thread), no canvas adapter was registered. As soon as any track required layer isolation (`profile === 'master'` or non-normal `blendMode`), `UniversalCanvasProvider.createCanvas()` threw an error, suppressing the frame render into black.
2. **Overlay Sequence Occlusion with Neutral Fallback:**
   When an overlay sequence without an `assetId` or with procedural visual modifiers (such as `overlay/canvas_particles` or `overlay/hologram_hud`) was rendered, `IRCanvasCompositor` evaluated `!asset` and painted an opaque neutral fallback rectangle `rgba(20, 20, 28, 0.4)` over the entire frame, occluding lower visual tracks.
3. **Silent Render Error Masking:**
   The `try/catch` in `preview.worker.ts` was silently discarding exceptions during `engine.renderFrame()`, obscuring canvas adapter missing faults.

## 2. Changes Made
- **`apps/studio/src/workers/preview.worker.ts`:**
  - Imported `UniversalCanvasProvider`, `WebCanvasAdapter`, and `registerCoreModifierPlugins`.
  - Registered `WebCanvasAdapter` and core modifier plugins inside the worker thread initialization.
  - Replaced silent error suppression with detailed frame render error reporting.
- **`packages/ir/src/renderer/shared/IRCanvasCompositor.ts`:**
  - Restricted the placeholder dark rectangle fallback strictly to primary media clips (`seq.type !== 'overlay' && (!seq.modifiers || seq.modifiers.length === 0)`).
  - Ensured overlay sequences and clips generating their own procedural visuals do not occlude lower tracks with dark boxes.
  - Added graceful handling for depth3d assets that are still pending decode.
- **`autogenerated-tests/multi_track_layer_blending_isolation.test.ts`:**
  - Added dedicated test `should not occlude lower tracks with black fill when overlay sequence has no asset`.
