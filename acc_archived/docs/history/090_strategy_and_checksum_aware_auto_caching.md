# History Log 090: Checksum & Strategy-Aware Auto Caching for Subject Segmentation & Depth Maps

- **Task**: Upgrade autoCandidate lookup and caching for subject segmentation and depth maps in `renderDepth3DScene` with source image content checksums (MD5) and active strategy names.
- **Date**: 2026-10-01
- **Status**: Completed

---

## 1. Context & Problem
Previously, `renderDepth3DScene` checked for `<image_name>_subject.png` on disk. If a developer had previously generated a legacy or heuristic cutout file, `renderDepth3DScene` would blindly reuse that stale file instead of executing the active SAM/Depth neural strategy (e.g. `SlimSamStrategy` or `SamVitBaseStrategy`). Furthermore, if the source image was updated or the model strategy was swapped, cache invalidation did not occur automatically.

## 2. Proposed Architecture & Cache Invalidation Strategy
Implemented a dual-layer checksum and strategy-aware candidate cache resolution:
1. **Source Content Checksum**: Computed 8-character MD5 hash of raw image buffer (`crypto.createHash('md5').update(imgBuffer).digest('hex').slice(0, 8)`).
2. **Strategy-Specific Identification**: Derived sanitized strategy name from active context (e.g. `slimsam`, `sam-vit-base`, `depth-anything-v2-small`, `heuristic`).
3. **Lookup Resolution Order**:
   - `[Tier 1: Explicit User Override]`: If `depth3d.subjectImage` is defined in story config, use it directly.
   - `[Tier 2: Strategy + Checksum Match]`: Check for `${baseName}_subject_${strategyName}_${checksum}.png`.
   - `[Tier 3: Checksum Match]`: Check for `${baseName}_subject_${checksum}.png`.
   - `[Tier 4: Dynamic Strategy Execution + Auto-Persist]`: If not found and auto-segment/depth is active, run the active strategy context and automatically persist the result with `${baseName}_subject_${strategyName}_${checksum}.png` for instant deterministic cache hits on subsequent runs.
