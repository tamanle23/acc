# History Entry [178]: Enforce Content-Dependent Modality Constraints & Fine-Grained Configurations

## Context & Problem
While 1-to-N fan-out allows multi-format generation from a single `PipelineIR`, blindly attempting to export every content type to all 5 modalities leads to nonsense deliverables (e.g. attempting to generate an audio podcast of someone reading an interactive DOM mortgage calculator or interactive regex tester, or attempting to generate an interactive calculator widget for a lo-fi rain soundscape). Furthermore, callers need fine-grained control to configure video aspect ratio/FPS, audio target LUFS, and social platforms independently within the same task input.

## Solution & Architecture
1. **Semantic Capability Envelopes (`supportedModalities`)**:
   - Calibrated each strategy descriptor to declare its strictly valid modalities (e.g., `item_223_mortgage_calculators` supports `['interactive-web', 'static-web']`, while rejecting `audio` or `video`).
2. **Compatibility Validation Guard in `BaseContentTaskStrategy`**:
   - `BaseContentTaskStrategy.produceOmnichannelOutput` validates all requested modalities against `this.supportedModalities`.
   - Fails fast with clear descriptive error messages if an incompatible format is requested.
3. **Fine-Grained Modality Configuration Blocks**:
   - Supported `videoConfig` (aspect ratio, FPS, duration), `audioConfig` (format, LUFS loudness, ducking), `socialConfig` (platforms, custom hashtags), `staticWebConfig`, and `interactiveWebConfig`.
4. **Specification Documentation**:
   - Documented the complete architectural specification in `docs/CONTENT_DEPENDENT_OMNICHANNEL_FANOUT_SPEC.md`.
