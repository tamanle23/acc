# [040] Audio Normalizer & Seamless DSP Pipeline

## 1. Context & Problem Statement
The user reported that audio effects downloaded from Freesound (via the `library` engine) or generated by AI models often lack professional studio quality. Specific problems included:
- Raw files contained unwanted silence at the beginning/end.
- Loudness levels were inconsistent (varying volume).
- Loopable effects (e.g., rain, wind) had hard cuts, causing clicking/popping when looped sequentially on a timeline.
- One-shot effects (e.g., mouse clicks) lacked smooth fade-outs.

## 2. Implementation Plan
A robust Digital Signal Processing (DSP) pipeline was designed using FFmpeg to intercept all generated/downloaded audio before it reaches the final output directory.
- **Categorization:** Identify effects as `oneshot` or `loop` based on their category/variant.
- **One-shot Pipeline:** Silence removal, high-pass filtering (reduce low-end rumble), loudness normalization (EBU R128), and a 0.2s fade-out.
- **Loop Pipeline (Seamless Splicing):** High-pass filtering, loudness normalization, and a standard audio splicing technique (split audio, swap head and tail, and apply `acrossfade=d=0.5`) to create a perfectly seamless loop.
- **Metadata:** Emit `playback_type`, `is_normalized`, and `loudness` flags into the accompanying JSON metadata.

## 3. Changes Made
- **[NEW] `src/core/AudioNormalizer.ts`:** Implemented the static class `AudioNormalizer` containing `getPlaybackType()` and `normalize()` methods utilizing `FFmpegManager`.
- **[MODIFY] `src/sound-effects/engine.ts`:** Hooked the `AudioNormalizer.normalize()` method into `renderSoundEffect()`. All engines (`ffmpeg`, `ai`, `library`) now route their raw output through this pipeline.
- **[MODIFY] `.agents/rules/sound-effects-architecture.md`:** Added a new section documenting the DSP normalization pipeline and the One-shot vs Loop behavior.
