# Task History Entry: 203_fix_cli_studio_keep_alive.md

## 1. Overview & Problem Statement
When running `bun run cli.ts studio` (or `bun run apps/cli/src/index.ts studio`), the process immediately exited after logging the server URL (`✨ Dual-Engine Studio Preview live at: http://localhost:3300`). This prevented users from accessing and previewing their projects in the browser because the node/bun process terminated prematurely instead of staying alive as an interactive preview server.

Root causes identified:
1. `apps/cli/src/commands/studio.ts`: `handleStudioCommand` started `StudioServer` via `Bun.serve`, but immediately returned without maintaining a keepalive listener for termination signals (`SIGINT`/`SIGTERM`).
2. `apps/cli/src/index.ts`: The CLI command handler resolved immediately upon `handleStudioCommand` completion, triggering `Logger.info(...)` and finishing the CLI process.
3. `cli.ts`: The root launcher exited immediately via `process.exit(0)` after `run(rawArgs)` completed for any command except `serve`.

## 2. Changes Made
1. **`apps/cli/src/commands/studio.ts`**:
   - Added `keepAlive?: boolean` to `StudioCliOptions`.
   - When `options.keepAlive` is enabled, logs `"Studio server is running. Press Ctrl+C to stop."` and awaits a Promise that binds one-time listeners to `SIGINT` and `SIGTERM`.
   - Upon receiving the signal, it stops `StudioServer` gracefully (`studio.stop()`) and resolves the promise.
2. **`apps/cli/src/index.ts`**:
   - Passed `keepAlive: true` to `handleStudioCommand` in both the direct CLI command branch (`options.command === 'studio'`) and the interactive prompt branch (`case 'studio':`).
3. **`cli.ts`**:
   - Updated the post-run exit check so that `studio` (like `serve`) does not trigger immediate premature `process.exit()`.
