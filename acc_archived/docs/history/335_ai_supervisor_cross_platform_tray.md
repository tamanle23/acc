# Task History: 335 - AI-Supervisor Cross-Platform System Tray & Startup Support

## Context & Requirements
Previously, `@acc/ai-supervisor` supported native system tray and startup features exclusively on Windows via PowerShell (`tray_runner.ps1`) and Windows Registry keys (`windowsStartup.ts`). On macOS and Linux, the tray bridge immediately logged a fallback message and disabled tray functionality.

The goal is to enhance the system tray to support macOS and Linux as first-class desktop environments.

## Solution Architecture
1. **macOS Native Status Bar Runner (`tray_runner_mac.swift`)**:
   - Uses Cocoa `NSStatusBar.system.statusItem` and `NSMenu`.
   - On first launch, compiled via `swiftc` into a cached native binary at `~/.acc/bin/tray_runner_mac`.
   - Communicates over standard IO with the same protocol (`TRAY_READY`, `EVENT:OPEN`, `EVENT:PURGE_VRAM`, `EVENT:RESTART_ALL`, `EVENT:CHECK_UPDATE`, `EVENT:EXIT`, `ICON:<color>`, `TOOLTIP:<text>`).

2. **Linux Tray Runner (`tray_runner_linux.py`)**:
   - Provides AppIndicator3 / GTK3 system tray support with context menus.
   - Falls back gracefully to `notify-send` desktop alerts when in headless/minimal Linux environments.

3. **Cross-Platform Startup Manager (`StartupManager.ts`)**:
   - **Windows**: HKCU Run registry key via PowerShell.
   - **macOS**: User LaunchAgent plist (`~/Library/LaunchAgents/com.acc.ai-supervisor.plist`) loaded via `launchctl`.
   - **Linux**: XDG desktop entry (`~/.config/autostart/com.acc.ai-supervisor.desktop`).
   - Retained backwards-compatible shim in `windowsStartup.ts`.

4. **OS-Native WebView Window Host (`WindowHost.ts`)**:
   - Upgraded to prioritize true OS-provided native webviews with zero runtime compilation:
     - **macOS**: Shipped with precompiled **Universal Mach-O (`arm64` + `x86_64`)** native binaries located at [`src/assets/bin/`](file:///Users/anle/workspace/acc/apps/ai-supervisor/src/assets/bin/):
       - `tray_runner_mac`: Native Cocoa status item & menu
       - `webview_host_mac`: Native Cocoa `WKWebView` window host
     - **Windows**: Native WinForms window hosting `Microsoft.Web.WebView2` ([`webview_host_win.ps1`](file:///Users/anle/workspace/acc/apps/ai-supervisor/src/assets/webview_host_win.ps1)) with automatic fallback to WebBrowser control.
     - **Linux**: Native GTK window hosting `WebKit2.WebView` ([`webview_host_linux.py`](file:///Users/anle/workspace/acc/apps/ai-supervisor/src/assets/webview_host_linux.py)).
   - Multi-tier fallback hierarchy:
     1. `NativeWebViewStrategy` (precompiled WKWebView / WebView2 / WebKit2GTK)
     2. `ChromiumAppModeStrategy` (`--app=<url>`)
     3. `DefaultBrowserStrategy` (system default browser)
   - Automatically opens on user launch (or when system tray is disabled/unavailable), while respecting `--minimized` for headless background startup.

5. **Integration & Dashboard Launch**:
   - Updated `NativeTrayBridge.ts` to dispatch platform-specific runners for `win32`, `darwin`, and `linux`.
   - Updated `index.ts` to coordinate `NativeTrayBridge` and `WindowHost`.
