## 1. Context & Motivation
Following the creation of `@acc/legacy-story-renderer` in Iteration 31, legacy disk-based rendering still maintained an automatic fallback path inside `VideoEditPipelineOrchestrator.renderStoryVideo()` in `@acc/cli`.

To enforce strict architectural isolation and prevent accidental or unmanaged invocation of deprecated disk-stitching routines during modern operations, **all fallback and secondary execution routes to the legacy renderer have been completely stripped from `@acc/cli`**. 

Legacy mode is now **exclusively executable via the Direct Quarantined CLI** in `@acc/legacy-story-renderer`.

---

## 2. Key Architecture & Implementation Changes

### 2.1 Direct Quarantined CLI (`apps/legacy-story-renderer/src/cli.ts`)
- Added a standalone CLI entrypoint for the legacy package:
  ```bash
  bun run apps/legacy-story-renderer/src/cli.ts <story-directory> [-o <outputPath>]
  ```
  or via the registered bin:
  ```json
  "bin": {
    "acc-legacy-render": "./src/cli.ts"
  }
  ```
- Includes self-contained folder resolution, schema checks, and direct delegation to `LegacyDiskStoryRenderer.render()`.

### 2.2 Stripping Legacy Fallback from `@acc/cli`
- Refactored `VideoEditPipelineOrchestrator.renderStoryVideo()` in `apps/cli/src/pipelines/04-generative-story/VideoEditPipelineOrchestrator.ts`:
  - Removed `LegacyDiskStoryRenderer` import entirely.
  - Stripped the catch block fallback that routed compilation failures into the legacy engine.
  - `@acc/cli` now exclusively executes via the Canonical Universal Video IR Engine (`IRChunkWorkerPool` / `IRMasterRenderer`).
- Legacy AST helper `prepareIR` delegates to `LegacyIRPreparationAdapter` strictly for backward compatibility with AST test contracts.
