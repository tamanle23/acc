## 1. Context & Problem Statement
Following the modular Strategy Pattern refactoring of the vision subsystem, the subject segmentation models were successfully expanded to RMBG-1.4, SAM 2.1, BiRefNet, and SlimSAM. The user requested:
1. Explaining the role of Depth Anything in the project and the current depth estimation architecture.
2. Expanding depth estimation strategies with metric depth, DPT, and large/base depth models (e.g., `Depth-Anything-v2-Base`, `GLPN-Metric-Depth`, `DPT-Large`).
3. Running a formal multi-strategy depth benchmark using automated unit tests with zero Python dependencies.

---

## 2. Proposed Architecture & Strategy Implementations

### Depth Strategies Implemented
1. **`DepthAnythingV2SmallStrategy`** (`onnx-community/depth-anything-v2-small`, ~95MB):
   - **Role**: SOTA Default relative monocular depth estimation.
   - **Speed**: ~1.2s on CPU.
   - **Characteristics**: Sharp boundary edge delineation, zero depth bleeding.
2. **`DepthAnythingV2BaseStrategy`** (`onnx-community/depth-anything-v2-base`, ~380MB):
   - **Role**: High-capacity Relative Depth model for maximum detail.
   - **Characteristics**: 12-layer Vision Transformer backbone with high dynamic depth range.
3. **`GlpnMetricStrategy`** (`Xenova/glpn-nyu`, ~60MB):
   - **Role**: True **Metric Depth** estimation (in real-world meters).
   - **Speed**: ~4.4s on CPU.
   - **Characteristics**: Global-Local Path Network for indoor/outdoor metric scale depth maps.
4. **`DptLargeStrategy`** (`Xenova/dpt-large`, ~130MB):
   - **Role**: Dense Prediction Transformer for volumetric spatial awareness.
   - **Characteristics**: Invariant depth representation across large resolutions.
5. **`HeuristicDepthStrategy`** (`heuristic-luminance-gradient`, 0MB):
   - **Role**: 0ms Instant Fallback strategy with zero disk/GPU footprint.
