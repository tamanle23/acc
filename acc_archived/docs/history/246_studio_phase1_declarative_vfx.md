# 246 - Studio Phase 1: Declarative Particle & Hologram HUD Subsystem

## Overview
Phase 1 eliminates hardcoded visual effects (particle swarm and hologram HUD) from Studio's `Preview.tsx` canvas engine mount, converting them into declarative modifiers driven by the active sequence configuration and optional viewport ambiance controls.

## Problem
In `apps/studio/src/components/Preview.tsx`, the `useEffect` hook initializing the `UniversalCanvasEngine` was unconditionally executing:
```typescript
engine.initHologramHUD(0.35, 40);
engine.initParticleSystem(250);
```
As a result, every project rendered a sci-fi HUD ring and flying particle swarm, even for blank projects or standard video sequences.

## Solution
1. **Engine Dynamic Lifecycle**:
   - Enhanced `packages/effect-engines/src/canvas/UniversalCanvasEngine.ts` with `clearParticles()`, `hasParticles()`, `clearHologramHUD()`, `hasHologramHUD()`, and `setHUDConfig()`.
2. **Preview Modifier Sync**:
   - Removed the hardcoded initialization on mount.
   - Dynamically inspect active sequences rendered at the current playhead frame. If an active sequence contains particle modifiers (`vfx/particles`, `overlay/canvas_particles`) or HUD modifiers (`overlay/hologram_hud`, `sci_fi_hud`), the engine activates the corresponding subsystem; otherwise, it clears them.
   - Added a `showVfxAmbiance` toggle in the Viewport Control Bar with a `<Sparkles />` icon for developer/designer previewing.
3. **Tests & Paired Docs**:
   - Test suite: `autogenerated-tests/studio_phase1_declarative_vfx.test.ts`.
   - Paired docs: `apps/studio/doc/implementation_plan_11.md` and `apps/studio/doc/walkthrough_11.md`.
