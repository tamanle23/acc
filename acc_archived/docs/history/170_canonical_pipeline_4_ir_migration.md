## 1. Context & Motivation

Prior to this phase, `StoryOrchestratedRenderStage` maintained a bifurcated code path: it only invoked the Universal Video IR rendering engine when `ctx.metadata?.useIRBackend` was explicitly supplied, otherwise delegating to `VideoEditPipelineOrchestrator.renderStoryVideo`. The legacy orchestrator rendered individual scenes into intermediate MP4 disk files (`scene_0.mp4`, `scene_1.mp4`), generated temporary ASS subtitle files on disk, and stitched them together using ad-hoc FFmpeg filtergraph strings (`FFmpegFilterGraph`).

This legacy path caused:
1. Significant I/O overhead from repeated disk writes and re-encodings.
2. Inconsistent effect composition compared to the IR relational timeline.
3. Fragile filtergraph string generation for complex audio ducking, transitions, and multi-track overlays.

In Phase 2 of the Enterprise Universal IR transformation plan, we:
1. Promoted the Universal Video IR engine (`IRChunkWorkerPool` / `IRMasterRenderer`) to be the **default, canonical rendering backend** for Pipeline 4 (`GenerativeStoryPipeline`).
2. Eliminated intermediate disk file generation entirely from the primary execution path.
3. Preserved 100% backward compatibility by refactoring `VideoEditPipelineOrchestrator.renderStoryVideo` into a facade that delegates directly into the canonical IR engine.
4. Maintained compliance with the `STORY-CONFIG-8POINT-SYNC`, `DETERMINISTIC-HANDSHAKE-BACKPRESSURE`, and `ZERO-ALLOC-FRAME-LOOP` architectural directives.

## 2. Key Architecture & Implementation Changes

### 2.1 Default Canonical IR in `StoryOrchestratedRenderStage`
- **File**: `apps/cli/src/pipelines/04-generative-story/stages/StoryOrchestratedRenderStage.ts`
- Made `StoryConfigToUniversalIRAdapter`, `RelationalDAGCompiler`, and `IRChunkWorkerPool` / `IRMasterRenderer` the primary default rendering mechanism for all executions of `GenerativeStoryPipeline`.
- Dynamically resolves concurrency from `ctx.options?.concurrency`, `resolvedConfig.settings.concurrency`, or auto-detected CPU cores (`os.cpus().length`).
- Slices timelines cleanly using `IRChunkWorkerPool` when `concurrency > 1`, and uses `IRMasterRenderer` + `FFIVideoEncoderSink` for single-thread scenarios.
- Records unified rendering metadata in `ctx.metadata.irPoolResult` and `ctx.metadata.irRenderResult` (including Merkle root hash, total frames, duration, and dimensions).

### 2.2 Backward Compatibility Facade in `VideoEditPipelineOrchestrator`
- **File**: `apps/cli/src/pipelines/04-generative-story/VideoEditPipelineOrchestrator.ts`
- Refactored `VideoEditPipelineOrchestrator.renderStoryVideo` to adapt incoming `ResolvedStoryConfig` into a `VideoIRDocument` and render directly via `IRChunkWorkerPool` or `IRMasterRenderer`.
- Any external caller or script invoking `VideoEditPipelineOrchestrator.renderStoryVideo(...)` automatically benefits from the zero-copy, multi-worker parallel chunking engine with zero intermediate files.
- Preserved legacy fallback handling for maximum defensive resilience.

### 2.3 Strict 8-Point Sync (`STORY-CONFIG-8POINT-SYNC`)
- Verified all 8 touchpoints:
  1. `src/types.ts` & `packages/core/src/types.ts`: `concurrency` typed as `number | 'auto'`.
  2. `schema/story-config.schema.json`: `settings.concurrency` schema supports integer and `"auto"`.
  3. `docs/STORY_CONFIG_SPEC.md`: Accurately documents concurrency, container formats, and platform defaults.
  4. `cli.ts` / `src/renderer.ts` / `src/platforms.ts`: Platform defaults correctly set `concurrency: 'auto'`.
  5. `sample-story/story-config.json`: Fully valid against canonical IR DAG compiler.
