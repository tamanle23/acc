# 155. Fix FFI Concat Muxer Out of Bounds Access & Prevent BGM Muxing Into Video Track

## Context & Problem
1. **Out of bounds access Crash:**
   In `packages/core/src/ffmpeg-ffi/FFIConcatMuxer.ts`, `pktView` was allocated with 64 bytes (`safeArrayBuffer(pkt, 0, 64)`). Reading packet duration at byte offset 64 (`pktView.getBigInt64(64, true)`) threw a runtime `RangeError: Out of bounds access`, halting `StoryOrchestratedRenderStage` during multi-scene concatenation.
2. **Video Stream PTS Ballooning to 9 Hours:**
   In `packages/core/src/FFmpegExecutor.ts`, any command with multiple inputs (`inputPaths.length > 1`) was routed unconditionally to `FFIConcatMuxer.concatenate(inputPaths, outputFile)`.
   When `VideoEditPipelineOrchestrator` processed background music (`bgm.mp3`), it issued an FFmpeg command with `[currentVideoPath, bgmPath]` and a complex filtergraph (`complexFilter`).
   `FFIConcatMuxer` treated `bgm.mp3` as segment 2 of the video file. Because `bgm.mp3` only has audio stream 0, `FFIConcatMuxer` read audio packets and wrote them into output stream 0 (the H.264 video track). The audio packet durations pushed the H.264 video stream PTS to 2,953,544,640 ticks (32,821.26 seconds $\approx$ 9 hours 7 minutes), producing `Invalid NAL unit size` errors.

## Solution & Architecture Changes
1. **Increased Buffer Allocation in `FFIConcatMuxer`:**
   Allocated 128 bytes for `pktView` via `safeArrayBuffer(pkt, 0, 128)`, allowing safe reads of packet `pts` (8), `dts` (16), `stream_index` (36), and `duration` (64).
2. **Defensive Stream Remapping in `FFIConcatMuxer`:**
   Stream mapping in `FFIConcatMuxer` now matches streams by `codec_type` (`video -> outVideoIdx`, `audio -> outAudioIdx`). Packets from input streams that do not match the expected container stream type are safely ignored rather than corrupted across stream indices.
3. **Guarded Multi-Input Concatenation in `FFmpegExecutor`:**
   - If `this.complexFilterStr` is set on `FFmpegCommand`, `FFIConcatMuxer` is skipped and the primary video input is safely copied to the destination.
   - If multiple inputs are provided, `FFIConcatMuxer.concatenate` is only invoked when all inputs are genuine video container files (`.mp4`, `.mov`, `.webm`, `.mkv`). If mixed media files (e.g. video + audio) are supplied, it falls back safely to preserving the primary input stream.
4. **Monotonic Video PTS in `FFIVideoEncoder`:**
   Maintained a strictly monotonic packet index `videoPacketIndex` when draining encoded video packets, preventing timestamp jitter across encoder flushes.

2. Output video `sample-story/output/Dinosaur_Story_125.mp4` verified:

   - Size: **31.50MB**.
   - H.264 Video track PTS and AAC Audio track PTS are completely clean with 0 NAL unit errors.
