## Context & Objectives
In `apps/studio/src/components/RightSidebar.tsx`, the inspector accordion items rendered action buttons (`<Button>`) and toggles (`<Switch>`) directly as children of `<AccordionTrigger>`. Because Radix UI's `<AccordionPrimitive.Trigger>` renders an HTML `<button>` element, and `<Switch>` renders a `<button role="switch">`, this triggered a React DOM nesting validation error:
`accordion.tsx:25 <button> cannot contain a nested <button>.`

## Work Accomplished
1. **`apps/studio/src/components/ui/accordion.tsx`**:
   - Enhanced `AccordionTrigger` with `actions?: React.ReactNode` and `headerClassName?: string` props.
   - Restructured `<AccordionPrimitive.Header>` to render `<AccordionPrimitive.Trigger>` (containing only the title/icon and chevron indicator) and a sibling `<div className="flex items-center gap-1 pr-2 shrink-0">` holding auxiliary action elements.
   - Sibling actions stop event propagation so clicking buttons/switches never toggles accordion state.
2. **`apps/studio/src/components/RightSidebar.tsx` & `Sidebar.tsx`**:

   - Verified that `<AccordionTrigger>` children contain strictly the title icon and text span.
3. **Automated Testing & Build Verification**:
