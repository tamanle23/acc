# [285] Fix Studio Preview Initial Black Screen Canvas on Window Open

## Context & Problem
When opening ACC Studio (`bun run cli.ts studio`), the preview viewport rendered a pitch-black canvas instead of rendering the initial timeline sequence frame (frame 0) or placeholder.

### Root Causes
1. **Worker Boot Silence**: When `PreviewWorkerBridge.init()` transferred the canvas to the background worker (`preview.worker.ts`), the worker created the `IRPreviewEngine` and posted `{ type: 'ready' }` back, but never rendered frame 0.
2. **Missing Ready Re-sync Callback**: In `PreviewWorkerBridge.ts`, the `ready` signal was set to `isReady = true`, but no callback was registered to alert the React container that the worker was operational and ready to accept texture syncs and frame render instructions.
3. **Texture Synchronization Without Immediate Repaint**: When `updateTextures` was delivered to the worker, it updated its internal `textureCache` map, but did not trigger a repaint of the current parked frame. If the frame had already been rendered as pure black prior to texture download completion, the canvas remained black until manually scrubbed.

## Implementation Details

1. **Auto-Render on Worker Initialization (`apps/studio/src/workers/preview.worker.ts`)**:
   - In `case 'init':`, after `engine = new IRPreviewEngine(data.timeline);` and `self.postMessage({ type: 'ready' });`, immediately invoke `renderCurrentFrame(currentFrame, 1.0, 1.0)`.
   - In `case 'updateTextures':`, whenever new bitmaps arrive and playback is parked (`!isPlaying`), immediately call `renderCurrentFrame(currentFrame, 1.0, 1.0)`.

2. **Bridge Lifecycle & Readiness Hook (`apps/studio/src/lib/worker/PreviewWorkerBridge.ts`)**:
   - Added `onReady(callback: () => void)` and `getIsReady(): boolean` to `PreviewWorkerBridge`.
   - Dispatches `onReadyCallback()` as soon as the worker completes initial setup.

3. **Subscribed Initial Texture Sync (`apps/studio/src/components/Preview.tsx`)**:
   - Hooked `bridge.onReady(() => setAssetTick((t) => t + 1))` so that once the worker thread is live, active textures and bitmaps are immediately converted via `createImageBitmap` and transferred, repainting frame 0 seamlessly.
