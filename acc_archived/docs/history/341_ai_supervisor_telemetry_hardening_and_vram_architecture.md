## 2. Key Architectural Components & Changes

### A. Studio Health Probing Mechanism
- **File**: `apps/ai-supervisor/src/bun/PortScanner.ts`, `apps/ai-supervisor/src/bun/SupervisorEngine.ts`
- **Dual-Stack Socket Probing**:
  - `isPortListening(port, host, timeoutMs)` opens a lightweight `net.Socket()` connection with a 500ms timeout.
  - Probes `127.0.0.1` (IPv4) followed by `::1` / `localhost` (IPv6 fallback) to accommodate modern Vite dev server binding defaults.
  - On connection, flags status as `ADOPTED` if running externally before supervisor startup, or `RUNNING` if spawned and monitored by `SupervisorEngine`.
  - Non-responsive ports transition child processes to `STARTING` or `CRASH_LOOP` upon exit.

### B. High-Density Telemetry Cards (`TelemetryGrid.tsx`)
- **File**: `apps/ai-supervisor/src/ui/components/TelemetryGrid.tsx`
- **Hardware Accelerator & Execution Target**: Displays GPU accelerator name, active compute tier (`TIER1` - `TIER5`), and execution target pill (`MPS`, `CUDA`, or `CPU`).
- **Host & Sidecar Memory Pressure**: Visualizes dynamic RAM usage (Used / Total GB), threshold-ramped progress bar (`<65%` green, `65-85%` amber, `>85%` rose), and **Fleet RSS** (aggregate memory consumed across child processes).
- **Neural VRAM & Model Cache**: Live VRAM metrics, percentage usage, hot model count, and active inference engines (`Kokoro TTS` / `VieNeu v3 Turbo`).
- **CPU & Pipeline Execution Velocity**: Displays active cores, fleet CPU %, and dynamic worker state: shows **Idle / Ready** or live **Job ID**, frame progress (`currentFrame / totalFrames`), and encoding speed (`fps`).

### C. OS Process Sampling Hardening
- **File**: `apps/ai-supervisor/src/bun/telemetry/OSProcessSampler.ts`
- Supported both `IProcessRunner.execute` and `IProcessRunner.exec` method signatures, ensuring compatibility across Bun execution environments and test mocks.
- Sanitized `ps -o %cpu,rss -p <pid>` parsing on macOS/Linux and PowerShell `Get-Process` on Windows.

### D. Dedicated VRAM vs. Apple Silicon Architecture
- **Dedicated Graphics Cards (NVIDIA)**:
  - Driver query: `nvidia-smi --query-gpu=memory.total,memory.free,name`
  - In-process CUDA query: `torch.cuda.mem_get_info()` queries physical GDDR registers.
  - Eviction & Purging: Dispatches `torch.cuda.empty_cache()` and `torch.cuda.ipc_collect()` to reclaim GPU heap blocks.
- **Apple Silicon (macOS arm64)**:
  - Queries `sysctl -n hw.memsize`. Host RAM acts as a unified pool shared dynamically across CPU, GPU (Metal), and Neural Engine.
  - Explanation of `240 MB / 16.0 GB`: Reflects the exact footprint of the loaded TTS engine (240 MB) against the unified host memory pool (16 GB).
