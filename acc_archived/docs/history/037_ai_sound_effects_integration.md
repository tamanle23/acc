# [037] AI Sound Effects Integration & Strategy Pattern

**1. Context & Problem Statement**
The user requested the ability to seamlessly switch between the local FFmpeg procedural engine and local Open-Source AI sound generation models (Stable Audio Open, AudioLDM 2, Tango 2). The strict constraint was that all AI execution must run locally without API keys, and the existing FFmpeg generators must remain completely untouched.

**2. Implementation Plan**
- **Strategy Pattern (Abstract Factory)**: `Registry.ts` dynamically routes generation requests to either the legacy `generators/` (FFmpeg) or the new `generators/ai/` based on a CLI `--engine` flag.
- **Daemon/Worker IPC Pattern**: Implement a `LocalAIEngine.ts` in TypeScript to manage a persistent background Python daemon (`python_worker.py`). This avoids the heavy performance penalty of reloading 2GB+ PyTorch models into VRAM for every individual sound file.

**3. Changes Made**
- `[NEW] docs/LOCAL_AI_BRIDGE.md`: Added comprehensive documentation for the AI Bridge lifecycle.
- `[NEW] src/sound-effects/generators/ai/*.ts`: Created parallel domain generators (`Foley`, `SciFi`, `Diegetic`, etc.) that compile English Text-to-Audio prompts instead of Lavfi filters.
- `[NEW] src/sound-effects/engines/LocalAIEngine.ts`: Implemented the Singleton TypeScript IPC manager handling the lifecycle (Lazy init, Handshake, Graceful termination on `SIGINT`/`exit`).
- `[NEW] src/sound-effects/engines/python_worker.py`: Implemented the Python daemon using PEP 723 inline dependencies for `uv` package management. Pinned `transformers<4.39.0` to resolve GPT2Model incompatibility with AudioLDM2.
- `[MODIFY] sound-effects-cli.ts`: Added `--engine` and `--ai-model` flags. Modified output routing to save files into respective `autogenerated/sound-effects/ffmpeg/` or `ai/` directories.
- `[MODIFY] src/sound-effects/core/Registry.ts`: Refactored to support conditional aliased imports.

**4. Verification & Walkthrough**
- Verified the batch processor still functions.
- Encountered a dependency hell bug in Python (`GPT2Model` missing `_update_model_kwargs_for_generation`). Fixed by pinning `transformers<4.39.0` in the inline metadata, leveraging `uv` to dynamically reconstruct the environment.
- The lifecycle cleanly manages PyTorch VRAM and leaves no zombie processes upon termination.
