# History Record 311: Canonical IR Plugin Registry Refactor, Categorized Add Effect Suite & Closed-Form Bézier Solver

## Context & Motivation
In Iteration 28, four key architectural and user experience issues were addressed:
1. **Redundant & Duplicate IR Plugins**:
   - `packages/ir/src/plugins/index.ts` registered legacy alias plugins alongside canonical plugins (`animation/gsap` vs `motion/gsap`, `overlay/sci_fi_hud` vs `overlay/hologram_hud`, duplicate transition registrations, `camera/3d`). Per explicit directive, backward-compatibility aliases were completely removed to keep the core IR plugin system pristine, canonical, and decoupled.
2. **Unwieldy "Add Effect" Dropdown List & Hardcoded Catalog Drift**:
   - The dropdown in `RightSidebar.tsx` rendered a flat column with 15+ items and redundant names. It was refactored into a **dynamic, registry-driven menu** that automatically discovers plugins from `ModifierPluginRegistry` at runtime, organizes them into categorized submenus (*Motion & Spatial*, *Visual Effects (VFX)*, *Transitions*, *Audio & DSP*, *Typography & Shapes*, *Extensions & Custom*), and reactively filters by track type.
3. **`[object Object]` Rendered in In-Canvas Transform Inspector**:
   - `TransformModifierPlugin.ts` did not define the `animation` field in its declarative schema. Consequently, when sequences contained transform lifecycle animations, `DynamicModifierInspector.tsx` fell back to string coercion (`String(val)` $\rightarrow$ `"[object Object]"`).
   - This was fixed by adding `animation` as a first-class `motion_lifecycle` parameter in `TransformModifierPlugin.ts` schema and ensuring `DynamicModifierInspector.tsx`'s `inferFieldDescriptor` maps any lifecycle object to `motion_lifecycle` (which resolves to `MotionLifecycleControlStrategy`).
4. **Closed-Form Cubic Bézier Solver & Two-Way Persistence**:
   - Implemented `packages/ir/src/renderer/preview/BezierMath.ts` providing zero-heap-allocation `parseCubicBezier` and `solveCubicBezier` (Newton-Raphson root solver with bisection fallback).
   - Wired `evaluateEase` in `DeterministicMotionEvaluator.ts` to evaluate `cubic-bezier(...)` strings natively.
   - Connected `TransitionCurveGraph.tsx`'s `onCurveChange` in `EasingCurveSelector.tsx` to commit `cubic-bezier(x1, y1, x2, y2)` into the VideoIR document.

## Changes Implemented

### 1. Packages / Core IR (`packages/ir`)
- **`packages/ir/src/plugins/index.ts`**:
  - Removed `animation/gsap`, `overlay/sci_fi_hud`, `camera/3d` aliases.
  - Consolidated transition registrations to canonical types (`transition/crossfade`, `transition/wipe`, `transition/push`, `transition/zoom`, `transition/dip`, `transition/glitch`, `transition/light_leak`, `transition/radial_wipe`, `transition/iris`).
- **`packages/ir/src/plugins/transform/TransformModifierPlugin.ts`**:
  - Added `animation` field to `schema.fields` typed as `motion_lifecycle`.
- **`packages/ir/src/renderer/preview/BezierMath.ts`** [NEW]:
  - `parseCubicBezier(spec: string): [number, number, number, number] | null`
  - `solveCubicBezier(x1: number, y1: number, x2: number, y2: number, x: number): number` (pure Newton-Raphson + bisection fallback, $\le 8$ iterations, zero nursery allocations).
- **`packages/ir/src/renderer/preview/DeterministicMotionEvaluator.ts`**:
  - Wired `evaluateEase` to detect `cubic-bezier(...)` and evaluate using `solveCubicBezier`.
- **`packages/ir/src/renderer/index.ts`**:
  - Exported `BezierMath`.

### 2. Studio Application (`apps/studio`)
- **`apps/studio/src/components/inspector/modifierCatalog.ts`**:
  - Added `ModifierCategory` union (`'motion' | 'vfx' | 'transitions' | 'audio' | 'text' | 'custom'`).
  - Enriched `MODIFIER_PRESENTATION_CATALOG` with category metadata.
  - In `getAvailableModifiersFromRegistry()`, dynamically assigns categories and provides fallback for runtime-registered custom plugins.
  - Pruned legacy alias branches in `getSectionIdForModifierType`.
- **`apps/studio/src/components/RightSidebar.tsx`**:
  - Refactored Add Effect menu to dynamically group modifiers by category using `DropdownMenuSub`, `DropdownMenuSubTrigger`, and `DropdownMenuSubContent`.
  - Maintained strict architectural line ceiling ($< 350$ lines, exactly 334 lines).
- **`apps/studio/src/components/inspector/DynamicModifierInspector.tsx`**:
  - Handled `key === 'animation'` and nested lifecycle objects to return `type: 'motion_lifecycle'`, eliminating `[object Object]` text inputs.
- **`apps/studio/src/components/inspector/TransitionCurveGraph.tsx`**:
  - Integrated `parseCubicBezier` to initialize control handles directly from `cubic-bezier(...)` strings.
- **`apps/studio/src/components/EasingCurveSelector.tsx`**:
  - Connected `onCurveChange` callback to format and commit `cubic-bezier(x1, y1, x2, y2)`.
