# Technical Specification: Multi-Modal Synchronization Architecture

**Target Specification:** Video IR Schema V1.0-Stable
**Classification:** Temporal Resolution, Pacing, and Audio-Visual Alignment

---

## 1. Executive Summary

In automated video generation—particularly for localized marketing, AI-driven storytelling, and programmatic news—content length is highly volatile. A Text-to-Speech (TTS) voiceover chunk that takes 4.2 seconds in English might take 5.8 seconds in German. 

Traditional NLE schemas (XML, EDL) rely on absolute timestamps (e.g., `start: 00:01:15:00`). If a single voiceover clip changes length, every subsequent video clip, background music cue, and subtitle file becomes permanently desynchronized, requiring manual recalculation.

The **Video IR Relational DAG** solves this by establishing a **Master-Subordinate synchronization topology**. By using audio durations as the immutable "Anchor," visuals and captions automatically stretch, ripple, and align in real-time during the compilation phase, guaranteeing zero-drift synchronization.

---

## 2. Pillar 1: The "Audio-Anchor" Topology

In storytelling pipelines, the spoken word dictates the pacing. Therefore, audio tracks must be treated as the **Anchor Nodes**, while video and data tracks act as **Subordinate Nodes**.

### 2.1 Relational Binding
Instead of declaring that a visual clip lasts for `150` frames, the IR binds the visual sequence directly to the audio sequence using `matchLengthOf` and `syncWith`.

* **The Voiceover (Anchor):** `seq_vo_scene_1` (Length determined dynamically in Pass 1 by probing the `.wav` file).
* **The Visual (Subordinate):** `seq_vid_scene_1` declares `"start": { "syncWith": "seq_vo_scene_1" }` and `"duration": { "matchLengthOf": "seq_vo_scene_1" }`.

If the TTS engine generates a slower voiceover, the visual track automatically remains on screen longer to cover the gap.

---

## 3. Pillar 2: Relative Captioning (Word-Level Precision)

Subtitles are notoriously difficult to sync in dynamic pipelines. If subtitles use global timestamps (e.g., `Show 'Hello' at Frame 300`), any upstream edit breaks them.

### 3.1 Chunk-Isolated Cues
The Video IR schema enforces **Sequence-Relative Timing** for timed text. Subtitle sequences are bound to the Voiceover sequence, and the individual words (`cues`) are timed in milliseconds *relative to the start of that specific sequence*, not the global timeline.

```json
{
  "id": "seq_sub_1",
  "time": { 
    "start": { "syncWith": "seq_vo_1" },
    "duration": { "matchLengthOf": "seq_vo_1" }
  },
  "cues": [
    { "startOffsetMs": 0, "endOffsetMs": 450, "text": "Welcome" },
    { "startOffsetMs": 450, "endOffsetMs": 900, "text": "to our" },
    { "startOffsetMs": 900, "endOffsetMs": "end", "text": "channel." }
  ]
}
```

**The Result:** If an AI agent inserts a 5-second intro logo at the beginning of the video, `seq_vo_1` is pushed back 150 frames. `seq_sub_1` automatically follows it, and the internal `cues` remain perfectly locked to the waveform. 

---

## 4. Pillar 3: Visual Fill Policies (Mismatch Resolution)

When a visual asset is dynamically bound to an audio anchor, a physical duration mismatch is inevitable. 
* *Example:* The voiceover takes 8 seconds, but the underlying B-Roll MP4 is only 5 seconds long.

If left unhandled, the video will go black for 3 seconds. The IR handles this via a **Playback Modifier Plugin**, allowing automated decision-making on how to fill the void.

### 4.1 Playback Modifiers
By attaching a `playback/time_remapping` modifier to the video sequence, the engine deterministically resolves the mismatch:

1. **`freeze_on_last_frame`:** The video plays at normal speed for 5 seconds, then holds the final frame as a static image for the remaining 3 seconds. (Ideal for presentation slides or web UI captures).
2. **`loop`:** The video plays to the end, then seamlessly restarts from frame 0. (Ideal for abstract backgrounds or drone footage).
3. **`stretch`:** The engine dynamically calculates a slow-motion ratio (e.g., 5 seconds / 8 seconds = 0.625x speed) and interpolates the frames so the video finishes exactly as the voiceover ends.

---

## 5. Pillar 4: Cinematic Pacing (J-Cuts and Pre-Roll)

Strict 1:1 synchronization feels robotic. Human editors leave "breathing room"—allowing the video to cut a fraction of a second before the speaker starts talking, or letting the visual linger after they stop.

### 5.1 Temporal Padding & Offsets
The IR supports relational offsets to simulate human editing (J-Cuts and L-Cuts):

* **Pre-Roll (Visual starts early):** 
  `"start": { "syncWith": "seq_vo_1", "offsetFrames": -15 }`
  The B-Roll appears half a second before the narrator begins speaking.
* **Post-Roll (Visual lingers):**
  `"duration": { "matchLengthOf": "seq_vo_1", "paddingFrames": 30 }`
  The B-Roll remains on screen for 1 second of silence after the voiceover ends.

Because the subsequent sequences use `"after": "seq_vid_1"`, the DAG compiler automatically factors this padding into the ripple-edit, ensuring the next scene doesn't start prematurely.

## 6. Concrete Implementation Example

The following IR payload demonstrates perfectly synced Voiceover, Video (with a loop policy), Subtitles (with relative cues), and Background Music (ducking underneath the VO).

```json
{
  "version": "1.0.0-stable",
  "meta": { "contentId": "sync_demo_01", "globalFps": 30 },
  "assets": {
    "vo_intro": { "src": "s3://audio/tts_intro.wav", "type": "audio" },
    "b_roll_cloud": { "src": "s3://video/clouds.mp4", "type": "media" }
  },
  "tracks": [
    {
      "id": "track_v1_main",
      "type": "video",
      "sequences": [
        {
          "id": "seq_vid_1",
          "assetId": "b_roll_cloud",
          "time": {
            "start": { "syncWith": "seq_vo_1", "offsetFrames": -15 }, 
            "duration": { "matchLengthOf": "seq_vo_1", "paddingFrames": 30 }
          },
          "modifiers": [
            {
              "type": "playback/time_remapping",
              "params": { "outOfBoundsPolicy": "loop" }
            }
          ]
        }
      ]
    },
    {
      "id": "track_subtitles",
      "type": "timed_text",
      "sequences": [
        {
          "id": "seq_sub_1",
          "time": {
            "start": { "syncWith": "seq_vo_1" },
            "duration": { "matchLengthOf": "seq_vo_1" }
          },
          "cues": [
            { "startOffsetMs": 0, "endOffsetMs": 1200, "text": "Look at the clouds." },
            { "startOffsetMs": 1200, "endOffsetMs": "end", "text": "They are beautiful." }
          ]
        }
      ]
    },
    {
      "id": "track_a1_voiceover",
      "type": "audio",
      "sequences": [
        {
          "id": "seq_vo_1",
          "assetId": "vo_intro",
          "time": { "start": 15 } 
        }
      ]
    }
  ]
}
```

### Conclusion

By elevating audio durations to act as topological anchors, embedding relative timestamp offsets for captions, and defining strict playback mismatch policies as modifiers, the Video IR Engine completely eliminates "sync drift." AI orchestration agents can swap scripts, languages, and assets blindly, trusting the DAG compiler to re-weave the timeline into a cinematically paced, perfectly synchronized final render.
