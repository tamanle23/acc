## 1. Non-Negotiable Core Architectural Invariants

All design choices, data flows, and code implementations must strictly adhere to four unbreakable engineering mandates:

### 1. Invariant 1: Absolute Determinism (Cannot Be Broken)
- **Zero Wall-Clock Dependency:** Rendering time is strictly an ordered integer domain $t \in \{0, 1, \dots, N-1\}$. Wall-clock timers (`Date.now()`, `performance.now()`, `setTimeout`, `requestAnimationFrame`) are strictly prohibited in the render loop.
- **Backpressure Frame Locking:** Producer (Skia / Canvas) and Consumer (FFmpeg / libavcodec) step frame-by-frame synchronously. Frame $t+1$ is never started until Frame $t$ is acknowledged and consumed. Zero dropped frames under any compute load.
- **Stateless Seeded PRNG:** All procedural noise (film grain, handheld camera shake, jitter) is evaluated purely as mathematical functions of spatial coordinates, seed, and the integer frame $f(u, v, t, \text{seed})$.
- **Sample-Locked Audio Clock:** Bresenham integer accumulator prevents fractional rounding drift down to the individual audio sample ($1/48000\text{s}$).
- **Bit-Identical Reproducibility:** Given identical inputs and assets, the engine must produce bit-identical SHA-256 raw frame buffers across runs.

### 2. Invariant 2: Dual-Target Utility (Backend Autonomous Rendering & Frontend Visual Video Editing)
The Video IR is not merely a backend renderer format—it is a **bidirectional medium**:
- **Backend Autonomous Rendering:** Consumed headlessly by serverless workers and batch pipelines for deterministic rasterization and muxing via CLI or IPC.
- **Frontend Visual Video Editing:** Acts as the reactive document model for canvas-based NLE / GUI timelines (e.g. Liquid Glass UI, WebGL preview, React Flow timeline scrubbers).
- **Relational Scrubbing & Live Inspection:** Relational time topology (`after`, `syncWith`, `matchLengthOf`, `offsetFrames`, `paddingFrames`) allows GUI frontends to ripple-edit scenes in real-time simply by adjusting anchors, without manual offset recalculation.
- **Zero Ambiguity:** Both frontend visual timeline player and headless backend compiler evaluate the exact same topological graph rules and modifier parameters.

### 3. Invariant 3: Strict Open-Closed Principle (OCP) for Schema Evolution
- **Closed for Modification:** The structural core schema—defining **What** is playing (`assets`) and **When** it plays (`tracks`, `sequences`, relational `time` graph)—is rigid and immutable. Core structural fields cannot be randomly changed, breaking existing pipelines.
- **Open for Extension:** Media processing instructions—defining **How** content is processed—are strictly abstracted into generic `modifiers` arrays.
- **Polymorphic Discriminator Architecture:** New VFX, audio filters, transitions, and AI operators are introduced purely by registering new plugin definitions into the `$defs` registry with a `type` discriminator.
- **Graceful Forward/Backward Compatibility:** Older engines encountering unknown modifier types log a warning and pass-through safely rather than crashing the pipeline.

### 4. Invariant 4: Dual-Mode Rendering Performance Optimization
The rendering engine has diametrically opposed optimization profiles between headless batch production and interactive frontend visual editing:
- **Headless Mode Target:** Maximum batch throughput, zero-copy hardware memory bandwidth, temporal GOP-chunking across distributed workers, and strict zero-nursery-heap allocation invariance.
- **Preview / Editor Mode Target:** Sub-16ms interactive scrubbing latency (60 fps), progressive LOD (Level of Detail) downscaling, dirty-rectangle & bounding-box culling, reactive DAG sub-graph re-evaluation, and audio scrub buffer slicing.

## 3. Design Patterns Architecture: Maintainability & Regression-Free OCP

To prevent code degradation, God-objects, and brittle monolithic conditionals (`if/else` or giant `switch` statements), the engine implements **7 canonical Gang of Four (GoF) & enterprise architectural design patterns**:

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                        DESIGN PATTERNS APPLIED TO VIDEO IR                             │
├─────────────────────┬─────────────────────────────────┬────────────────────────────────┤
│ Design Pattern      │ Monorepo Placement              │ Role & OCP / Regression Shield │
├─────────────────────┼─────────────────────────────────┼────────────────────────────────┤
│ 1. Strategy Pattern │ packages/ir/src/compiler/       │ Temporal constraint solvers    │
│ 2. Plugin / Registry│ packages/effect-engines/plugins/│ Extensible modifier execution  │
│ 3. Command Pattern  │ packages/core/src/commands/     │ Inspectable, dry-runnable ops  │
│ 4. Flyweight Pattern│ packages/core/src/assets/       │ Immutable asset context & VRAM │
│ 5. Adapter Pattern  │ packages/ir/src/adapters/       │ StoryConfig & legacy bridging  │
│ 6. Observer / Tree  │ packages/ir/src/compiler/       │ Reactive sub-graph timeline DAG│
│ 7. Producer-Consumer│ packages/core/src/handshake/    │ Synchronous backpressure queue │
└─────────────────────┴─────────────────────────────────┴────────────────────────────────┘
```

### 3.1 Strategy Pattern (Temporal & Playback Resolution)
- **Role:** Temporal constraints (`after`, `syncWith`, `matchLengthOf`) and out-of-bounds playback policies (`loop`, `freeze_on_last_frame`, `stretch`) are modeled as isolated strategy implementations conforming to an interface (`ITimeSolverStrategy`, `IPlaybackFillStrategy`).
- **Regression Shield:** Adding a new time behavior (e.g. `rhythm_grid_snap` or `ping_pong_loop`) requires zero edits to existing solver algorithms—you simply register a new Strategy class.

### 3.2 Plugin & Registry Pattern (The Modifier Engine)
- **Role:** Every visual effect, audio filter, editorial transition, or overlay is an independent plugin adhering to `ModifierPlugin<TParams>`. The `ModifierPluginRegistry` resolves plugins dynamically by their URI (`type: "vfx/camera_shake"`).
- **OCP Compliance:** Core rendering logic never needs modification when introducing new VFX, AI upscalers, or 3D depth modes.
- **Defensive Graceful Degradation:** If an un-registered plugin is encountered, the registry invokes a `NoOpFallbackPlugin` with a warning, preventing rendering crashes.

### 3.3 Command Pattern (Dry-Runnable Media Operations)
- **Role:** Low-level rendering steps (Skia drawing passes, audio DSP nodes, FFmpeg filtergraph segments) are wrapped in atomic `RenderCommand` objects.
- **Regression Shield:**
  - Commands can be inspected, serialized, reversed, or dry-run validated for cost/VRAM feasibility before invoking native C FFI calls.
  - Composes complex multi-pass effects into reusable macro commands (e.g., `Depth3DMacroCommand` = Cutout + Depth Map + Shadow + Matrix Projection).

### 3.4 Flyweight Pattern (Immutable Shared Memory & Asset Context)
- **Role:** Distinguishes intrinsic shared state (large video buffers, decoded audio PCM blocks, neural model weights, font typefaces) from extrinsic temporal state (current playhead $t$, layer transform, opacity).
- **Regression Shield:** Prevents memory exhaustion (OOM) by ensuring multiple sequences referencing the same media asset share an immutable in-memory reference (`AssetContext`), avoiding redundant disk I/O and nursery heap cloning.

### 3.5 Adapter Pattern (Pioneer Legacy Bridging)
- **Role:** `StoryConfigToUniversalIRAdapter` bridges existing `ResolvedStoryConfig` structures into V1.0-Stable IR documents.
- **Regression Shield:** Shields the new IR compiler from legacy schema quirks and allows both legacy and modern pipelines to interoperate seamlessly without mutating core contracts.

### 3.6 Observer & Interval Tree Pattern (Reactive Sub-Graph DAG for Frontend)
- **Role:** Visual timeline editors emit change events when clips are dragged or trimmed. An Interval Tree / Dependency Graph observes modifications and invalidates *only* the affected temporal sub-graph and its downstream dependents ($B \to \text{Descendants}$).
- **Regression Shield:** Eliminates global timeline re-evaluations, guaranteeing sub-16ms interactive UI response without risking subtle ripple regressions in unrelated scenes.

### 3.7 Producer-Consumer Pattern with Bounded Backpressure
- **Role:** Synchronous handshake locks connecting the Skia frame producer to the FFmpeg `libavcodec` frame consumer.
- **Determinism Shield:** Throttles producer cadence to match consumer consumption rate, ensuring exact frame-lock and eliminating buffer bloat.

## 5. Deep-Dive: Dual-Mode Rendering Performance Considerations

Because the engine powers both serverless headless rendering and client-side interactive timeline manipulation, performance must be tailored per execution profile:

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│                   DUAL-MODE PERFORMANCE ARCHITECTURE MATRIX                      │
├──────────────────────────┬───────────────────────────┬───────────────────────────┤
│ Consideration Dimension  │ Headless Render Pipeline  │ Visual Video Editor (GUI) │
├──────────────────────────┼───────────────────────────┼───────────────────────────┤
│ Primary Target Metric    │ Throughput (FPS > 60)     │ Latency (< 16ms scrub)    │
│ Time Stepping Cadence    │ Monotonic discrete t++    │ Arbitrary random-access t │
│ Resolution & Fidelity    │ Full master (4K / 1080p)  │ Dynamic Proxy (1/2, 1/4)  │
│ Buffer Allocation        │ Pre-allocated native FFI  │ WebGL / Canvas textures   │
│ Expensive Effects (VFX)  │ Multi-pass full shaders   │ Shader bypass / preview   │
│ Audio Pipeline           │ Contiguous async mixdown  │ Decoded slice scrub cache │
│ DAG Re-computation      │ Single pre-compilation    │ Incremental sub-graph diff│
└──────────────────────────┴───────────────────────────┴───────────────────────────┘
```

### 5.1 Headless Autonomous Batch Rendering Optimization
1. **Zero-Allocation Nursery Invariance:**
   - Adhere strictly to **ZERO-ALLOC-FRAME-LOOP**: absolutely no nursery heap `Buffer.from()` cloning per frame.
   - Pointers (`srcDataC`, `srcStrideC`) are allocated once in native memory via `av_malloc` and reused across the entire video timeline.
2. **GPU Surface Pipe & Stream Multiplexing:**
   - Zero-copy transfers via direct GPU surface sharing (`DMA-BUF` / `IOSurface` / `NVMM`).
   - Hardware-accelerated encoding (NVENC `h264_nvenc`, Apple VideoToolbox `h264_videotoolbox`).
3. **Temporal Chunking & GOP Slicing:**
   - Long compositions are partitioned into GOP-aligned frame chunks rendered across distributed workers with temporal bleed padding ($\pm 30$ frames).
   - Lossless concatenation via pure FFI stream copy in $< 2$ seconds.
4. **Decoupled Asynchronous Audio Mixing:**
   - Audio DSP graphs execute on a dedicated CPU thread concurrently with GPU video rasterization, outputting contiguous PCM data before muxing begins.

### 5.2 Visual Video Editor & Interactive Preview Mode Optimization
1. **Sub-16ms Random-Access Seeking ($O(1)$ Time Lookups):**
   - The compiled DAG outputs an **Interval Tree (R-Tree)** of sequence and effect active ranges.
   - When the user drags the playhead to frame $t$, active layers and modifiers are resolved in $O(\log M)$ rather than traversing the entire document tree.
2. **Progressive Level-of-Detail (LOD) & Proxy Downscaling:**
   - During live scrubbing or playback in the viewport, the renderer renders at $0.25\times$ or $0.5\times$ resolution using bilinear scaling, switching to full $1.0\times$ fidelity only on playhead pause (settle debounce of 150ms).
3. **Dirty-Rectangle & Bounding-Box Culling:**
   - If an editor modifies text or moves an overlay sticker on Track V3, Tracks V1 (Background) and V2 (B-Roll) are not re-rasterized if their cached `SkPicture` / WebGL textures remain untouched.
4. **Reactive Sub-Graph Incremental Re-Compilation:**
   - When a user trims or ripples Sequence $B$ on the timeline, the Relational DAG Compiler only re-evaluates the topological dependents of Sequence $B$ ($B \to \text{Descendants}$), leaving the rest of the timeline graph completely untouched.
5. **Interactive Audio Scrubbing Cache:**
   - Decodes audio assets into in-memory WebAudio/PCM ring buffers, allowing instantaneous responsive waveform scrubbing without invoking full FFmpeg filtergraphs.

2. **Interval Tree Indexing (`packages/ir/src/compiler/IntervalTreeIndex.ts`):**

   - Spoken dialogue/voiceover acts as Anchor Nodes; visual B-Roll and timed captions stretch or ripple to match.

### Phase 4: Deterministic Headless Rasterizer & Interactive Preview Engine (Producer-Consumer & Flyweight)
**Objective:** Discrete frame-stepping rendering engine with pure FFI zero-allocation streaming for headless batch, and low-latency proxy engine for editor preview.

#### Tasks:

2. **Decoupled Asynchronous Audio Mixing & Scrubbing (`packages/core/src/renderer/ir/audio/`):**
   - Headless: Concurrently bounce master audio timeline into contiguous PCM memory while video rasterizes.
   - Preview: In-memory decoded audio slice ring buffer for instantaneous scrubbing.
3. **Deterministic Frame Capture & Backpressure Handshake (Headless):**
   - Synchronous frame-by-frame producer/consumer stepping: advance frame $t \to t+1$ only upon encoder buffer consumption ack.
   - Strictly adhere to **ZERO-ALLOC-FRAME-LOOP** and **FFMPEG-MANAGER** rules: zero nursery heap allocations per frame, reuse pre-allocated native C pointers (`av_malloc`), direct pointer dereferencing via `bun:ffi`.
4. **Interactive Preview Engine (`packages/core/src/renderer/ir/IRPreviewEngine.ts`):**
   - Random-access frame seeker with proxy resolution downsampling ($0.25\times, 0.5\times$).
   - Dirty-region caching and `SkPicture` memoization.
