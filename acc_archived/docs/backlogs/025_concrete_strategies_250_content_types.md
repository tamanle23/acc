## Context & Problem
The ACC engine defines 250 content variations across 6 Canonical Pipelines and 5 Modality Exporters, but only defines the abstract `IContentTaskStrategy` interface in `packages/core/src/conductor/interfaces/IContentTaskStrategy.ts`. There are zero concrete strategy implementations, leaving content tasks without standardized handlers for generating `PipelineIR` and triggering modality-specific exporters.

## Proposed Design
1. Build `BaseContentTaskStrategy` and `ContentStrategyRegistry` in `@acc/core`.
2. Implement 6 Strategy Archetypes (`ScraperDigestStrategy`, `DBComparisonStrategy`, `SocialThreadStrategy`, `FacelessShortsStrategy`, `PodcastAudioStrategy`, `CalculatorWidgetStrategy`).
3. Scaffold concrete strategies for all 250 content types across 6 phases.
4. Integrate with Conductor task commands and CLI.
5. Create comprehensive test suites in `/autogenerated-tests/strategies/`.

## Acceptance Criteria
- [x] Phase 1: Items 1–50 (Format 1: Static Web CMS) implemented & tested
- [x] Phase 2: Items 51–100 (Format 2: Social Media Automation) implemented & tested

- [x] Phase 4: Items 151–200 (Format 4: Audio & Podcasts) implemented & tested
- [x] Phase 5: Items 201–250 (Format 5: Interactive Web & Logic) implemented & tested
