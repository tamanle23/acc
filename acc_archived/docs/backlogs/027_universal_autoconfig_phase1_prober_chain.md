## Context & Problem
`auto-config.ts` previously mixed synchronous filesystem crawling with interactive terminal prompts. It hardcoded basic regex-based media collection for local slide images and audio files, making it impossible to perform automated, headless asset inspection for backend workers, autonomous Conductor tasks, or multi-modal pipelines (Pipelines 1–6).

To enable automated pipeline classification and canonical `PipelineIR` generation, we needed an enterprise, headless **Chain of Responsibility** asset probing engine in `@acc/core` that comprehensively discovers, validates, and extracts technical and semantic metadata from any directory without user intervention.

---

## Proposed Design
Implemented **Phase 1 of Universal Auto-Config**:
1. **Asset Manifest Model (`DiscoveredAssetManifest`)**:
   - Strongly typed descriptors for visual assets (images/videos), audio assets (voice/music/sfx/ambient), script assets (text/markdown), and structured data assets (csv/json).
2. **Chain of Responsibility Prober Engine (`MediaAssetProberChain`)**:
   - Decoupled handlers implementing `IMediaAssetProberHandler`:
     - `ImageProberHandler`: Resolves dimensions, aspect ratio, image format.
     - `VideoProberHandler`: Probes video duration, resolution, container type.
     - `AudioProberHandler`: Analyzes audio duration, channel count, music vs voiceover categorization.
     - `ScriptProberHandler`: Parses text/markdown scripts, word count, line structures, estimated speech duration.
     - `DataProberHandler`: Parses CSV/JSON datasets.
3. **Defensive & OS-Agnostic Execution**:
   - Zero-crash fallback for unreadable or partial files.
   - Strict `path.join` and dynamic file resolution.
   - Natural numeric sorting for chronological sequence discovery and visual-voiceover pairing.
