## 1. Context & Problem
Rendering a 2-minute video with the current single-threaded Universal Video IR engine takes approximately 4 minutes (240s). To make the platform production-ready and achieve an SLA of $<45\text{s}$ across 4-8 logical cores, we must introduce distributed multi-worker temporal chunking.
The distributed engine must preserve strict compliance with:
1. `DETERMINISTIC-HANDSHAKE-BACKPRESSURE` (bit-identical hash parity between single-thread and multi-worker execution).
2. `ZERO-ALLOC-FRAME-LOOP` (zero heap cloning per frame, pre-allocated C memory for native FFI).

---

## 2. Proposed Design
1. **`IRChunkWorkerPool`**: Master-worker orchestrator that calculates chunk ranges aligned with keyframe/scene boundaries, spawning bounded Bun workers.
2. **`FFIChunkConcatMuxer`**: Lossless zero-reencode fast concatenation via native `bun:ffi` packet remuxing ($<500\text{ms}$).
3. **Deterministic Chunk Hash & Merkle Root**: Each worker reports an SHA-256 chunk hash; the master orchestrator computes the combined Merkle root:
   $$\text{RootHash} = \text{SHA256}(\text{ChunkHash}_1 \parallel \text{ChunkHash}_2 \parallel \dots \parallel \text{ChunkHash}_N)$$
4. **CLI Integration**: Expose `--concurrency` (alias `-j`) in `acc ir-render` and the underlying IR render flow.
