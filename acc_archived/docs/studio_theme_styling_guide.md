# Studio Theme System — Styling Guide

How to style `@acc/studio` components so they respond correctly to every theme preference (mode, glass style, blur, accent).

Source of truth:
- Runtime: `apps/studio/src/lib/theme/ThemeProvider.tsx`
- CSS tokens & utilities: `apps/studio/src/index.css`
- Regression test: `autogenerated-tests/studio_theme_unification.test.ts`
- Rationale: `docs/history/306_unified_system_theme_architecture.md`

---

## 1. Mental Model

```
ThemeProvider (preferences)
   │  applyThemeToDocument()
   ▼
<html class="dark|light" data-theme-mode data-glass-style data-blur-intensity data-accent
      style="--primary --ring --accent-primary --accent-glow --color-brand-accent">
   ▼
index.css  (:root/.dark vars, [data-*] overrides)
   ▼
@theme  (maps CSS vars → Tailwind v4 utilities)
   ▼
Components use semantic classes only
```

Components never read preferences. They use semantic classes, and the cascade does the rest. Changing a preference swaps CSS variables, so every component updates with no re-render.

### Preferences

| Preference | Values | DOM output |
|---|---|---|
| `mode` | `dark` (Obsidian), `light` (Frosted Acrylic) | `.dark` / `.light` class, `data-theme-mode` |
| `glassStyle` | `specular`, `frosted`, `cyber` | `data-glass-style` |
| `blurIntensity` | `low` (6px), `medium` (18px), `high` (40px) | `data-blur-intensity` |
| `accentColor` | `cyan`, `violet`, `emerald`, `amber`, `rose` | `data-accent`, `--accent-primary`, `--accent-glow`, `--primary`, `--ring` |

## 2. Token Cheat Sheet

### Surfaces and text (shadcn-style)

| Use | Class |
|---|---|
| App background | `bg-background` |
| Primary text | `text-foreground` |
| Secondary/hint text | `text-muted-foreground` |
| Subtle fills (inputs, chips, hover wells) | `bg-muted`, `bg-muted/40` |
| Popovers/dialogs | `bg-popover text-popover-foreground` |
| Destructive | `text-destructive`, `bg-destructive/10` |
| Generic border | `border-border` |

### Liquid Glass (theme-aware)

| Use | Class |
|---|---|
| Glass background | `bg-glass-surface` (`bg-glass-surface/60` for alpha) |
| Glass border | `border-glass-border` |
| Highlight edge (top/specular) | `border-glass-border-highlight` |
| Glass shadow | `shadow-glass` |
| Accent glow | `shadow-accent-glow` |

### Accent (follows the user's accent color)

| Use | Class |
|---|---|
| Accent text/icon | `text-accent-theme` |
| Accent fill | `bg-accent-theme` |
| Text on accent fill | `text-primary-foreground` (**never** `text-slate-950`/`text-white`) |
| Tinted selected state | `bg-accent-theme/10`, `/15`, `/20` |
| Accent border | `border-accent-theme`, `border-accent-theme/40` |
| Focus ring | `ring-accent-theme` |
| Selection highlight | `selection:bg-accent-theme/30` |

### Prebuilt component classes

| Class | Purpose |
|---|---|
| `glass-panel` | Large surfaces: sidebars, dialogs, toolbars (blur + saturate + specular edge) |
| `glass-card` | Cards inside panels |
| `glass-pill` | Small chips/segmented buttons (reads `data-active`) |
| `glass-button`, `glass-button-primary` | Buttons; the primary variant uses accent fill |
| `glass-badge-accent` | Accent badge |

> Reuse these before composing your own glass look with raw utilities.

## 3. Recipes

### Panel with card and accent action

```tsx
<aside className="glass-panel border-r border-glass-border flex flex-col">
  <header className="px-3 py-2 border-b border-glass-border flex items-center gap-2">
    <Sparkles className="w-4 h-4 text-accent-theme" />
    <h2 className="text-xs font-bold uppercase tracking-wider text-foreground">Effects</h2>
  </header>
  <div className="glass-card p-3 rounded-xl">
    <p className="text-[11px] text-muted-foreground">Hint text</p>
    <button className="mt-2 px-2 py-1 rounded-full bg-accent-theme text-primary-foreground shadow-accent-glow">
      Apply
    </button>
  </div>
</aside>
```

### Toggle / selected state

```tsx
className={`px-2 py-0.5 rounded-full border transition-colors ${
  active
    ? 'border-accent-theme bg-accent-theme/20 text-accent-theme shadow-accent-glow'
    : 'border-glass-border text-foreground/70 hover:text-foreground hover:bg-foreground/10'
}`}
```

Hover wells use `hover:bg-foreground/10`, not `hover:bg-white/10`. White-on-white is invisible in light mode.

### Inputs

```tsx
<input className="bg-glass-surface border border-glass-border text-foreground
                  focus:border-accent-theme focus:shadow-accent-glow focus:outline-hidden" />
```

### Semantic status colors

Status colors (emerald = ok, amber = warning, rose/`destructive` = error) are intentionally **not** accent-bound, so a rose accent doesn't make "success" look like an error. Pair them for both modes:

```tsx
'text-emerald-500 dark:text-emerald-300 bg-emerald-500/10 border-emerald-500/40'
```

Use `text-destructive` for destructive actions.

### Mode / style-specific overrides (custom variants)

Available variants: `dark:`, `light:`, `glass-cyber:`, `glass-frosted:`, `glass-specular:`, `blur-low:`, `blur-medium:`, `blur-high:`.

```tsx
<div className="shadow-md glass-cyber:shadow-accent-glow light:border-glass-border" />
```

Prefer variables over variants. Reach for a variant only when a structural difference is needed.

### Custom CSS

Reference tokens, never literals:

```css
.my-widget {
  background: var(--glass-bg);
  backdrop-filter: var(--glass-blur) saturate(160%);
  border: 1px solid var(--glass-border);
  box-shadow: var(--glass-specular), var(--glass-shadow);
  color: hsl(var(--foreground));
}
.my-widget:focus-visible { outline: 2px solid var(--accent-primary); }
```

For tints, use `color-mix(in srgb, var(--accent-primary) 25%, transparent)`. Don't use `var(--alpha(...))`, which is invalid.

### Canvas / SVG

- SVG strokes and fills: `stroke="currentColor"` plus a text class, or `stroke="var(--accent-primary)"`.
- `<canvas>` can't read Tailwind classes. Read a variable once with `getComputedStyle(document.documentElement).getPropertyValue('--accent-primary')`, and refresh it on theme change.

## 4. Do / Don't

| Don't | Do |
|---|---|
| `bg-white dark:bg-slate-900` | `bg-glass-surface` or `bg-card` |
| `text-slate-500` / `text-slate-400` | `text-muted-foreground` |
| `text-slate-800 dark:text-slate-200` | `text-foreground` |
| `border-slate-200` | `border-glass-border` (or `border-border`) |
| `bg-indigo-600 text-white` | `bg-accent-theme text-primary-foreground` |
| `text-cyan-400` for brand emphasis | `text-accent-theme` |
| `bg-[var(--accent-primary)]` | `bg-accent-theme` |
| `border-[var(--glass-border)]` | `border-glass-border` |
| `shadow-[0_0_15px_var(--accent-glow)]` | `shadow-accent-glow` |
| `hover:bg-white/10` | `hover:bg-foreground/10` |
| `text-accent-theme/600`, `bg-accent-theme/200` | Opacity is 0–100: `/10`, `/20`, `/40` |
| Hardcoded hex in components | Tokens, or `ACCENT_CONFIGS` in code |

The `bg-[var(--...)]` forms still work, but the semantic classes are the standard. They're shorter and checked by the regression test.

### Intentional exceptions

- **Video output surfaces**: the canvas backing (`#000000`), in-canvas subtitles (`bg-black/80 text-white`), and clip-body text on colored track badges stay theme-independent. These render into exported video or sit on fixed track colors, so they must not change with the UI theme.
- **Track-type colors** (emerald audio, amber FX, violet text, indigo video) are data encoding, not chrome.

## 5. Using Theme State in TypeScript

```tsx
import { useTheme, ACCENT_CONFIGS } from '@/lib/theme/ThemeProvider';

const { preferences, setTheme } = useTheme();
setTheme({ accentColor: 'violet' });         // partial updates
setTheme({ glassStyle: 'cyber', blurIntensity: 'high' });

const hex = ACCENT_CONFIGS[preferences.accentColor].hex; // for canvas/JS only
```

Use JS access only when CSS can't do the job (canvas, charts, third-party widgets). Otherwise rely on classes.

Outside React, `applyThemeToDocument(preferences)` applies the full DOM and CSS-variable state synchronously. `ThemeProvider` already calls it during initial state hydration to avoid a flash of the wrong theme.

## 6. Adding to the System

### New accent color

1. Add its `hsl`, `hex`, and `glow` to `ACCENT_CONFIGS` and the `AccentColor` type.
2. Add a `[data-accent="name"]` block in `index.css`, following the existing five.
3. Add it to `ACCENT_COLORS` in `SettingsModal.tsx`.
4. Add it to the accent list in `studio_theme_unification.test.ts`.

### New theme token

1. Define the variable in `:root` and `.dark` (and in any `[data-*]` override block that changes it).
2. Expose it in `@theme` (for example `--color-my-token: var(--my-var)`) to get `bg-my-token`, `text-my-token`, and so on.
3. Add an assertion for it in the test file.

## 7. Verification Checklist

Before merging UI work:

- [ ] Toggle Dark and Light. Text, borders, and hovers are legible in both.
- [ ] Cycle all 5 accents. Selected, focus, and primary-button states follow the accent. Text on accent fills stays readable (`text-primary-foreground`).
- [ ] Cycle `specular`, `frosted`, and `cyber`. Panels still have borders and depth.
- [ ] Cycle blur low, medium, and high. Nothing becomes unreadable at `low`.
- [ ] Every component covers the 5 states (default, loading, empty, error, disabled) with tokens.
- [ ] No leftovers: search the component for `slate-`, `indigo-`, `bg-white`, `text-slate-950`, `#hex`, `var(--accent-primary)` inside class strings.
- [ ] `bun run --cwd apps/studio build` passes.
- [ ] `bun test ./autogenerated-tests/studio_theme_unification.test.ts` passes.

## 8. Troubleshooting

| Symptom | Likely cause |
|---|---|
| Class does nothing | Opacity step isn't 0–100 (`/200`), or the token isn't registered in `@theme` |
| Text invisible in light mode | Hardcoded `text-white`, `text-slate-300`, or `hover:bg-white/*` |
| Accent button has poor contrast | Used `text-white` or `text-slate-950` instead of `text-primary-foreground` |
| Glass looks flat or borderless in `cyber` | Used a fixed border instead of `border-glass-border`; cyber derives borders from the accent |
| Flash of wrong theme on load | Theme applied after first paint; keep application inside `applyThemeToDocument` during state init |
| Canvas ignores theme | Canvas can't read classes; read CSS variables via `getComputedStyle` and redraw on theme change |
