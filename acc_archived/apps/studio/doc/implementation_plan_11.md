# Implementation Plan 11 - Phase 1: Declarative Particle & Hologram HUD Subsystem

## Overview
Phase 1 decouples the procedural particle system and hologram HUD from the global canvas mount lifecycle in Studio's Preview viewport, converting them into declarative, sequence-driven modifiers and optional preview ambiance.

## Problem Statement
Previously, `Preview.tsx` unconditionally invoked `engine.initHologramHUD(0.35, 40)` and `engine.initParticleSystem(250)` on engine initialization. This resulted in particles and HUD rings permanently rendering on every project, even when no corresponding modifiers (`vfx/particles`, `overlay/canvas_particles`, `overlay/hologram_hud`, `sci_fi_hud`) were defined in the active sequences or VideoIR DAG.

## Solution Architecture
1. **Engine Declarative Lifecycle**:
   - Implemented `clearParticles()`, `hasParticles()`, `initHologramHUD(..., color, rotationSpeed)`, `clearHologramHUD()`, `hasHologramHUD()`, and `setHUDConfig()` in `UniversalCanvasEngine.ts`.
2. **Preview Dynamic Sync**:
   - Removed the hardcoded invocations from the `useEffect` engine initialization block in `Preview.tsx`.
   - Linked particle and HUD lifecycle to the active sequences and modifiers rendered at the current frame playhead.
   - Added a manual viewport toggle (`showVfxAmbiance`) via `<Sparkles />` in the top control bar for previewing visual ambiance without mutating VideoIR.
3. **Verification**:
   - Created `autogenerated-tests/studio_phase1_declarative_vfx.test.ts` verifying API lifecycle and source integrity.
